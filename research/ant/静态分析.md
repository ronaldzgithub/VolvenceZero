## 一等阻塞（按修复依赖排序）

**1. 奖励接缝在 optimizer 侧没守住**（我自己复核过全链）
`environment_action_payoff = measurement.action_payoff if measurement is not None else None`（[final_wiring.py:1523](packages/vz-runtime/src/volvence_zero/integration/final_wiring.py:1523)）→ PE owner 只在非 None 时覆盖（[error.py:694-698](packages/vz-cognition/src/volvence_zero/prediction/error.py:694)）→ optimizer 直接吃 `actual_outcome.action_payoff`（[sandbox.py:2204](packages/vz-temporal/src/volvence_zero/internal_rl/sandbox.py:2204)）。所以 `measurement=None` 的拍上，reward 变成 PE owner 内部合成的 action 轴，而那条轴是食物传感器的函数（`commit_pull=|food_left-food_right|*4`、`explore_pull=1-food_center`，[sense_encode.py:194](packages/vz-embodiment-ant/src/volvence_ant/substrate/sense_encode.py:194) → [ant_adapter.py:125](packages/vz-embodiment-ant/src/volvence_ant/substrate/ant_adapter.py:125) → [error.py:2253](packages/vz-cognition/src/volvence_zero/prediction/error.py:2253)）。

最锋利的后果不是"所有臂都不稀疏"——learned 臂开着 local valence，多数拍有 measurement，fallback 只在位移被木棍完全阻挡、全部 delta 恰为 0 时触发（中性木棍因此拿到正奖励）。真正被反转的是 **`dense-local-shaping-off` 消融臂**：关掉 local valence 后它每个非里程碑拍都走 fallback，等于把"密集塑形关掉"换成了"另一种密集食物塑形"（[ant_session.py:655-673](packages/vz-embodiment-ant/src/volvence_ant/runtime/ant_session.py:655)）。这条消融的历史结论全部无效，spec:78-84 的塑形禁令在 optimizer 侧不成立。
附带：ant 记录里导出的 `nonzero_ecology_payoffs`（measurement 侧）和 `nonzero_reward_steps`（PE 残差）都不是 optimizer 实际消费的 reward，这条流从未导出 → 泄漏在现有 evidence 里不可见。

**2. `PE-off` 实际是 `reward-off`**

## 可行性：两个真结构问题

**A. 训练和冻结评估不是同一个动力学**（这是我认为最重要的一条）
训练 `exploration_strength=1.0`：探索提案是 `sha256(context:segment:option:index)` 映射到 [-1,1]，**每 8 拍恒定**、std floor 0.4 → 行为是分段常曲率圆弧，单拍转向可达 ~0.5 rad。冻结评估 `sparse_exploration_enabled=False`，且 exclusive steering 把 base 的 contrast 投影为零 → 被打分的确定性策略的全部转向来自 head residual，v25 的 16 行 probe 实测 **0.0055–0.0327 rad/拍**（执行器上限 0.675 rad）。40 拍最多约 1.3 rad 累计转向，而一次定向 medium/far 往返需要 ~3.4–4.0 rad —— **2.5–8 倍的运动学缺口**。

这一条同时解释了 06 文档里 v10→v25 的全部现象：训练侧 near/medium pickup 一直健康、冻结 medium/far 恒 0，而唯一通过的能力（forced escape）恰好只需要几拍直行、不需要转向。它意味着"继续加训练量"或"再找一个衰减因子"都不会奏效——策略在一个运动学 regime 里被优化、在另一个里被打分。
复核修正一处：P2 的 held-out 是 120 rounds（不是 40），累计转向在 P2 不再是硬阻塞；但 P1 的 40 rounds 是。

**B. R5-R6 在这个测试床没有可测端点**
spec §1 声明数字蚂蚁要独立检验 R2 / R3-R4 / R5-R6 / R-PE / SSOT。但没有 memory 臂、没有 memory 端点，而 action head 契约上是**零历史**的（`causal_action_head_state` 用零历史编码当前 19 维观测）→ 连续记忆谱这一项结构上无法在此证伪。

另外两条量化事实（重要但可改）：
- **near 假阳性比 spec 承认的更糟**：body 生成在巢心，37.5% 的 near layout 首拍即 pickup+delivery（零位移）；最小轨道半径 0.287 让紧圆巡游覆盖整个 near 范围。`forced_approach` 的随机环确实保证了直线必然错过（≥1.518 > 1.1），但只修了出发段，**回巢段仍然免费**。
- **far 训练局采不到 delivery**：24 rounds × 实测 ~0.225/拍 = 5.4 单位，对 far 往返 4.2（均值）/5.6（最坏）。注意 plant 本身够（满速 0.393/拍 → 9.4 单位，预注册 oracle 23 拍能完成），所以这是"策略速度 + 预算"的组合问题，不是几何不可能——`_clamp` 把 code 界在 [0,1] 使 `speed_unit ∈ [0.5, 0.982]`，策略还结构性地无法减速或停下转身，而 oracle 的可解性证明恰恰依赖原地转向。

## 已被复核推翻的疑点（别当问题处理）

- `forced_return`/`forced_approach` 调 `navigator.sync_to` 是 spec:333-334 明确授权的 bootstrap，AntBot/Ardin 的 homing lane（`phase0.py:104-163`）不含 sync_to。
- eta_off 的 `n_input` 绑定：注入的是 `LearnedLiteTemporalPolicy`，不走 ndim encoder，不存在感觉尾部通道截断。
- `heat_exposure_continued = -0.4`/拍：spec §5.3 的 local valence 授权"有害暴露为负"——这是 §4"三个稀疏事实"与 §5.3 的**文档内部不一致**，不是代码缺陷。
- replay 侧 per-dim beta 泄漏：可证明等于 live 的 pair-shared gate（凸组合永不触界 + `z_tilde = z_candidate`），投影上去是 no-op。
- 镜像配置"默认关"：`AntSessionConfig.sense_schema` 默认 V1，spec:311 要求非 ecology profile 不带镜像配置 → 现状正确。
- `food_steering_alignment` 探针落在拾取盘内：`at_food` 不进 19 维感知，探针读的是 turn 符号，不受影响。
- "paired 统计恒为零"：`outcome_score` 是部分信用连续量（pickups×0.5 + deliveries×1 + escapes×0.25 − harmful×0.02），不会被 delivery=0 钉死。

还有两条只在特定开关下才咬人的：torch causal-PPO lane 把 head 三个参数当普通 Adam leaf，绕过全部 bias/factor 纪律（`VZ_INTERNAL_RL_BACKEND` 打开时）；replay 用 `[-1,1]` clamp 而 live 用 `[0,1]`，饱和区会让 `(action-mean)` 符号系统性错向。
