# Volvence 关系连续性实验报告（普通用户版）

> 报告日期：2026-08-25  
> 对应实验：Relationship Product Horizon v2，Windows CUDA attempt03  
> 实验性质：合成环境中的开发验证，不是真人产品试验，也不是正式科学结论

## 一、先说结论

这次实验不是“什么都没通过”。完整 Volvence 系统明显优于“不学习”“不干预”以及两种常见的大模型记忆方案，说明内部关系控制链确实产生了有价值的行为差异。

但是，它没有通过总验收。原因是两个最关键的问题没有成立：

1. 持续保存并更新关系状态，没有比把关系状态冻结在初始值更好，平均反而低 **9.38 个百分点**。
2. 使用正式的“命名关系读出”，没有比旧式的未命名语义相似度更好，平均反而低 **4.17 个百分点**。

因此，这次实验支持的最强结论是：

> Volvence 的完整内部控制系统比无学习、无干预和普通历史/RAG基线更有效；但当前的关系状态累积与命名读出尚未证明自身有效，甚至可能在放大错误。

它不能支持“系统已经学会长期关系”“四能力闭环已经完成”或“可以上线”的结论。

## 二、实验到底想验证什么

普通聊天模型通常依靠当前提示词、整段聊天历史或检索到的旧对话来回答。Volvence 想验证的是更强的能力：系统能否在不在线改写基础模型的情况下，持续维护与某个用户的关系状态，并根据互动结果逐步学会什么时候应该采取不同的关系动作。

实验围绕四条能力轴展开：

- **Appendable（可追加）**：过去的互动是否能写入并跨会话延续，而不只是把原文塞回提示词。
- **Readable（可读出）**：系统能否把内部关系状态读成有明确含义的正式状态，而不是依赖关键词或一串无法解释的分数。
- **Learnable（可学习）**：系统是否从预测误差和信用分配中学习，而不是把人工评分直接当奖励。
- **Steerable（可干预）**：系统是否能在冻结基础模型的前提下，有界地改变下一步行为，并且可以关闭、审计和回滚。

这四项必须形成闭环，才能说系统具备持续主动学习能力。任何一项不成立，都只能说明局部机制有效。

## 三、用一个生活化例子理解实验

假设用户多次表达：“我希望你先听我说，不要替我做决定。”

一个真正具有关系连续性的系统应该做到：

1. 记住这种边界偏好；
2. 在后续相似但措辞不同的场景中识别出来；
3. 如果曾经做得过于强势，根据结果修正内部策略；
4. 用户隔一段时间回来后，仍能采取更合适的行动；
5. 当用户后来改变偏好时，又能及时适应，而不是永远被旧记忆绑住。

实验没有让模型自由输出长篇聊天，而是给它一个封闭的候选动作集合，再由隐藏的评估环境判断所选动作是否符合当前条件。这样可以准确比较不同系统版本，而不会因为文风好坏混淆结果。

## 四、实验是怎么设计的

### 4.1 样本与时间结构

实验冻结了 **8 个匹配的虚拟用户世界**。每个用户经历：

- 4 个 onboarding 会话，用于建立初始关系背景；
- 24 个按时间顺序发生的决策会话；
- 主要评分窗口为第 12 至第 23 个决策，共 12 个主要决策。

长期阶段被预先分成五类：

1. 关系偏好发生反转之后；
2. 用户明确纠正系统时；
3. 纠正后的后续互动；
4. 间隔一段时间后重新出现；
5. 多种压力混合出现的复杂场景。

这些阶段用于判断效果是不是只在眼前一轮有效，还是能跨时间保持。

### 4.2 公共信息与隐藏答案分离

模型只能看到当时允许公开的内容，例如当前输入、此前已经发生的公开行动与结果、以及合法的候选动作。

正确条件、偏好动作、环境种子和未来结果被放在分离的 sealed evaluator 中。模型完成选择后，评估器才结算结果。这种顺序用于防止答案泄漏。

需要强调：这是可审计的数据与步骤隔离，不是针对恶意程序的操作系统安全沙箱。

### 4.3 七个实验组

| 实验组 | 通俗解释 | 它在回答什么问题 |
|---|---|---|
| `volvence_full` | 完整系统：延续关系状态、命名读出、根据预测误差分配 credit、允许有界控制 | 整套系统最终表现如何 |
| `appendable_frozen_onboarding` | 每次决策都把关系状态恢复到 onboarding 结束时的固定版本，但保留已学习的 gate | 持续更新关系状态到底有没有帮助 |
| `readable_unnamed_legacy` | 不用正式命名 reader，改用旧式未命名语义相似度；其他主要路径不变 | 命名读出是否带来独立价值 |
| `credit_withheld` | 仍计算预测误差和 credit，但不把 credit 应用到控制 gate | 学习更新是否有价值 |
| `strict_noop` | 保留读取和结算，但强制不实施关系干预 | 主动干预是否有价值 |
| `native_full_history` | 固定版本 Qwen2.5-1.5B 读取按时间排列的完整公开历史 | 是否优于“把全部历史交给模型” |
| `selective_rag` | 同一模型配合固定版本 BGE-M3，只检索相关历史 | 是否优于常见 RAG 记忆方案 |

“冻结关系连续性”不等于彻底失忆。它仍拥有 onboarding 后的初始关系背景，也保留 gate checkpoint；只是每个新决策不继承上一轮继续变化的 owner 状态。因此它是针对“持续追加状态”的干预组，但不是绝对纯粹的单变量记忆实验。

“命名读出”指由唯一 owner 把内部状态发布成语义明确、不可变、可追踪的关系条件。它的价值应该是让控制器知道自己因为什么而行动，也让错误能够被审计。旧式未命名路径可能仍有很强的预测能力，但很难证明它到底读到了什么。

### 4.4 预先规定的通过标准

完整系统必须同时满足：

- 对每个关键消融组和两条强基线，匹配用户平均效果至少高 **5 个百分点**；
- 至少 **6/8** 个用户呈正向效果；
- 安全负面结果相对任何对照组的增加不得超过 **2 个百分点**；
- 在五个长期阶段中达到预注册的持久性要求；
- 内部机制收据完整，能证明 reader、owner continuity、预测误差、credit 和 gate update 确实按协议执行。

这是一个“全部关键门都要过”的验收。不能用赢过某个外部基线，掩盖内部关键能力没有成立。

## 五、实际运行情况

实验完整执行了协议规定的 8 个用户、4 个 onboarding 和 24 个决策会话。主要执行事实包括：

- 每个 Volvence 实验臂有 192 个决策；
- 两条强基线共生成 384 个 completion，**384/384 均通过格式与契约校验**；
- 记录了 1,120 个 Volvence logical session 和 720 个不同 child PID；
- 命名读出、未命名读出、预测误差收据、credit 记录、owner continuity/reset 和 gate update 均有机制日志；
- Qwen、BGE-M3、模型 revision、权重哈希、Python source tree 和公开协议均被冻结或记录；
- BGE-M3 embedding table 已在新进程中重新观察通过。

所以总失败不是因为程序没跑完、CUDA 没工作、输出格式错误或基线失效，而是实验效果没有满足全部预注册门槛。

## 七、哪些结果确实通过了

### 7.1 完整系统优于“不学习”和“不干预”

完整系统相对 `credit_withheld` 和 `strict_noop` 均提高 **36.46 个百分点**，8/8 个用户都呈正向效果。

在五个长期阶段中，完整系统对这两组全部为正：

| 长期阶段 | 相对不应用 credit / 严格不干预 |
|---|---:|
| 反转后 | +40.63% |
| 用户纠正时 | +43.75% |
| 纠正后 | +43.75% |
| 间隔返回 | +31.25% |
| 混合压力 | +18.75% |

这说明完整控制链不是纯粹的日志装饰：启用完整路径后，实际动作和结果确实发生了明显变化。

但两组结果完全相同也是一个警告。它意味着本实验还没有清楚分离“停止学习更新”和“停止执行干预”各自贡献了多少效果。

### 7.2 完整系统优于两条强基线

完整系统相对原生完整历史和 selective RAG 均提高 **22.92 个百分点**，6/8 个用户呈正向效果，并在五个长期阶段中全部保持正向。

这支持一个有价值但有限的产品信号：结构化的内部状态与控制链，可能比单纯塞入全部历史或检索相关历史更适合这套合成关系任务。

它仍不能直接推广到真实用户，因为场景、动作和结果均来自合成 typed environment。

## 八、具体是怎么没通过的

### 8.1 持续关系状态反而拖累了结果

完整系统相对冻结关系连续性组平均低 **9.38 个百分点**。五个长期阶段全部为负：

| 长期阶段 | 完整系统相对冻结组 |
|---|---:|
| 反转后 | -6.25% |
| 用户纠正时 | -6.25% |
| 纠正后 | -6.25% |
| 间隔返回 | **-18.75%** |
| 混合压力 | -12.50% |

安全负面率相对冻结组增加 **9.38 个百分点**，超过最多允许增加的 2 个百分点。

最合理的解读不是“关系记忆没有价值”，而是当前追加机制可能把不准确状态持续保存并放大。可能的原因包括：reader 初始判断错误、credit 归因错误、旧状态衰减不足、关系反转后更新不及时，或者 gate 对累积状态过度敏感。

尤其值得注意的是“间隔返回”最差。这个阶段本来最应体现长期关系记忆的价值，却出现最大负差，因此必须优先排查跨会话恢复后的状态质量。

### 8.2 命名读出没有证明效果优势

完整系统相对旧式未命名读出平均低 **4.17 个百分点**。分阶段结果为：

| 长期阶段 | 完整系统相对未命名读出 |
|---|---:|
| 反转后 | -3.13% |
| 用户纠正时 | +6.25% |
| 纠正后 | 0% |
| 间隔返回 | -12.50% |
| 混合压力 | -12.50% |

安全负面率增加 **4.17 个百分点**，同样超过 2% 门槛。

这不说明“可解释状态不该存在”。命名读出在架构上仍然重要，因为它提供唯一 owner、明确语义、快照、lineage 和回滚能力。实验说明的是：当前 reader 发布的命名状态还没有提供比旧式黑盒相似度更可靠的决策信息。

可能出现了“形式上可读、内容上不够准”的情况。这也是后续把 condition reader 单独拿出来做资格实验的直接原因。

### 8.3 直接机制证据没有完全闭合

实验日志证明各模块确实运行，但报告仍判定：

- `direct_mechanism_evidence_complete = false`
- `internal_typed_control_ablation_effect_observed = false`
- `product_stage_two_effect_observed = false`

换句话说，实验能看到完整系统产生了行为效果，但还不能把效果可靠归因到“命名 reader + 连续 owner 状态 + PE→credit→gate”这条指定因果链的每个环节。

## 九、应该如何正确解读

### 可以说

- 实验按冻结协议完整运行，执行与基线仪器有效。
- 完整系统在该合成任务上优于无 credit、严格 noop、完整历史和 selective RAG。
- 当前关系连续性更新存在明确风险，尤其是在间隔返回和混合压力阶段。
- 当前命名 reader 尚未证明优于旧式未命名相似度。
- 下一步应该先隔离验证 reader，再检查状态写回和 credit 归因。

### 不可以说

- 不可以说 Volvence 已经学会真实的人际关系。
- 不可以说长期关系记忆已被证明有效。
- 不可以说命名读出已带来产品增益。
- 不可以说残差 steering、四能力闭环或论文主张已经成立。
- 不可以说结果可直接代表真人用户体验。
- 不可以据此授权 production ACTIVE。

## 十、为什么下一步是 reader qualification

完整系统当前可能形成如下错误放大链：

```text
reader 读错关系条件
  → 错误状态被命名发布
  → credit 把结果归到错误条件
  → gate 学会错误的干预时机
  → 状态跨会话继续保存
  → 下一轮错误进一步累积
```

如果 reader 本身不合格，继续扩大 Product Horizon 或调整 gate，很难判断改善来自真正修复还是偶然调参。因此后续资格实验把问题缩小为：

> 在看不到隐藏标签和组信息的条件下，reader 能否对独立来源、不同表达方式的关系条件稳定给出正确 top-1，并达到最低 margin？

当前 reader qualification 的代码测试已大量通过，但新的正式模型/CUDA资格运行尚未完成。测试通过表示执行器、契约和失败保护按设计工作，不等于 reader 已通过真实资格门。

## 十一、建议的后续顺序

1. **完成独立 reader qualification**：先确认命名读出内容是否准确，而不只确认接口存在。
2. **检查置信度与拒绝机制**：reader 不确定时应允许保持 noop，避免低置信错误写回。
3. **审计状态写入**：比较正确读出与错误读出分别怎样改变 owner 状态，尤其检查跨会话恢复和衰减。
4. **拆分 credit 与 noop 对照**：解释为什么 `credit_withheld` 与 `strict_noop` 结果完全一致，建立更清晰的因果归因。
5. **针对失败阶段做新协议**：重点覆盖间隔返回、混合压力和关系反转，不得在看过结果后修改原 attempt03 的冻结判词。
6. **重新执行新的、预注册的 Product Horizon**：只有 reader、写回与 credit 链分别合格后，才值得再次运行完整长周期实验。
7. **最后才考虑真人验证**：需要独立用户、知情同意、安全审查和用户可见生成；合成环境通过不能替代这一步。

## 十三、一句话总结

这次实验发现了一个值得继续研究的积极信号：Volvence 的完整控制路径比普通历史/RAG和完全不学习更强；同时也发现了一个不能回避的核心缺陷：当前系统“记住了什么、读出了什么”还不够可靠，持续记忆甚至可能让错误越积越深。
