# Volvence 独立第三幕：部署方式

## 旁白

Volvence 的部署很简单：Base 模型和 Adapter 模型统一部署，形成一套共享模型服务。每个用户不拥有一套模型，只拥有一份独立的 Profile。

Base 模型负责通用能力：语言、知识、推理和工具使用。它回答的是，模型能不能听懂、想明白、把事情做出来。

Adapter 模型是所有用户共享的 Volvence 能力。它保存：

- 通用语义本体论
- 抽象动作族先验
- 抽象切换先验
- 预测误差 解释先验
- 安全边界先验
- 默认关系动力学

它回答的是，面对不同状态，应该怎样理解、怎样决策、怎样从结果中学习。

用户档案完全不同。它不是模型权重，也不是每个用户一份微调模型。它只保存这个人的真实状态：

- 实际用户模型取值
- 实际关系状态轨迹
- 具体记忆
- 不同抽象策略对这个用户的有效性记录
- 这个用户的策略保持与切换偏好
- 已经作出的承诺和尚未完成的事项
- 用户授权范围和不可越过的边界事实

一次请求到来，系统先根据用户身份，从隔离的 Profile 存储中读取获授权的状态，再把它动态加载到共享模型服务。Base 和 Adapter 不变，变化的只是这次请求带入的用户状态。

因此规模化也很直接：模型节点可以无状态扩容，很多用户共享同一套 Base 和 Adapter；Profile 独立存储、独立加载、互不混淆。请求结束后，新的记忆和结果只回到对应用户的 Profile。

一句话总结：共享的是语言、决策与学习能力；隔离的是每个人的状态、关系与记忆。这就是 Volvence 的部署方式。
