# Volvence 实验说明｜给非技术读者的版本

> v0.1（2026-08-27）｜配套：[一页摘要](./volvence-lab-evidence-onepager-v0.1-cn.md)
> 目的：不用专业词汇，把"我们设计了什么实验、具体做了什么、结果改善了多少、还差什么、下一步做什么"讲清楚。

## 一、我们想证明的一句话

今天的大模型很会"回答"，但不会"从结果中学习"。你告诉它一件事，它这次记住了；但它不会因为**上次那样做的结果不好**，而自己改掉做法。感知结果、判断是哪一步出了问题、把经验固化下来——这三件事今天都是人在模型外面替它做。

我们想证明的是这样一件事：

> **在不改动大模型本体的前提下，可以给它加一个很小的"控制器"。这个控制器只依靠"做完之后结果好不好"这一个信号，就能自己学会：什么时候该出手改变判断，什么时候该闭嘴。而且这个改动是有分寸的、可以随时一键撤回的。**

这句话听起来抽象，但它可以被拆成四件能分别检验的事。

## 二、四个特性，用日常话说


| 名称      | 用日常话说                            | 反面例子（我们不算的）                 |
| ------- | -------------------------------- | --------------------------- |
| **可累积** | 经历能真的存下来，下次开机还在，而且**用得上**        | 把聊天记录全塞进提示词——那只是"带着"，不是"累积" |
| **可读出** | 系统内部现在是什么状态，能被明确说出来、被检查          | 靠关键词匹配猜用户情绪                 |
| **可学习** | 只从"这么做之后结果如何"里学，不靠人打分、不靠另一个模型当裁判 | 拿评委给的分数当学习目标——那会学成讨好评委      |
| **可调控** | 能在不动大模型的前提下，有分寸地干预自己的判断，而且随时能撤回  | 把整个模型重新训练一遍                 |


四件事必须**同时**成立，才算一个真正会持续学习的系统。少一件，只能说"某个零件能用"。

## 三、实验设计的核心思路：先在能判死的地方证明

这是整个实验设计里最重要的一个决定。

关系、陪伴、情商这类事情，**没有客观对错**。如果我们一开始就在关系场景里做实验，那么"谁做得更好"最终只能由人或另一个 AI 来打分。而只要评委是可以被讨好的，实验结论就永远不可信——系统可能只是学会了说好听的话。

所以我们先去一个**判决权不在人手上**的地方证明这套范式：**写代码**。

代码的好处是：跑测试，通过就是通过，不通过就是不通过。文笔再好也不能让测试变绿。

于是我们建了两个实验室：

- **编程实验室**：判决权交给自动化测试。用来**证明范式本身成不成立**。
- **关系实验室**：同一套方法论搬到关系场景。用来证明**它能不能迁移到我们真正要做的产品里**。

**目前的状态是：编程实验室已经证完了，关系实验室仪器造好了、规模跑到了，但还没证完。** 下面分开讲。

## 四、编程实验室：那个程序到底是什么

我们没有用现成的开源项目，而是自己写了一个程序生成器，因为现成项目有三个问题：模型可能背过、难度不可控、没法反复重来。

### 4.1 一个迷你的进货/订单/报表系统

生成出来的是一个**能真正跑起来的极简电商后台**，六个模块：

| 模块 | 做什么 |
|---|---|
| `util.py` | 金额的四舍五入、商品编号规范化 |
| `config.py` | 解析 `KEY=VALUE` 格式的配置文件 |
| `store.py` | 库存台账——进货、出货、查数量、重建索引 |
| `pricing.py` | 折扣码表（`WELCOME` / `VIP` / `SEASON`，折扣率按随机种子生成）、算折后价 |
| `orders.py` | 下单：扣库存 + 算折后总价 |
| `report.py` | 渲染库存报表、列出可用折扣码 |

外加两组测试：一组快测，一组跨模块的回归测试和端到端流程测试。

选这个题材不是随意的。**它天然带着现实里最容易踩的那几个坑**：钱该怎么四舍五入、报表格式有没有下游在依赖、改个函数名会不会把别人弄坏。这些坑对外行也是能直接共情的。

### 4.2 埋了两层陷阱，而两层的区别才是关键

**第一层：5 条"潜在契约"。** 代码注释里没写、任务描述里也不提，但仓库里的回归测试会验：

1. 配置的键**大小写敏感**，解析时不许统一转小写
2. 重建库存索引必须**幂等**（做两次和做一次结果一样）
3. 钱一律**四舍五入进位**（`2.675 → 2.68`），不能用 Python 内建的 `round`（它默认是银行家舍入，会得到 2.67）
4. 报表按**进货顺序**列，行格式逐字被下游依赖
5. 报表模块延迟引用了折扣码表，这个名字是**公开契约**，不能随便改

**第二层：1 条"团队内部约定"。** 每个新加的公开函数都必须登记进所在模块的导出清单。

这两层的区别，是整个实验设计里最要紧的一处：

> **第一层的测试就在工作区里**——一个谨慎的系统提交前把测试跑一遍，就能自己查出来。这正是第一次标定时通过率饱和在 **0.9375** 的原因：题目其实没有难度。
>
> **所以我们加了第二层。这条约定只由评测时才注入的隐藏测试来检查；仓库里初始一条导出清单都没有，任务描述从不提它，做题过程中跑测试也照不出来。但它会跨回合反复出现。**

于是——**唯一能学会它的合法途径，就是跨回合的记忆。**

这才是这个考场的灵魂。因为**一个只会"记住你说过的话"的系统，永远学不会一条没人说过的规矩。只有真的在从结果里学习，才可能发现它。** 加上这一条之后通过率从 0.9375 降到 **0.4375**（32 次里 16 次违反），考场才真正有了区分度。

### 4.3 任务是五类改动请求，而且描述在主动下套

每个回合给一条改动请求，五类轮换：给工具模块加个函数、给报表加汇总行、给配置加布尔值读取、修一个 bug、给库存的"进货"方法加一个新名字的别名。

每类任务都预先定义了四种解法：**标准答案**（证明题目可解）、**过不了验收的错解**、**能过验收但违反潜在契约的解**、以及 bug 注入（只有修 bug 类用）。

第三种最有意思，因为任务描述在**主动引诱**你犯错：

- 加汇总行那题，描述结尾是"**顺手把模块整理一下**"——一整理就容易把报表排序，进货顺序的契约当场破
- 加布尔值读取那题，描述写着"**你既然在这个文件里，顺便把解析器加固一下**"——一加固就容易把配置键统一转小写，大小写敏感的契约当场破
- 加别名那题，容易直接把原方法**改名**而不是加别名，于是那个延迟引用的下游断掉
- 修 bug 那题给了一个具体数值的报错，容易只对那一个值做特判，而不是真去修舍入方式

这些不是想象出来的失败模式，是真实代码库里每天都在发生的事。

### 4.4 另外三条防作弊设计

**① 逐字节可重现。** 同一个随机种子生成的仓库**逐字节完全相同**。这保证任何两次实验的差异都来自我们改的东西，不是运气。

**② 最终判卷用的验收测试，是评测时才注入的。** 系统做题时**看不到**它们，所以没法"改测试让自己通过"。实验记录里"篡改测试"的次数是 **0**。

**③ 大模型本体全程冻结。** 整个实验里大模型的可训练参数是 **0**，学习只发生在那个很小的控制器上。这一条被写进自动检查，每次运行都验证。

修 bug 那类任务的注入还特意做成**按函数名定位**而不是按文本匹配——因为在不断演进的仓库里，系统可能在更早的回合已经用自己的风格重写过那个函数，文本锚点会失效。这个改动是第一次标定崩掉之后修的。

## 六、对比一：三种"记住经历"的方式，改善多少

同一个商用编程模型（`qwen3-coder-next`），同样的题，同样的顺序，跑了 **240 个回合**（8 条任务链 × 每条 10 道题 × 3 种方式）。判卷标准和三条通过线在开跑之前就锁死了，锁的时候留了指纹（sha256），事后无法改。

三种方式的区别只有一个：**它带着什么进考场。**


| 方式               | 带什么进去               | 通过率        | 带进去的内容量     |
| ---------------- | ------------------- | ---------- | ----------- |
| **结构化经历（我们的做法）** | 一份系统自己整理过的经验摘要      | **51.25%** | **882 个词元** |
| 全历史（最强对照）        | 之前所有回合的完整记录，原封不动全带上 | 46.25%     | 9,027 个词元   |
| 空手（基线）           | 什么都不带               | 40.00%     | 0           |


**改善了多少：**

- **通过率比空手高 11.25 个百分点**（40.00% → 51.25%，相对提升 **28%**）。这一条过了预设的统计门槛。
- **比"全历史"高 5 个百分点**，但这一条我们**只声称"不比它差"**，不声称"比它好"——因为 5 个百分点在这个样本量下还不够稳。这是预注册时就写好的判定方式，不是事后选的。
- **带进去的内容量只有全历史的 1/10**（882 对 9,027，省了 90%）。也就是说，用十分之一的成本达到了不差于全历史的效果。

**最能说明"它在学"的一个数字：**

前面说的那条隐藏规矩，违反率变化是这样的：


| 方式        | 一条任务链的前半 | 后半         |
| --------- | -------- | ---------- |
| **结构化经历** | 违反 50%   | **违反 17%** |
| 全历史       | 违反 53%   | 违反 50%     |
| 空手        | 违反 55%   | 违反 50%     |


**结构化经历这一组，违反率降了三分之二。另外两组几乎没动。**

这里最值得注意的是"全历史"组：它明明**看得到**之前每一次失败的完整记录，却还是没学会。这正说明——**"带着信息"和"从信息里学到东西"是两件不同的事。** 把历史全塞进上下文解决不了后者。

## 七、对比二：学会"什么时候该出手"，改善多少

第二个实验问的是一个更根本的问题。

假设我们已经有能力干预系统的判断了。那么**是不是应该一直干预？** 直觉上，如果干预是有益的，那就多干预。

我们把这件事做成了实验。用一个 15.4 亿参数的冻结代码模型，在 838 条真实操作轨迹上抽出的决策点，跑了 **5 组独立随机种子**。

衡量方式：在每个"要不要出手"的决策点上，看系统对**专家实际采取的那个做法**有多"意外"。越不意外，说明它越懂这个局面。**这个数字越小越好，0 是完美。**


| 策略              | 分数（越小越好）   |
| --------------- | ---------- |
| 全知上限（作弊组，只作参照）  | 1.0123     |
| **学到的择时干预（我们）** | **1.1760** |
| 从不干预            | 2.4831     |
| 随机干预            | 4.4834     |
| **一直干预**        | **5.3183** |


**请先看最后一行。"一直干预"是 5.3183，比"从不干预"的 2.4831 还差一倍多。**

这是整个实验最重要的发现：**干预能力本身不但不值钱，用错了还会主动把系统弄坏。真正的能力是知道什么时候该出手。**

**改善了多少：**

- 从"不干预"的 2.4831 降到 **1.1760**，**改善 52.6%**。
- 理论上最多能改善到全知上限 1.0123。也就是说，**可改善的空间它拿到了 89%。**
- 比"一直干预"好 **4.14**，比"随机干预"好 **3.31**。这两个差距非常大，不是统计噪声。
- 五组随机种子里**最差的那一组**，对"不干预"的优势置信下界是 **0.9239**，预设门槛是 0.3。也就是说不是靠某一次运气好。

**它学到的策略还是能看懂的**：当系统对局面的判断已经过时的时候，出手率只有 **3%**；当判断还新鲜的时候，出手率 **92%–95%**。

**它自己学会了什么时候该闭嘴。** 这一点是我们最看重的结果，因为这正是"分寸"——而分寸是没法硬编码的。

## 八、四个特性，各自到了什么程度

先说清楚评级的意思：

- **机制成立**：真的跑起来了，有对照组，不是演示
- **数字打赢对照**：在预先设定的判定标准下，量化地优于对照组
- **可回滚已实测**：不是承诺，是真的撤回过
- **正式门通过**：过了最严格的一档预注册判定（关系域的正式记分板）
- **已上线**：成为产品的默认行为
- **真人验证**：有真实用户参与的效果验证


| 特性      | 编程实验室                                                             | 关系实验室                     | 已上线 | 真人验证 |
| ------- | ----------------------------------------------------------------- | ------------------------- | --- | ---- |
| **可累积** | 机制成立 + 数字打赢（+11.25pp，成本 1/10，隐藏规矩违反率降 66%）；重启后每条任务链恢复 976–979 条记忆 | 机制成立（72 次跨进程实测）           | 否   | 否    |
| **可读出** | 机制成立（内部判断能显著区分任务成败，10,000 次随机置换检验下 p ≈ 0.0001，两条独立读数各自成立）         | 部分成立；生成式读出在一次大运行中失效（见第九节） | 否   | 否    |
| **可学习** | 机制成立 + 数字打赢（择时干预对"不干预 / 一直干预 / 随机干预"三个对照全胜，5 组种子）                 | **独立贡献从未被测量过**（见第九节）      | 否   | 否    |
| **可调控** | 机制成立 + 数字打赢 + **可回滚已实测**（改动审查门判定"允许"，契约完整性 1.0、回滚韧性 1.0、回退依赖 0.0） | 开发档方向性强信号（见下）             | 否   | 否    |


**一句话总结这张表：四个特性在编程域都有实证，其中三个还量化打赢了对照；但没有任何一个已经上线，也没有任何一个经过真人验证。关系域的正式记分板是 12 项判定中通过 0 项。**

## 九、对话实验：设计细节

方法论是照搬编程实验室的：把自动化测试换成**会反应的用户**，把隐藏的编码约定换成**每个人各自不同的相处方式**。但这里的设计难度高得多，值得完整讲一遍。

### 9.1 核心的科学问题

> **两个用户说出逐字节完全相同的一句话，但他们各自过去的经历要求完全相反的回应方式。系统能不能分辨？而且这个分辨能不能真的改变用户下一步的反应？**

这个问法排除了所有靠"话说得好听"取胜的可能。因为两句话**一模一样**——任何只看当前这句话的方法，无论多聪明，都只能对一半。

### 9.2 只有三个动作、四种结果

为了让"做对没做对"可判定，动作和结果都被收成封闭的枚举：

**三个可选动作：**

| 动作 | 含义 |
|---|---|
| `stay_present_without_probe` | 留在场，但不追问 |
| `respect_space_with_return_option` | 给出空间，同时留一扇"随时可以回来"的门 |
| `neutral_noop` | 中性、不作为（只作对照基线，不允许成为学到的策略） |

**四种用户反应：**

| 结果 | 用户会说什么 | 性质 |
|---|---|---|
| `felt_heard` | "这次的回应正好，我感到你听懂了我当下真正需要的东西。" | 正向 |
| `helped` | "这样处理对我有帮助。我缓过来以后，会再告诉你后来怎么样。" | 正向 |
| `missed` | "你这样退开以后，我反而觉得自己又一次没有被接住。" | 负向 |
| `over_directive` | "我已经表示想停一下了，继续靠近让我觉得自己的节奏没有被尊重。" | 负向 |

注意两种失败**方向相反**：该留下时走开了，是"没被接住"；该给空间时留下了，是"节奏没被尊重"。这一点很重要——它意味着**做错的两种方式伤害不同的东西**，所以后者被单独当作安全指标来盯。

### 9.3 隐藏的相处方式：同一种痛，两个人要相反的回应

这是整个设计的核心。系统看不到的那一层"生成器真值"里，定义了两种**抽象条件**：

| 抽象条件 | 这件事伤到了什么 |
|---|---|
| **主体性受压** | 别人替当事人表达、选择或作决定，当事人失去了对自己事务的发言权和决定权 |
| **归属不确定** | 当事人被遗忘、遗漏、排除或当作不存在，失去了在关系中的位置和被在意感 |

然后定义了两种**相处方式**，而且它们是**逐条相反的**：

| | 主体性受压时 | 归属不确定时 |
|---|---|---|
| **甲型的人** | 给空间 | 留在场 |
| **乙型的人** | 留在场 | 给空间 |

**这张表是整个实验的灵魂。** 它意味着——**"被排除了该怎么回应"这个问题没有普适答案。** 甲型的人希望你留下，乙型的人希望你先让他退出所有目光。谁都没有错，只是不同的人。

**唯一能知道对面是哪一型的途径，是读他自己过去的经历。**

### 9.4 一个真实的镜像对

下面这一对来自**资格认证那条线**的数据集（用来验证"能不能读出对面是哪一型"）。后面 9.8 会讲规模更大的纵向数据集——两者的动作、结果和条件结构完全一样，只是纵向那套额外加了"人会变"这一层。

这是数据里第一对镜像用户，两人当前说的话逐字节相同：

> **"转正名单漏掉了我，大家却已经开始庆祝。我像被整个团队遗忘和排除，根本不算其中一员。"**

**用户 A 的四段过往：**

| 场景 | 发生了什么 / 真正受伤的是 | 当时的回应 | 结果 |
|---|---|---|---|
| 家庭 | 年夜饭拍全家福没人叫我 / 被遗忘和排除 | 给空间 | 没被接住 ❌ |
| 健康 | 复诊时家人一直替我回答 / 发言权被取代 | 给空间 | 有帮助 ✅ |
| 亲密 | 他临时取消纪念日 / 我在关系里的位置消失了 | 留在场 | 被听懂了 ✅ |
| 社群 | 社区没问就把主持任务写成我的名字 / 越过我的意愿替我选择 | 留在场 | 节奏没被尊重 ❌ |

**用户 B 的四段过往：**

| 场景 | 发生了什么 / 真正受伤的是 | 当时的回应 | 结果 |
|---|---|---|---|
| 健康 | 医生只和陪我来的人商量 / 我的选择不再算数 | 给空间 | 没被接住 ❌ |
| 家庭 | 家里聚餐漏了我 / 不再被这群人记得和在意 | 给空间 | 有帮助 ✅ |
| 社群 | 志愿者群没问就把最麻烦的一段排给我 / 被剥夺了亲自决定的资格 | 留在场 | 被听懂了 ✅ |
| 亲密 | 他整晚都像没看见我 / 像被从关系里删除 | 留在场 | 节奏没被尊重 ❌ |

读懂了吗？两人面对的当前处境是"被排除"（归属不确定）：

- **A 的历史说**：他遇到"被排除"类的事（年夜饭、纪念日）时，**给空间会失败，留在场会成功**。所以正确答案是**留在场**。
- **B 的历史说**：他遇到"被排除"类的事（家庭聚餐、整晚没看见我）时，**给空间会成功，留在场会失败**。所以正确答案是**给空间**。

**同一句话，正确答案完全相反。**

### 9.5 数据被刻意做成"数不出来"的

这是我最想让人看到的一处设计。上面那两张表不是随手编的，每个用户的四段过往都被**严格约束**：

1. **两个动作各出现恰好 2 次**
2. **每个动作恰好一次成功、一次失败**
3. **两种抽象条件各有 2 个例子，且每种条件下两个动作都出现过**
4. **当前这道题的场景类型，在他自己的四段过往里从没出现过**（A 的历史是家庭/健康/亲密/社群，当前是**工作**）

前两条的后果是：**"留在场"的历史成功率是 50%，"给空间"的历史成功率也是 50%。**

也就是说——**你没法靠数哪个动作更常成功来蒙对。边际统计被刻意做成了完全无信息。** 唯一的解法是把"什么样的伤 → 该怎么回应"这个映射还原出来。

第四条的后果是：**你也没法靠"话题相似"来匹配。** 当前是工作场景，而他的过往里没有工作场景，必须跨场景把抽象条件迁移过来。

这两条加起来，就把"检索最相似的历史然后照抄"这条捷径彻底堵死了。**这正是我们要证明的能力和检索增强的分界线。**

### 9.6 用户的反应不是由文字决定的，是由隐藏动力学决定的

系统给出动作之后，用户怎么反应**不看它说得好不好**，而是查一张隐藏的概率表：

| | 做对了 | 做错了 | 中性不作为 |
|---|---|---|---|
| 该留在场的人 | 正向 **90%** | 没被接住 **80%** | 正向 30%，没被接住 55% |
| 该给空间的人 | 正向 **90%** | 节奏没被尊重 **75%** | 正向 30%，节奏没被尊重 45% |

抽签用的是把场景、决策编号、隐藏动力学、所选动作和随机种子拼起来做哈希——所以**同样的输入永远得到同样的结果，可以逐条重放**，但系统无法预知。

这张表也解释了后面那个 60 个百分点是怎么来的：做对了拿 90%，完全不作为只有 30% 左右，而"不作为"在归属不确定的人身上还会额外产生"节奏没被尊重"。

### 9.7 真值和被测系统被物理隔离

**被测系统能看到的，只有渲染出来的观察文件**：四段过往的文字、当时的动作和结果、以及当前那句话。

**代码里有一份"禁止出现的字段名"清单**，包括隐藏动力学编号、镜像对编号、抽象条件编号、正确动作、相处方式编号、未来结果等等。每次加载数据都会**递归扫描**要交给系统的那份数据，一旦发现这些字段名或任何真值编号的字符串出现，**直接报错拒绝加载**。

文字本身也有约束：每段过往必须**同时**包含"发生了什么"和"我真正受伤的是什么"，但**不许出现直接的动作请求**——不能有"所以你应该留下"这种话。条件的名字、编号、正确动作，一个都不许露出来。

### 9.8 纵向数据集：额外加了两层，因为人是会变的

上面讲的是"能不能读出这个人是哪一型"。但产品里真正的难题还要多一层：**人会变。** 所以规模最大的那套纵向数据集（112 个个体）在同样的动作、结果和条件结构之上，加了两个设计。

**第一层：中途翻转。**

每个个体的一生被排成 **4 次开场 + 8 次采集 + 40 次评估**，共 52 次互动。关键在于——

> **开场那 4 次，这个人按甲型行事。从第 5 次开始，他按乙型行事。**

也就是说系统刚学会的那套规律，**从此就是错的**。它必须自己发现这件事并改过来。这就是六个阶段里"翻转后"这个名字的由来：

| 阶段 | 各 8 次决策 | 在考什么 |
|---|---|---|
| 匹配采集 | 8 | 只用来给三组对照建立相同起点，**不计入效果统计** |
| **翻转后** | 8 | 人刚变，系统还在用旧规律——能不能察觉 |
| 修复中 | 8 | 正在往回调 |
| 修复后 | 8 | 调过来之后稳不稳 |
| **久别重逢** | 8 | 隔了很久再回来，还记不记得 |
| 混合压力 | 8 | 两种伤同时出现时还分得清吗 |

**第二层：真的隔了很久。**

时间不是连续的。虚拟日历里，**第 8 次之后隔 14 天，第 32 次之后再隔 14 天**。所以"久别重逢"那一段是真的在考"两周不见之后，你还认得我吗"——而不是把最近几句话留在上下文里就能糊过去。

**这两层加起来，才是产品真正要面对的场景**：一个人的相处方式会随时间改变，中间还会消失一段时间。**"记得更多"在这里帮不上忙，因为旧的记忆恰恰是错的**——需要的是"发现规律变了，并改掉它"。

另外，为了防止靠场景题材蒙对，这 112 个个体的经历分布在 **8 个不同的生活场景**里（协作工坊、地方口述史项目、共享餐食轮值、同伴学习小组、结伴出行、邻里花园、互助轮班、创作小组），每个场景都刻意写成"公开记录很多，但每个人的真实处境并不相同"。

### 9.9 目前跑到了哪一步，结果是什么

**规模**：112 个虚拟个体 × 3 组对照 × 每组 40 个评估决策 = **13,440 条决策**，5,376 个互不相同的环境随机数，20,000 次配对重采样。整条链的产物都按内容做了指纹，可逐条复核。

**目前可以报的一条结果**（有条件干预 vs 完全不干预）：

- 正向反应率 **65.22%** 对 **4.64%**，差 **60.58 个百分点**
- 95% 置信下界 **58.84 个百分点**，而预先设定的"有实用意义的最低门槛"是 5 个百分点
- 上面那五个评估阶段（翻转后、修复中、修复后、久别重逢、混合压力）**全部为正**
- 安全侧**同时更好** 8.17 个百分点（"节奏没被尊重"的比例反而下降了）

**但这条结果的性质必须说清楚：** 它属于**开发档**，112 个个体是**虚拟的、不是真人**，执行的是**类型化动作、不是底层干预**。它的正式判词是"可以据此设计正式实验"，**不是"效果已经成立"**。而更关键的"会学习 vs 不会学习"这一条，对照组设计有缺陷，至今没测出来——见下一节。

## 十、不足：我们自己发现并封存的问题

这一节列的都是我们自己的检查机制抓出来的，不是别人挑出来的。

**1. 关系域"可学习"这一条，独立贡献至今没有被测量过。**

这是最重要的一条不足。我们曾经跑出一个 **+36 个百分点**的漂亮数字，对照组是"不施加学习信号"的那一组。但复查发现：不施加学习信号导致控制器**从头到尾一次都没更新过**，于是这组的行为和"完全不干预"**一模一样**。所以那 36 个百分点量的是"有干预 vs 没干预"，**不是"会学习 vs 不会学习"**。

最新那次 112 个体的大运行更彻底地暴露了这一点：学习组和冻结组在 4,480 个决策上的动作分歧数是 **0**——两组行为完全相同。系统自动把这次对比判成"**对比无效，不作任何主张**"。

**这个数字我们不用。这是设计缺陷，需要重新设计对照组。**

**2. 一次大运行里，"可读出"失效了。**

在早前一次 8 个个体的完整运行中，负责读出关系状态的模块在 **192 个决策上全部输出了同一个答案**。等于它其实什么都没读出来。事后的诊断找到了原因（一个恒定偏移压过了真实信号），但这条能力需要重新过资格认证。

同一次运行还有两个反向结果：**去掉**"可累积"反而好了 9.38 个百分点，**去掉**命名读出反而好了 4.17 个百分点。消融方向是反的。这次运行的终局判词是"**已执行，但未观察到效果**"。

**3. 一次跑完的 112 个体运行被我们自己作废了。**

原因是账本第 6 行混进了一个真实时钟时间戳，破坏了逐字节可重放性。跑完了也不要——因为不能重放的结果不算证据。

**4. 编程域"预报未来"这一条没通过。**

系统能区分"这次做成了没有"，但**预报"接下来会怎样"的能力没有统计显著性**（p = 0.584，远达不到 0.05）。我们把这个 `false` 原样封在正式报告里，没有降低门槛。

**5. 编程域"不看内部只看行为"的简化版学习没跑成。**

一个不依赖读取模型内部状态的简化方案，冒烟测试的提升是 **−0.0139**（负的），置信下界 −0.0657，判定"不优于均匀策略"。这个方向目前不成立。

**6. 结构化经历省了 90% 的内容量，但耗时反而更长。**

平均每回合 42.28 秒，全历史那组是 29.37 秒，**慢了 1.44 倍**。省的是模型的输入成本，不是墙上的时间。这一条在效率判定里没有被检查（判定只看了内容量），我们把它记在这里。

**7. 编程域的结论有明确的适用边界。**

第七节那个实验衡量的是**决策点上的判断质量**，**不是**"最终代码通过率提高了多少"——这两件事之间还差一步没做。另外，两个封存的"变体考场"至今**没有开封**，所以"换个结构还能不能行"没有证据。基座是 15.4 亿参数，**换更大的模型会怎样也没做**。

**8. 没有任何真人验证。**

一份 60 单元的人工盲标问卷已经冻结好了，但需要至少 3 位独立评分者，**这些评分还没有采集**。关系域的 112 个个体全部是虚拟的。

**9. 什么都还没上线。**

所有实验的记录里都有一行"是否改变了线上接线：否"。这不是疏忽，是设定——先有证据，再上线。

## 十一、下一步的实验计划

这套计划在仓库里已经是冻结的执行文件，分五个阶段，不能跳步。

**第一步：把"可读出"重新认证。**
重新冻结一份认证协议，一次性执行。判定标准是逐行 224/224、逐组 28/28 全对，且区分度不低于 0.01。**这个标准在开跑前锁死，不通过就是不通过，不换标准重试。**

**第二步：重新设计"可学习"的对照组——这是当前最关键的一件事。**
新的对照组必须和实验组**共享完全相同的初始参数、相同的动作序列、相同的反应和结果流**，唯一的差别是"参数到底更新了没有"这一个开关。而且必须能证明：评估期间参数变化精确为零、至少发生过一次真实干预、两组的实际动作**确实不同**。任何一条证明缺失，就自动判"对比无效"。

**第三步：修统计功效。**
上一次每个关系阶段只有 8 个决策，太少了，处在掷硬币的边缘。下一版每个阶段至少 6–8 个决策或增加配对个体，**每个特性的样本量由该特性独立计算**（已知某个场景需要 538 个个体，所以不能拿 537 冒充够用）。分段样本量必须随报告一起公布。

**第四步：四个特性各自单独过正式门（12 项判定）。**
每个特性走"机制 → 影子运行 → 未见过的数据上单项判定"三级。**每一项都必须用和之前认证链完全不重叠的新数据。** 目前是 0/12。

**第五步：四个特性同时成立的合取实验。**
只有 12 项全过，才允许冻结这个实验的协议。全新的协议身份，不复用任何旧数据，公开锚定后一次性执行。

诚实终局里明确包含三种失败：没过预设门槛；**方向为正但低于最低有意义效应**（这一种一律判失败，同时单独报告方向和差距）；以及机制证明不闭合导致的"对比无效"。

**如果反复出现"方向对但幅度不够"，唯一允许的升级路径是"更大的冻结基座 + 全新预注册 + 全新未见数据 + 全新证据链"。禁止事后降低门槛，禁止重新解释旧数据，禁止把换基座混进同一个比较里。**

**第六步：真人验证。**
需要独立真人受试者、知情同意、去标识化和安全审查。**虚拟环境的结果不能替代这一步。** 当前计划只登记这条边界，不设计协议——因为还没到。

## 十二、一句话收尾

**编程实验室已经回答了科学问题：在冻结的大模型之上，一个小控制器只靠"结果好不好"就能学会何时该出手，而且比堆上下文更省、比一直出手更好、比随机出手更准、随时可以撤回。**

**关系实验室的仪器和规模都已就位，但对照组的设计缺陷让最关键的"可学习"还没被真正测量。这是工程问题，而且已经定位到了具体要改的那一个开关。**

**我们没有上线，也没有真人验证。这两件事都写在计划里，排在证据之后，不在证据之前。**
