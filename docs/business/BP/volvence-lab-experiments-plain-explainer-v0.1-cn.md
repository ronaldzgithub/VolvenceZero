# Volvence 实验说明｜给非技术读者的版本

> v0.1（2026-08-27）｜配套：[一页摘要](./volvence-lab-evidence-onepager-v0.1-cn.md)
> 目的：不用专业词汇，把"我们设计了什么实验、具体做了什么、结果改善了多少、还差什么、下一步做什么"讲清楚。
> 文中每个数字都来自已冻结的实验记录，可现场重新计算。

## 一、我们想证明的一句话

今天的大模型很会"回答"，但不会"从结果中学习"。你告诉它一件事，它这次记住了；但它不会因为**上次那样做的结果不好**，而自己改掉做法。感知结果、判断是哪一步出了问题、把经验固化下来——这三件事今天都是人在模型外面替它做。

我们想证明的是这样一件事：

> **在不改动大模型本体的前提下，可以给它加一个很小的"控制器"。这个控制器只依靠"做完之后结果好不好"这一个信号，就能自己学会：什么时候该出手改变判断，什么时候该闭嘴。而且这个改动是有分寸的、可以随时一键撤回的。**

这句话听起来抽象，但它可以被拆成四件能分别检验的事。

## 二、四个特性，用日常话说


| 名称      | 用日常话说                            | 反面例子（我们不算的）                 |
| ------- | -------------------------------- | --------------------------- |
| **可累积** | 经历能真的存下来，下次开机还在，而且**用得上**        | 把聊天记录全塞进提示词——那只是"带着"，不是"累积" |
| **可读出** | 系统内部现在是什么状态，能被明确说出来、被检查          | 靠关键词匹配猜用户情绪                 |
| **可学习** | 只从"这么做之后结果如何"里学，不靠人打分、不靠另一个模型当裁判 | 拿评委给的分数当学习目标——那会学成讨好评委      |
| **可调控** | 能在不动大模型的前提下，有分寸地干预自己的判断，而且随时能撤回  | 把整个模型重新训练一遍                 |


四件事必须**同时**成立，才算一个真正会持续学习的系统。少一件，只能说"某个零件能用"。

## 三、实验设计的核心思路：先在能判死的地方证明

这是整个实验设计里最重要的一个决定。

关系、陪伴、情商这类事情，**没有客观对错**。如果我们一开始就在关系场景里做实验，那么"谁做得更好"最终只能由人或另一个 AI 来打分。而只要评委是可以被讨好的，实验结论就永远不可信——系统可能只是学会了说好听的话。

所以我们先去一个**判决权不在人手上**的地方证明这套范式：**写代码**。

代码的好处是：跑测试，通过就是通过，不通过就是不通过。文笔再好也不能让测试变绿。

于是我们建了两个实验室：

- **编程实验室**：判决权交给自动化测试。用来**证明范式本身成不成立**。
- **关系实验室**：同一套方法论搬到关系场景。用来证明**它能不能迁移到我们真正要做的产品里**。

**目前的状态是：编程实验室已经证完了，关系实验室仪器造好了、规模跑到了，但还没证完。** 下面分开讲。

## 四、编程实验室：环境是怎么造的

我们没有用现成的开源项目，而是自己造了一个"考场"，因为现成项目有三个问题：模型可能背过、难度不可控、没法反复重来。

这个考场是这样设计的：

**1. 题目是程序生成的，可以精确重来。** 给定同一个随机种子，生成出来的代码仓库**逐字节完全相同**。这保证任何两次实验的差异都来自我们改的东西，不是运气。

**2. 判卷交给自动化测试。** 改完代码跑测试，通过就得分。

**3. 验收测试是评测时才注入的。** 这一条是防作弊的关键——系统在做题时**看不到**最终判卷用的那些测试，所以它没法"改测试让自己通过"。实验记录里"篡改测试"的次数是 **0**。

**4. 埋了一条没人告诉它的规矩。** 我们在环境里设了一个团队内部编码约定（相当于"我们这儿的代码都要按某种方式写"）。**任何地方都没有告诉系统这条规矩存在。** 但只要违反，测试就会失败。

这最后一条是整个实验的灵魂。因为——**一个只会"记住你说过的话"的系统，永远学不会一条没人说过的规矩。只有真的在从结果里学习，才可能发现它。**

**5. 难度被调到最难的区间。** 一开始用商用模型跑，通过率 **0.9375**——太简单了，题目区分不出好坏，这次标定我们判为**不合格**并作废。加上那条隐藏规矩之后，通过率降到 **0.4375**（32 次里有 16 次违反了那条规矩）。这才是一个有意义的考场。

**6. 大模型本体全程冻结。** 整个实验里，大模型的可训练参数是 **0**。学习只发生在那个很小的控制器上。这一条被写进自动检查，每次运行都验证。

## 五、编程实验室：具体做了哪五步


| 步骤            | 做了什么                         | 结果              |
| ------------- | ---------------------------- | --------------- |
| **① 标定考场**    | 验证环境可精确重现、难度合适、测试无法被篡改       | 通过              |
| **② 只看不动**    | 系统在旁边观察，记录它的内部判断，但不允许它影响任何行为 | 通过（有一项没通过，见第九节） |
| **③ 记忆对比**    | 三种方式做同样的题，比通过率和成本            | 通过              |
| **④ 学习何时出手**  | 让控制器自己学"什么时候该干预"             | 通过              |
| **⑤ 上线审查与回滚** | 把学到的成果送去"改动审查门"，并实测回滚        | 通过              |




## 六、对比一：三种"记住经历"的方式，改善多少

同一个商用编程模型（`qwen3-coder-next`），同样的题，同样的顺序，跑了 **240 个回合**（8 条任务链 × 每条 10 道题 × 3 种方式）。判卷标准和三条通过线在开跑之前就锁死了，锁的时候留了指纹（sha256），事后无法改。

三种方式的区别只有一个：**它带着什么进考场。**


| 方式               | 带什么进去               | 通过率        | 带进去的内容量     |
| ---------------- | ------------------- | ---------- | ----------- |
| **结构化经历（我们的做法）** | 一份系统自己整理过的经验摘要      | **51.25%** | **882 个词元** |
| 全历史（最强对照）        | 之前所有回合的完整记录，原封不动全带上 | 46.25%     | 9,027 个词元   |
| 空手（基线）           | 什么都不带               | 40.00%     | 0           |


**改善了多少：**

- **通过率比空手高 11.25 个百分点**（40.00% → 51.25%，相对提升 **28%**）。这一条过了预设的统计门槛。
- **比"全历史"高 5 个百分点**，但这一条我们**只声称"不比它差"**，不声称"比它好"——因为 5 个百分点在这个样本量下还不够稳。这是预注册时就写好的判定方式，不是事后选的。
- **带进去的内容量只有全历史的 1/10**（882 对 9,027，省了 90%）。也就是说，用十分之一的成本达到了不差于全历史的效果。

**最能说明"它在学"的一个数字：**

前面说的那条隐藏规矩，违反率变化是这样的：


| 方式        | 一条任务链的前半 | 后半         |
| --------- | -------- | ---------- |
| **结构化经历** | 违反 50%   | **违反 17%** |
| 全历史       | 违反 53%   | 违反 50%     |
| 空手        | 违反 55%   | 违反 50%     |


**结构化经历这一组，违反率降了三分之二。另外两组几乎没动。**

这里最值得注意的是"全历史"组：它明明**看得到**之前每一次失败的完整记录，却还是没学会。这正说明——**"带着信息"和"从信息里学到东西"是两件不同的事。** 把历史全塞进上下文解决不了后者。

## 七、对比二：学会"什么时候该出手"，改善多少

第二个实验问的是一个更根本的问题。

假设我们已经有能力干预系统的判断了。那么**是不是应该一直干预？** 直觉上，如果干预是有益的，那就多干预。

我们把这件事做成了实验。用一个 15.4 亿参数的冻结代码模型，在 838 条真实操作轨迹上抽出的决策点，跑了 **5 组独立随机种子**。

衡量方式：在每个"要不要出手"的决策点上，看系统对**专家实际采取的那个做法**有多"意外"。越不意外，说明它越懂这个局面。**这个数字越小越好，0 是完美。**


| 策略              | 分数（越小越好）   |
| --------------- | ---------- |
| 全知上限（作弊组，只作参照）  | 1.0123     |
| **学到的择时干预（我们）** | **1.1760** |
| 从不干预            | 2.4831     |
| 随机干预            | 4.4834     |
| **一直干预**        | **5.3183** |


**请先看最后一行。"一直干预"是 5.3183，比"从不干预"的 2.4831 还差一倍多。**

这是整个实验最重要的发现：**干预能力本身不但不值钱，用错了还会主动把系统弄坏。真正的能力是知道什么时候该出手。**

**改善了多少：**

- 从"不干预"的 2.4831 降到 **1.1760**，**改善 52.6%**。
- 理论上最多能改善到全知上限 1.0123。也就是说，**可改善的空间它拿到了 89%。**
- 比"一直干预"好 **4.14**，比"随机干预"好 **3.31**。这两个差距非常大，不是统计噪声。
- 五组随机种子里**最差的那一组**，对"不干预"的优势置信下界是 **0.9239**，预设门槛是 0.3。也就是说不是靠某一次运气好。

**它学到的策略还是能看懂的**：当系统对局面的判断已经过时的时候，出手率只有 **3%**；当判断还新鲜的时候，出手率 **92%–95%**。

**它自己学会了什么时候该闭嘴。** 这一点是我们最看重的结果，因为这正是"分寸"——而分寸是没法硬编码的。

## 八、四个特性，各自到了什么程度

先说清楚评级的意思：

- **机制成立**：真的跑起来了，有对照组，不是演示
- **数字打赢对照**：在预先设定的判定标准下，量化地优于对照组
- **可回滚已实测**：不是承诺，是真的撤回过
- **正式门通过**：过了最严格的一档预注册判定（关系域的正式记分板）
- **已上线**：成为产品的默认行为
- **真人验证**：有真实用户参与的效果验证


| 特性      | 编程实验室                                                             | 关系实验室                     | 已上线 | 真人验证 |
| ------- | ----------------------------------------------------------------- | ------------------------- | --- | ---- |
| **可累积** | 机制成立 + 数字打赢（+11.25pp，成本 1/10，隐藏规矩违反率降 66%）；重启后每条任务链恢复 976–979 条记忆 | 机制成立（72 次跨进程实测）           | 否   | 否    |
| **可读出** | 机制成立（内部判断能显著区分任务成败，10,000 次随机置换检验下 p ≈ 0.0001，两条独立读数各自成立）         | 部分成立；生成式读出在一次大运行中失效（见第九节） | 否   | 否    |
| **可学习** | 机制成立 + 数字打赢（择时干预对"不干预 / 一直干预 / 随机干预"三个对照全胜，5 组种子）                 | **独立贡献从未被测量过**（见第九节）      | 否   | 否    |
| **可调控** | 机制成立 + 数字打赢 + **可回滚已实测**（改动审查门判定"允许"，契约完整性 1.0、回滚韧性 1.0、回退依赖 0.0） | 开发档方向性强信号（见下）             | 否   | 否    |


**一句话总结这张表：四个特性在编程域都有实证，其中三个还量化打赢了对照；但没有任何一个已经上线，也没有任何一个经过真人验证。关系域的正式记分板是 12 项判定中通过 0 项。**

## 九、关系实验室：做了什么，到哪一步

方法论是照搬的：把自动化测试换成**会反应的用户**，把隐藏编码约定换成**每个人各自不同的相处方式**。

核心的科学问题设计得很干净：

> 两个用户说出**逐字一样**的话，但他们各自过去的经历要求**完全相反**的回应方式。系统能不能分辨？而且这个分辨能不能**真的改变**用户下一步的反应？

**规模已经跑到了**：112 个虚拟个体 × 3 组对照 × 每组 40 个决策 = **13,440 条决策**，5,376 个互不相同的环境随机数，20,000 次配对重采样。整条链的产物都按内容做了指纹、可逐条复核。

**目前可以报的一条结果**（有条件干预 vs 完全不干预）：

- 正向反应率 **65.22%** 对 **4.64%**，差 **60.58 个百分点**
- 95% 置信下界 **58.84 个百分点**，而预先设定的"有实用意义的最低门槛"是 5 个百分点
- 五种关系阶段（修复中、混合压力、修复后、反转后、久别重逢）**全部为正**
- 安全侧**同时更好** 8.17 个百分点（过度指导的比例反而下降了）

**但这条结果的性质必须说清楚：** 它属于**开发档**，112 个个体是**虚拟的、不是真人**，执行的是**类型化动作、不是底层干预**。它的正式判词是"可以据此设计正式实验"，**不是"效果已经成立"**。

## 十、不足：我们自己发现并封存的问题

这一节列的都是我们自己的检查机制抓出来的，不是别人挑出来的。

**1. 关系域"可学习"这一条，独立贡献至今没有被测量过。**

这是最重要的一条不足。我们曾经跑出一个 **+36 个百分点**的漂亮数字，对照组是"不施加学习信号"的那一组。但复查发现：不施加学习信号导致控制器**从头到尾一次都没更新过**，于是这组的行为和"完全不干预"**一模一样**。所以那 36 个百分点量的是"有干预 vs 没干预"，**不是"会学习 vs 不会学习"**。

最新那次 112 个体的大运行更彻底地暴露了这一点：学习组和冻结组在 4,480 个决策上的动作分歧数是 **0**——两组行为完全相同。系统自动把这次对比判成"**对比无效，不作任何主张**"。

**这个数字我们不用。这是设计缺陷，需要重新设计对照组。**

**2. 一次大运行里，"可读出"失效了。**

在早前一次 8 个个体的完整运行中，负责读出关系状态的模块在 **192 个决策上全部输出了同一个答案**。等于它其实什么都没读出来。事后的诊断找到了原因（一个恒定偏移压过了真实信号），但这条能力需要重新过资格认证。

同一次运行还有两个反向结果：**去掉**"可累积"反而好了 9.38 个百分点，**去掉**命名读出反而好了 4.17 个百分点。消融方向是反的。这次运行的终局判词是"**已执行，但未观察到效果**"。

**3. 一次跑完的 112 个体运行被我们自己作废了。**

原因是账本第 6 行混进了一个真实时钟时间戳，破坏了逐字节可重放性。跑完了也不要——因为不能重放的结果不算证据。

**4. 编程域"预报未来"这一条没通过。**

系统能区分"这次做成了没有"，但**预报"接下来会怎样"的能力没有统计显著性**（p = 0.584，远达不到 0.05）。我们把这个 `false` 原样封在正式报告里，没有降低门槛。

**5. 编程域"不看内部只看行为"的简化版学习没跑成。**

一个不依赖读取模型内部状态的简化方案，冒烟测试的提升是 **−0.0139**（负的），置信下界 −0.0657，判定"不优于均匀策略"。这个方向目前不成立。

**6. 结构化经历省了 90% 的内容量，但耗时反而更长。**

平均每回合 42.28 秒，全历史那组是 29.37 秒，**慢了 1.44 倍**。省的是模型的输入成本，不是墙上的时间。这一条在效率判定里没有被检查（判定只看了内容量），我们把它记在这里。

**7. 编程域的结论有明确的适用边界。**

第七节那个实验衡量的是**决策点上的判断质量**，**不是**"最终代码通过率提高了多少"——这两件事之间还差一步没做。另外，两个封存的"变体考场"至今**没有开封**，所以"换个结构还能不能行"没有证据。基座是 15.4 亿参数，**换更大的模型会怎样也没做**。

**8. 没有任何真人验证。**

一份 60 单元的人工盲标问卷已经冻结好了，但需要至少 3 位独立评分者，**这些评分还没有采集**。关系域的 112 个个体全部是虚拟的。

**9. 什么都还没上线。**

所有实验的记录里都有一行"是否改变了线上接线：否"。这不是疏忽，是设定——先有证据，再上线。

## 十一、下一步的实验计划

这套计划在仓库里已经是冻结的执行文件，分五个阶段，不能跳步。

**第一步：把"可读出"重新认证。**
重新冻结一份认证协议，一次性执行。判定标准是逐行 224/224、逐组 28/28 全对，且区分度不低于 0.01。**这个标准在开跑前锁死，不通过就是不通过，不换标准重试。**

**第二步：重新设计"可学习"的对照组——这是当前最关键的一件事。**
新的对照组必须和实验组**共享完全相同的初始参数、相同的动作序列、相同的反应和结果流**，唯一的差别是"参数到底更新了没有"这一个开关。而且必须能证明：评估期间参数变化精确为零、至少发生过一次真实干预、两组的实际动作**确实不同**。任何一条证明缺失，就自动判"对比无效"。

**第三步：修统计功效。**
上一次每个关系阶段只有 8 个决策，太少了，处在掷硬币的边缘。下一版每个阶段至少 6–8 个决策或增加配对个体，**每个特性的样本量由该特性独立计算**（已知某个场景需要 538 个个体，所以不能拿 537 冒充够用）。分段样本量必须随报告一起公布。

**第四步：四个特性各自单独过正式门（12 项判定）。**
每个特性走"机制 → 影子运行 → 未见过的数据上单项判定"三级。**每一项都必须用和之前认证链完全不重叠的新数据。** 目前是 0/12。

**第五步：四个特性同时成立的合取实验。**
只有 12 项全过，才允许冻结这个实验的协议。全新的协议身份，不复用任何旧数据，公开锚定后一次性执行。

诚实终局里明确包含三种失败：没过预设门槛；**方向为正但低于最低有意义效应**（这一种一律判失败，同时单独报告方向和差距）；以及机制证明不闭合导致的"对比无效"。

**如果反复出现"方向对但幅度不够"，唯一允许的升级路径是"更大的冻结基座 + 全新预注册 + 全新未见数据 + 全新证据链"。禁止事后降低门槛，禁止重新解释旧数据，禁止把换基座混进同一个比较里。**

**第六步：真人验证。**
需要独立真人受试者、知情同意、去标识化和安全审查。**虚拟环境的结果不能替代这一步。** 当前计划只登记这条边界，不设计协议——因为还没到。

## 十二、一句话收尾

**编程实验室已经回答了科学问题：在冻结的大模型之上，一个小控制器只靠"结果好不好"就能学会何时该出手，而且比堆上下文更省、比一直出手更好、比随机出手更准、随时可以撤回。**

**关系实验室的仪器和规模都已就位，但对照组的设计缺陷让最关键的"可学习"还没被真正测量。这是工程问题，而且已经定位到了具体要改的那一个开关。**

**我们没有上线，也没有真人验证。这两件事都写在计划里，排在证据之后，不在证据之前。**
