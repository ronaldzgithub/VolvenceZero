# 进化涌现 Volvence｜八幕版一页摘要

> 面向蚂蚁集团投资及企业发展部 ｜ 口径同步自《八幕版 BP v0.3》｜ 披露级别：机制与部署形态，不含实现代码、结构参数、训练配方与门控口径

**定调**：今天的大模型会生成，不会从结果中学习——感知、决策、归因、学习这四件事都在模型之外由人补。我们要补的不是模型的知识，是模型的闭环：把状态装载、抽象决策、预测误差、嵌套记忆、主动取证放回模型内部并共用同一条误差信号；再用"共享能力 + 私有用户档案"的部署形态让它对很多人成立，而不给每个人复制一套模型。**关键闭环机制已出现可重复的正向信号，并具备严格消融与失败发现能力；产品规模、开放域泛化与商业结果，是融资与合作之后需要完成的验证。**

| 幕 | 一句话 |

| ③ 部署 | 共享基底 + 共享自适应模型 + 一人一份私有档案：个体化靠加载状态，不靠复制模型 |

| ⑧ 团队与融资 | 四个人闭合"理论—架构—产品—商业"一条链；这一轮买的是把假设变成证据的 18 个月 |

## 二、三个技术分歧点

**① 把闭环放回模型内部，而不是在模型外面加一圈人力。** 提示工程、检索增强、工作流编排解决的都是同一个环节——把信息拿进来；拿进来之后的四件事（在低维空间决策、对结果归因、把有效策略巩固成先验、证据不足时主动取证）仍由人和编排承担。我们把这四件事放回模型内部，并让学习信号来自系统在结果发生之前自己下的注，而不是人事后标注。**其中"状态在第一个词元之前进入注意力"这条差异化主张是我们的押注，不是既成事实**：默认链路目前仍把状态渲染成文本随提示投递，纯潜通道是证据专用、禁止部署的实验臂，识别判据尚未全部通过。

**② 共享能力 + 私有用户档案，而不是每人一份适配器。** 必须先校准代际：新一代已由超网络在一次前向内生成适配器，更新时延与冷启动两格已被抹平，拿 2024 一代当靶子是稻草人。真正剩下的分歧只有一条——**个体的状态与事实该不该由隐式权重承载**。我们的判断是按变化频率、能否被指认、能否被撤销来分工：风格可以进权重，状态不行；可迁移的**结构**进共享自适应模型，这个人的**事实**进可读、可改、可删的档案。我们输两格（隐式风格语气的承载、推理时的上下文预算），且**这个头对头对照实验我们还没有做**。

**③ 与 Era of Experience 的对位：两条有实现、一条相邻、一条真缺口。** 引用必须区分版本——**论文版**明确把"不更新权重、基于环境反馈的上下文内适应"算作强化学习，与我们"冻结基底 + 共享自适应模型"兼容；**访谈版**"大模型是死路"与我们不兼容，我们不引用它给自己背书。四支柱里**两条**我们有对应的可运行实现（成色待验）：经验流对应多时间尺度记忆，非人类的规划与推理对应低维决策空间；有根的奖励**相邻但不同**——我们的预测误差是内禀信号，回答"我预测对了吗"，不回答"世界变好了吗"。**缺的那一条——有根的动作与观察——是真缺口**：我们基本仍在文本与对话通道里，不粉饰，也不写"我们更领先"。

> **两条必须随本页一起转出的口径**：（a）**参数规模分两套**——百亿级基底 + 约 5 亿级自适应模型是 M6–M12 的**发布规格**；**当前验证配置是 15 亿级基底 + 一组微型研究控制器，本页引用的全部实验证据都产生于后者**。（b）**第四幕对话的性质**——通用模型一侧是同一开场白下的实际回复记录，我们这一侧是**按产品设计固化的对照脚本**，用于展示交互形态与决策纪律，不宣称是线上链路的逐字输出；案例情境为虚构。

## 三、证据三态（划分标准固定，不随场合变化）

**已是系统**（有代码、有测试、有回滚路径）
- 在线服务回路与异步学习回路骨架端到端可运行；跨会话状态持久化；跨用户零串流（另一用户各项计数从零开始）。
- 三层拆分（共享基底 / 共享自适应模型 / 私有档案）是代码里的实际结构；个体状态不进共享权重在实现层成立。
- 学习型组件影子双跑（只出报告、不改线上行为）、晋升判据与单点回滚；评测通道只读、训练数据与只读评测集严格分离；多租户控制面与人工接管；封闭内测**服务形态**。
- **删除能力分两段**：**用户记忆的按范围删除已实现并可调用**；**证据文件的范围化删除与删除证据台账仍是影子脚手架、HTTP 端点尚未接线**，排期在下一阶段。架构结论（删除一个用户 = 删除他的档案）成立，交付面尚未补齐。

**已有可重复的正向信号**（有对照臂、有验收门，规模有限）——统称本轮**证据三件套**
- 真实模型链路长测 **510 轮 / 509 条真实轨迹**；受控更新中未观察到明显灾难性遗忘。**同一份产物的晋升判定目前仍是 BLOCKED**，我们不把它当能力证据。
- 一次**定向复跑 32 项：31 通过 / 1 失败**。失败项不是能力下降，而是一项新启用的能力对另一条预测轴产生了**未事先声明的依赖影响，被契约白名单拦下**——失败是被机制发现的，不是被用户发现的。
- **多条预测轴大部分优于基线，其中与状态稳定性相关的一条弱于基线。** 这条负向结果我们没有从表里拿掉：它指向我们对"何时该切换判断模式"的估计还不够稳，而这恰恰是数字分身最需要的一项。

**仍是假设**（写明验证方式）
- 学习型组件成为线上默认决策的主导——**今天线上默认决策仍以结构化流程与启发式为主，缺的是证据不是代码**，这是我们当前第一优先级。
- 开放域泛化与迁移边界；生产时延、单卡可承载用户数与单位推理成本（**没有数字，不编**）；能力能否转化为留存、转化与收入。
- 评估指标尚未按"后果 / 预判"分轴标注，规则本月才确定、尚未写进评估规范。
- **持续更新的控制层可塑性丧失，是本月才发现的自身盲区**：冻结基底规避了基底层，但持续更新的控制层完整继承该缺陷，此前无任何仪表在看；逐项核查后范围比第一判断窄得多。补救分三级（先加只读仪表 → 再做可回滚的保守约束 → 最后才考虑换结构），**三级全部是尚未排期的设计提案，不给任何效果承诺**。

## 四、与蚂蚁的三层分工与核心协同

| 层 | 谁做 | 提供什么 |
|---|---|---|
| 连接与结算层 | **蚂蚁 / 支付宝** | 入口、身份、连接协议、支付与履约闭环、生态分发与信任背书 |
| 行业场景层 | **生态内行业伙伴** | 场景知识、供给、履约能力、行业合规 |
| 认知底座层 | **Volvence** | 第二幕的闭环 + 第三幕的部署形态 |

**我们不做入口、不做结算、不做连接协议，不做供给与履约，不替行业方拿合规资质。这一层是我们唯一想占的位置。**

**核心协同一句话：这个生态能提供的是"后果"，不是"预判"。** 单轮点赞、模型互评分、标注员打分都是在后果缺席时给出的预判，只能做诊断，给智能体设了天花板；是否采纳、是否成交、是否退款、是否复购、是否投诉、是否再次回来，是带真实时间戳、可归因到具体一次建议的后果型延迟标签。**学习真正缺的不是数据量，是有结果的数据。** 诚实补一句：后果型信号同样可被 game（刷单、诱导评价、为返现而"采纳"），信号防污染与异常归因要写进 PoC 第一天的设计，这是要一起做的工作，不是已解决的问题。

## 五、三个候选试点，与明确不做的三件事

选题标准：**有可观测的结果信号 · 有真实的长周期 · 风险可控。**

| 方向 | 场景形态 | 首轮验证指标 |
|---|---|---|
| **A. 商家私域经营 Agent** | 长期客户经营：答疑、跟进、复购提醒、关键时刻转人工 | 授权率、30/90 日留存、任务完成率、转化与复购、人工接管率下降 |
| **B. 生活服务型长期顾问** | 育儿、健康管理、家庭生活决策等长周期陪跑 | 问题解决率、持续使用周数、建议采纳率与 1/7/30 日效果回流 |
| **C. 企业内数字员工** | 客户成功、知识官、销售辅助 | 上岗通过率、单员工承载量、审计事件率、私有化 SLO；并挂载三个直接判据——错误记忆的纠正时延与是否只改这一条、删除执行后的探针残留、每用户边际成本 |

**明确不做：个性化投资建议 · 信贷与风控的替代性决策 · 医疗诊断。** 这三类的结果信号强度其实最高，但风险与合规成本不匹配我们当前阶段——一次错误决策的代价不是留存下降，是不可逆的伤害。我们宁可放弃最好的监督来源。

## 六、四段节奏，与第一阶段只看的两个数

| 阶段 | 只验证 | 交付物 |
|---|---|---|
| **0–30 天** | 一次 60 分钟对齐：贵方内部对"长期交互 + 结果回流"是否已有判断与安排 | 一份共识，或一份明确的"暂不合适" |
| **30–90 天** | 单场景 PoC：授权 → 状态装载 → 决策 → 结果回流 → 受控更新，全链路可审计、可删除、可回滚 | 首批延迟结果标签 + 一条可重复跑的回流管线 |
| **90–180 天** | 对照实验：同场景 vs 通用大模型 + 记忆/RAG 基线，在留存或任务成功率上给出可重复差异**或明确证伪**；同期完成"每人一份适配器 vs 共享能力 + 用户档案"的双臂对照 | 对照报告（含消融与失败项） |
| **180–365 天** | 第二场景复用同一底座；单位经济成立；生态接入形态确定 | 可复制的交付路径 |

**第一阶段只看两个数：授权率**（多少用户愿意开启长期状态）与**结果回流率**（多少次交互能拿到 1/7/30 日的真实结果）。**这两个数不成立，后面所有指标都是空的**——没有后果就没有有根奖励，闭环退化成一个更贵的对话系统。

## 八、Ask、合作形态与杀死条件

**本轮：人民币 6,000 万元 · 投前估值 5 亿元。资金不用于重训通用基础大模型**，用于验证并放大第二幕的闭环、把第三幕的部署做到生产级。投向：核心模型与系统研发 40% · 数据标注与评测 20% · 产品与标杆场景 20% · 算力安全与基础设施 10% · 关键人才与运营 10%，与上表四个阶段一一对应。

冷启动侧有自有约 **6,000 万**全网可触达用户底座（母婴、私域、IP 等场景合作方矩阵，名单可在尽调提供）。**我们不把触达数字等同于用户数**：按跨平台去重后 **1% 完成明确授权并形成有效使用测算，约 60 万有效用户——这是测算口径，不是已实现的转化。** 要验证的是授权率与结果回流率，不是粉丝总数。

**三种合作形态**：战略投资 + 生态接入（首选，资金与场景同时进入）· 纯生态合作（API / 私有化 / 联合试点，与融资解耦，任一试点可单独谈）· 联合研发（共建持续学习的评测标准与开源轻量版）。

**杀死条件**：若在严格消融下，内部闭环不优于外部控制、主动取证不优于随机采样，**我们主动收缩为一家产品型的长期记忆与决策支持公司**——仍有真实业务与收入，但不再宣称持续学习的完整命题。这条写在内部文档里，不是这次谈话才想出来的。

## 九、下一步只请贵方做一件事

**一次 60 分钟对齐**，只回答一个问题：**贵方内部对"长期交互 + 结果回流"这件事，是否已有判断与安排。** 结论是共识或"暂不合适"都可交付——我们不需要在这次会上拿到承诺，只需要知道这条方向在贵方的判断框架里成不成立。技术尽调可现场复跑与代码走查，包括本页所列的每一项证据与每一项缺口。
