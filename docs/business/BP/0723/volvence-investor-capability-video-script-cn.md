# Volvence 投资人能力证明视频脚本

## 一、视频定位

- **主片时长**：约 5 分钟。
- **核心受众**：技术型投资人。
- **核心目标**：不是证明模型“更会说话”，而是证明它能从自然交互中形成目标、感知、决策、反馈和学习闭环。
- **情绪主线**：一个疲惫的人第一次感到，机器不是在给她标准答案，而是在和她一起承担问题。
- **技术主线**：自然输入 → 潜在状态 → 主动追问 → 全景决策 → 关系引导 → 残差流控制 → 结果识别 → 信用归因 → 记忆巩固 → 有界更新。

## 二、全片必须让投资人记住的三句话

1. **调用方始终只提供自然交互，不需要设计反馈接口，也不需要人工告诉模型什么值得学习。**
2. **Volvence 不只生成回答，还在神经网络内部形成任务与关系状态，决定下一步行动，并直接控制理解、推理和表达。**
3. **真实结果出现后，系统自行完成归因、记忆和有界更新，让下一次行动变得更好。**

## 三、逐秒拍摄脚本

### 00:00–00:20｜不是从技术开始，而是从一个人开始

**画面**

黑屏。只听见凌晨房间里的轻微环境声和一个真实用户的声音。随后出现手机锁屏时间：`02:17`。

**用户原声**

> 宝宝又醒了。我明天还要上班。  
> 我已经看过很多方法，可我现在真的不知道，是宝宝出了问题，还是我做错了。

**屏幕字幕**

> 一个问题，通常不只有一个答案。  
> 它还有压力、关系、边界和时机。

**证明点**

先让投资人看见“人”，避免视频从架构和参数开始。

---

### 00:20–00:42｜提出结构性问题

**画面**

普通大模型的聊天窗口快速闪过几个标准答案：规律作息、减少夜奶、营造睡眠环境。画面冻结，然后全部淡出。

**旁白**

> 今天的大模型可以给出正确答案。  
> 但它不知道，此刻最重要的是继续给建议，还是先理解她；  
> 不知道还缺哪条信息；  
> 更不知道七天以后，自己的建议到底有没有帮助她。

**屏幕大字**

> 回答问题，不等于解决问题。  
> 完成一次对话，不等于学会下一次。

### 00:42–01:35｜第一轮：模型先理解“目标、缺口和关系”

**画面**

开始一镜到底的真实屏幕录制。左侧是统一对话接口，右侧是只读模型元信息面板。画面顶部固定显示：

> 真实模型｜固定版本｜无预置目标｜无反馈标签｜无人工切换策略

**左侧自然输入**

> 宝宝8个月，最近总是夜醒，我白天还要上班。

**Volvence 回复**

> 听起来你已经很辛苦了。每晚大约醒几次？目前是否夜奶？已经持续多久？

**右侧模型元信息依次亮起**

| 模型元信息 | 屏幕显示 |
|---|---|
| 目标理解 | 改善宝宝睡眠，同时降低照护者压力 |
| 任务状态 | 根因仍待识别 |
| 关系状态 | 用户压力较高，需要先支持再追问 |
| 当前决策 | 主动追问高价值信息 |
| 待补信息 | 夜醒频率、夜奶情况、持续时间 |
| 关系引导 | 先共情，再澄清 |
| 记忆候选 | 宝宝8个月、用户白天上班 |

**旁白**

> 调用方没有告诉模型目标，也没有编排下一步。  
> Volvence 从原始交互中，同时形成任务状态和关系状态。  
> 它没有立刻给出更多建议，而是选择了此刻信息价值最高的动作：追问。

**证明点**

- 目标不是调用方提交的字段，而是模型从自然交互中形成。
- 追问不是固定工作流，而是模型选择的抽象动作。
- 关系状态与任务状态同时出现，关系不是任务完成后的附加评分。

---

### 01:35–02:28｜第二轮：共同建模，而不是直接下结论

**左侧自然输入**

> 每晚醒4次，有夜奶，已经持续3周。我试过一次戒掉，但哭得太厉害，我没坚持住。

**Volvence 回复**

> 这不是你没有坚持住，而是一次改变同时压到了宝宝和你。我们先不追求一次戒掉：先固定入睡流程，再选择一顿最容易减少的夜奶。三天后只看两个指标：夜醒次数和你的疲惫程度。

**右侧模型元信息依次亮起**

| 模型元信息 | 屏幕显示 |
|---|---|
| 问题建模 | 睡眠习惯、夜奶依赖和照护压力相互影响 |
| 全景计分 | 改善效果、执行难度、照护压力、安全边界 |
| 决策动作 | 分阶段计划 + 降低自责 + 设定可观察指标 |
| 关系引导 | 从“是否坚持”转向“方案是否适合当前条件” |
| 残差流控制 | 理解：去责备；推理：分阶段；表达：支持性、低压力 |
| 记忆证据 | 夜醒4次、夜奶、持续3周、一次激进调整失败 |

**画面细节**

用一条非常短的动画表示控制信号进入基底模型的多个残差层。不要展示大段思维链，只展示结构化状态和控制方向。

这条动画必须绑定同轮真实开放权重运行的残差钩子证据。若实际钩子触发率、回退率或前缀对齐干预未通过门槛，则删除该动画和“直接作用”的旁白，不得用规划配置代替真实干预。

**旁白**

> 这里发生的不是“把话说得温柔一点”。  
> 模型先在潜在空间中选择如何处理这件事，再把任务与关系控制信号直接作用于基底模型的残差流。  
> 它因此同时改变理解、推理和表达：不责备用户，不追求理论最优，而是寻找这个人真正做得到的下一步。

**证明点**

- 全景决策支持体现共同建模、权衡和收敛。
- 高情商不是固定话术，而是任务轨与关系轨共同影响模型计算。
- 不展示或声称读取模型隐式思维链，只展示正式发布的结构化读数。

### 02:28–03:20｜第三轮：用户没有“反馈”，只是继续生活

**画面**

屏幕出现字幕：`七天后，同一用户，一次普通对话。`

**左侧自然输入**

> 按你的方法做了一周，现在每晚只醒2次。我没有那么崩溃了，但昨晚又醒了3次，是不是又退回去了？

**Volvence 回复**

> 从4次稳定到2次已经说明方向有效，一晚的波动不等于退回原点。先保持三天，不增加新的改变；如果连续三晚回到3次以上，我们再一起找新的原因。

**右侧模型元信息依次亮起**

| 模型元信息 | 屏幕显示 |
|---|---|
| 结果识别 | 夜醒4次降至2次；用户压力下降 |
| 建议采纳 | 已采纳分阶段调整 |
| 关系变化 | 从自责转向能够观察和判断 |
| 时间片段闭合 | 原决策 → 执行 → 延迟结果已绑定 |
| 经验归因 | 分阶段计划在当前条件下有效 |
| 记忆巩固 | 有效方案、适用条件与波动边界进入长期记忆 |
| 有界更新 | 进入控制器安全候选；基底模型不在线改写 |
| 调用方标注 | 不需要 |

**旁白**

> 她没有点击“有帮助”，没有上传奖励，也没有调用反馈接口。  
> 她只是说了这周发生了什么。  
> Volvence 自动识别真实结果，把七天后的变化归因到此前的状态和动作，巩固个人记忆，并把可迁移的经验送入有门控的学习流程。

**短暂停顿后继续**

> 对用户来说，这是一次普通对话。  
> 对模型来说，这是一次完整学习。

**证明点**

- 延迟结果来自后续自然交互。
- 预测误差是原始学习信号，信用归因是其下游。
- 个体事实进入经授权、可纠正和可删除的个人记忆。
- 跨用户策略只能进入有界控制器候选，不能在线改写整个基底模型。

### 03:20–03:52｜把“感觉”变成可以尽调的技术事实

**画面**

用户画面缩小到左侧，右侧出现一张极简技术闭环：

```text
自然交互
   ↓
任务状态 + 关系状态
   ↓
抽象决策 + 残差流控制
   ↓
真实结果
   ↓
预测误差 → 信用归因
   ↓
个人记忆巩固 + 控制器候选更新
```

**旁白**

> 这条链路没有把学习藏在提示词、工作流或人工运营里。  
> 冻结或极慢更新的基底负责稳定能力；  
> 有界控制器负责快速适应；  
> 多时间尺度记忆负责把经历变成连续经验；  
> 更新门负责审计、比较和回滚。

**屏幕底部**

> 同一个模型系统，同时学习“事情怎么做”和“如何与这个人一起把事情做成”。

### 03:52–04:20｜证据页：诚实比夸张更有力量

**画面**

切入真实终端和证据文件，不使用重新制作的动画数字。每个数字旁显示证据文件名称和校验摘要。

**屏幕数据**

- 真实 `1.5B` 基底、`500` 轮影子运行、`499` 条已结算真实转移；
- 时间表征、内部决策学习和连续记忆等多个学习组件发生真实参数更新；
- 完整学习平均回报提升 `+1.5503`，不优化对照为 `0`；
- 旧知识保持度 `1.0`；
- 所有候选保持影子状态，尚未晋级在线生效。

**旁白**

> 我们不把一次演示称为通用智能，也不把内部读数称为用户真实感受。  
> 当前证据证明的是：这套闭环已经能够在真实基底上运行、更新、保持旧知识，并在不满足门槛时拒绝上线。  
> 尚未完成的外部盲评和长期真实用户验证，我们会明确标注，而不是藏起来。

**证明点**

让技术投资人看到团队不仅会展示能力，也知道如何证伪自己的能力。

## 四、现场演示界面要求

### 左侧：用户看到的自然交互

- 只有用户标识、会话标识和自然语言输入。
- 不出现目标、奖励、关系标签、记忆写入或学习开关。
- 三轮交互始终调用同一个统一对话接口。

### 右侧：投资人看到的只读模型元信息

- 目标理解；
- 任务状态与关系状态；
- 当前抽象决策；
- 全景计分与缺失信息；
- 关系引导与残差流控制方向；
- 个人记忆候选、证据和巩固状态；
- 结果识别、时间片段闭合与经验归因；
- 更新门状态、回滚状态和证据编号。

这些元信息必须来自正式快照或证据对象，禁止从最终回答文本反向生成“解释”。

## 五、拍摄真实性规则

1. **主交互必须一镜到底。** 可以剪掉等待时间，但审计版必须保留完整录屏和时间戳。
2. **不得预写模型回答。** 如果模型没有产生目标能力，就保留失败或重新选择真实案例，不能后期伪造输出。
3. **不得预先注入目标和关系标签。** 演示要证明模型从自然交互中形成状态。
4. **不得把系统自评包装成用户感受。** 用户感受只能来自经授权的真实用户陈述或外部盲评。
5. **不得展示隐式思维链。** 只展示系统正式发布的结构化状态、决策和证据读数。
6. **学习必须有界。** 片中明确显示个人记忆、控制器候选和基底模型更新处于不同层级。
7. **用户数据必须取得授权。** 可匿名、变声和模糊身份；授权记录不出现在主片，但进入审计包。

## 六、拍摄前的能力证明门槛

只有以下门槛真实通过，主片才可以使用“能力证明”口径：

| 证明对象 | 最低门槛 | 未通过时如何处理 |
|---|---|---|
| **自然目标识别** | 请求中不存在目标、关系、奖励和路由标签；模型仍发布正式目标与状态快照 | 删除“模型自行理解目标”的表述 |
| **主动决策** | 下一动作来自控制器正式快照，不是固定工作流或文本关键词规则 | 只能称为产品流程演示 |
| **真实残差流控制** | 使用真实开放权重基底；回退率为0；实际钩子触发率达到证据门槛；前缀对齐干预有效 | 不展示残差动画，不宣称神经网络层面干预 |
| **延迟结果归因** | 后续自然交互形成可观察结果，并与原时间片段、预测误差和信用记录建立正式血缘 | 只能展示结果识别，不能宣称模型已经学习 |
| **长期记忆** | 写入来自唯一记忆所有者；具备用户授权、范围隔离、纠正、删除和回滚记录 | 只能展示会话内上下文，不宣称长期记忆 |
| **关系能力** | 展示任务轨与关系轨的独立正式读数；用户感受只引用真实用户或外部盲评 | 不把系统自评写成“用户感到被理解” |
| **模型更新** | 更新只进入有界控制器候选，并通过更新门、影子比较和回滚检查 | 不宣称在线持续学习已经生效 |

任何一个关键门槛失败，都应在审计版中保留失败结果。**能够拒绝未经证明的能力，比做出一段完美但不可复核的演示更能建立投资人的信任。**

## 七、建议同步交付的三份视频资产

| 资产 | 时长 | 用途 |
|---|---:|---|
| **投资人主片** | 5分钟 | 建立情感理解和核心技术认知 |
| **一镜到底审计版** | 8–12分钟 | 技术尽调，保留完整请求、响应、日志和时间戳 |
| **证据附件** | 可下载 | 模型版本、代码提交、配置、种子、证据文件摘要和校验值 |

主片负责让投资人记住“为什么重要”，审计版负责回答“是不是真的”，证据附件负责回答“能不能复现”。

## 八、不要这样拍

- 不要用炫酷粒子、机器人脸和宏大宇宙镜头替代真实能力。
- 不要连续展示十几个功能点，投资人最后只会记住“又一个智能体平台”。
- 不要让创始人先讲十分钟理论，再出现产品。
- 不要用“觉醒”“有意识”“已经实现通用智能”等无法验证的词。
- 不要把个人记忆、检索、提示词和真正的模型学习混为一谈。
- 不要隐藏尚未通过的晋级门槛。能够拒绝不成熟更新，本身就是系统能力。

## 九、整支视频的最后判断

这支视频真正要证明的不是：

> Volvence 能把一个育儿问题回答得更好。

而是：

> 当一个人的目标、关系和真实结果不断变化时，Volvence 能够在不要求人类替它设计学习闭环的前提下，持续理解、决策、记忆、归因和改进。

这才是持续学习型大语言模型与普通大模型之间的分界线。
