## Page 1｜封面

各位好，我们是进化涌现，我们的产品叫 Volvence。它是一款持续学习型大语言模型，致力于开启通用人工智能新纪元。

基础模型已经让机器拥有了大量知识。Volvence 要解决的，是怎么让机器拥有经验。

我们不是再训练一个只在上线前学习的模型，而是构建一个部署以后仍能从真实交互中成长的完整模型系统。

---

## Page 2｜三个结构性缺口

今天的大模型很强，但它还没有真正形成经验，原因有三个。

第一，学习停在部署之前。模型主要在预训练和后训练阶段获得能力，上线后发生的大量真实结果，并不会稳定变成它的长期能力。

第二，闭环停在模型之外。目标是谁设的、结果好不好、错误在哪里、什么时候更新，主要还是人和外部工程系统在完成。

第三，关系停在语言表面。Prompt、RAG 和文本记忆主要处理“说了什么”，但关系还包括时序、语气、行为、结果、沉默、边界和长期变化。语言是关系的一种表达，不是关系本身。

所以现有大模型是非常强的即时工具，但还不是一个能在长期关系中积累经验的智能体。

---

## Page 3｜我们的机会

下一代 Agent 的分水岭，不只是参数更大，而是部署之后还能不能学习。

这件事有三道门槛。第一，高价值反馈很少、很贵、还经常延迟。第二，系统既要复用过去经验，又不能被短期噪声带偏。第三，很多关系状态无法用文本完整表达。

Volvence 分别用 Learning Engine、Memory Engine 和 Representation Interface 回答这三个问题，再由 Decision Engine 把它们变成跨时间尺度的行动。

我们的机会不是比基础模型知道更多，而是让基础模型在每一段真实关系和任务里，持续变得更合适。

## Page 4｜行业路线与五维收敛

这里必须诚实回答一个问题：是不是只有 Volvence 在做持续学习？当然不是。

行业里已经有多条路线。RAG 和长上下文解决跨会话召回；EWC、SI、OWM 和 Replay 重点解决学新任务时不要忘掉旧任务；Adapter、LoRA 和 Test-time Learning 解决如何用少量参数快速适配；RLHF 和 Agent Workflow 解决输出对齐与工具执行；世界模型和潜空间控制则开始把预测与决策放到语言之外。

这些路线都有真实价值，但大多数只解决持续学习的一部分。

我们对约一百篇 Cognitive AGI 和持续学习核心论文的内部研究发现，不同社区实际上正在收敛到五个共同维度。

第一，预测误差要成为一级信号。结果和预期之间的差，不只用来打分，而要驱动下一轮学习。

第二，长期控制要发生在 Token 之上的内部空间。自然语言适合表达，但不适合承载全部长期决策。

第三，记忆要成为架构的一部分，而不仅是外挂数据库。

第四，有意义的策略和行为结构要从交互中涌现，不能全部靠人写规则。

第五，自我修改必须有界，评估必须只读，系统要可审计、可回滚，不能为了通过考试反过来学习考题。

Volvence 的差异不是声称别人都走错了，而是把这五个已经出现的方向，第一次组织成面向真实关系的完整闭环。投资人真正应该比较的，不是某个单点算法谁先发表，而是谁能让五个维度同时运行、相互制约，并产生商业结果。

## Page 5｜产品定义

Volvence 是一个具备持续学习能力的完整模型系统。

系统内部既有提供通用知识、推理和语言能力的基底模型，也有 Volvence 自己的 Decision、Memory、Learning 和 Representation 模块。

这张图从左向右看：Representation Interface 先把文本、语音、行为和时序编码成关系潜状态；Memory Engine 提供过去经验；Decision Engine 形成高层动作；基底模型和 Residual Steering 共同生成具体表达或行动。

真实结果回来以后，Learning Engine 做误差归因、主动选样和更新，再把可信经验送回 Memory 和 Decision。Governance Layer 对记忆写入、决策和学习同时施加权限、评测、审计与回滚约束。

所以我们交付的不是让客户自行拼装的一组外挂组件，而是一个能够边服务、边反馈、边成长的模型系统。

## Page 6｜模型系统部署架构

这张图讲的不是算法逻辑，而是我们的模块实际怎么部署。

左边是线上模型服务，负责每一次低延迟推理。交互编码模块先处理原始交互，Memory Engine 读取相关记忆，Decision Engine 选择高层动作，随后由基底模型和残差流控制模块共同生成回复、工具调用或 Agent 动作。

右边是持续学习中心。真实结果通过反馈事件流进入 Learning Engine，系统完成误差归因、主动选样和必要的人类求助，再由 Memory Engine 和训练服务完成记忆巩固或模型更新。

更新不会立即污染线上模型。新的记忆和模型版本必须先通过评测和安全门控，再发布到线上。

治理中心同时约束线上推理和后台学习，负责权限、隔离、审计、版本与回滚。整个部署的核心就是：线上稳定服务，线下持续学习，验证以后再安全发布。

## Page 7｜四项核心技术

我们的核心技术是三个引擎加一个表示接口。

Decision Engine 回答“下一步做什么”。它把决策从海量 Token 空间提升到高层动作空间，所以长程规划和错误归因会更清楚。

Memory Engine 回答“什么值得留下”。刚发生的经验先快速适应，反复验证后才进入长期层；冲突和高风险经验进入隔离区。这样既能快，又不容易遗忘或被噪声污染。

Learning Engine 回答“下一步学什么”。它不平均处理所有数据，而是主动寻找最有信息量、最高风险或最可能改善结果的反馈。

Representation Interface 回答“真实交互如何进入模型内部”。它把原始交互压缩为关系潜状态，再把这个状态变成作用于残差流的控制信号。

一句话概括：Decision 决定做什么，Learning 决定学什么，Memory 决定留下什么，Representation Interface 决定这些状态怎么进入模型。

## Page 8｜两个核心价值与商业飞轮

这一页要把我们的商业逻辑从根上讲清楚：电商不是起点，帮助用户解决问题才是起点。

Volvence 有两个核心价值。

第一个是 Panorama 决策支持。用户面对的往往不是一个标准问答，而是一个信息不完整、目标相互冲突、很多因素还没有想清楚的真实问题。Panorama 通过决策平衡计分卡，和用户一起定义目标、约束和利益相关方，共同对问题建模、共同推演不同方案、共同收敛，必要时还可以共同探索新的解。

在这个过程中，AI 能够自动研究外部信息，自动补齐决策矩阵；当它发现问题根源没有找清楚，或者关键条件缺失时，会主动向用户收集情况，而不是直接编一个答案。

第二个价值是高情商认知与 Coaching。很多时候，知道正确答案并不等于能把事情处理好。系统还要理解对方的情绪、关系、边界和时机，知道应该怎么表达、什么时候推进、什么时候停止，并持续 Coach 用户采取行动、观察结果和复盘调整。

所以我们的价值不是给用户一份报告，而是陪用户把问题真正解决。

这也解释了为什么它最后能够形成陪伴电商。要做电商，必须知道真实需求；要知道需求，必须真正了解客户；要了解客户，必须让客户持续使用；要让客户持续使用，就必须持续解决问题；而要解决真实世界的复杂问题，就必须 IQ 和 EQ 双在线。

因此 Volvence 不是先卖货、再维护关系，而是先创造问题解决价值，再从长期使用和真实关系中自然形成需求、商品和服务的匹配。交易结果又回到模型，帮助下一轮决策和 Coaching 做得更好。

## Page 9｜已完成的证明与消融

这一页只讲系统中已经跑出来的证据，并且把反证一起放上来。

第一，Decision Engine 的内部强化学习 paper suite 已通过七道门。相对最强 matched control，held-out success 提升 2.4 个百分点。独立 no-optimize 消融里，完整模型平均回报提升 1.55，不更新参数的对照提升为零；奖励稀疏度为 1，未发现 reward shaping 泄漏。这说明增益来自闭环学习，而不是把答案藏在奖励里。

第二，Memory Engine 的慢循环已经能反哺快决策。slow-to-fast initialization benefit 为 0.9625。基于 Qwen2.5-1.5B 的真实链路跑了 510 轮，CMS 新旧实现完成 2,274 次数值对齐，通过率 100%，旧知识保持窗口均值为 0.99995。

第三，末段两百轮预测中，任务进展、动作收益和关系变化三条轴都优于静态基线。但 regime stability 仍差于基线，所以我们只说三条轴成立，不说全面领先。

第四，我们刚刚重跑了记忆探针、多人关系、他人感受和延迟归因测试，结果是 31 项通过、1 项失败。失败项显示 `feeling_about_other` 激活后会影响 `social_prediction`，但契约白名单没有登记这条依赖。这是一个需要修复的治理问题，也说明我们的测试能抓住隐藏耦合。

我们同时保留两个明确边界：无 fast prior 脚手架的时间抽象证据目前仍然偏弱；510轮本地研究长测的平均时延不能代表生产 SLO。至于留存、转化和收入提升，还必须由真实产品 A/B 实验证明。

## Page 10｜模型结构与参数规模

这页直接给两个数字。

当前验证版使用 Qwen2.5-1.5B 基底，也就是约 15 亿参数。它外挂的是机制验证规模的微型网络：Decision 的结构发现网络 724 个参数，独立 PPO 配置 313 个参数；Memory 的三层 CMS 792 个参数，PE-aware 更新门 199 个参数。这些实验的潜空间维度不同，不能为了得到一个漂亮数字而直接相加。当前准确口径是：约 15 亿基底参数，外加若干独立实验控制器。

进一步推演后，3B 加 20M 只适合轻量版，不足以承担我们定义的完整产品。3B 基底可以做基础对话和垂直任务，但开放域自动研究、复杂决策推演、根因追问和高情商 Coaching 对知识、推理和表达都有更高要求。20M 也足以证明机制，却很难容纳跨场景策略、长期世界模型和关系模型。

因此 Volvence 1.0 主力 API 版定义为：140亿参数开源基底，加5亿个 Volvence 自有持续学习参数，总参数约145亿。自有参数包括共享状态编码和残差流接口、32个稀疏决策专家、4个时间尺度的神经记忆、长期世界和关系模型、更新门、路由器、价值头和预测头。决策潜空间为512维，每次只激活最相关的2个专家。

参数不会随着用户数据量线性增长。原始对话、用户事实和事件进入有权限的外部记忆；参数学习的是跨用户可迁移的结构、策略和规律。数据越来越多时，我们先扩大记忆容量、专家覆盖和训练深度，只有容量曲线饱和才增加参数。

我们同时提供 3B 基底加1亿自有参数的 Mini 版，用于端侧、私有部署和成本敏感场景。需要强调：当前 1.5B 是已经运行和长测的版本；14B 加500M是主力1.0的工程发布目标，必须通过规模消融和统一验收门后发布。

## Page 11｜自动标注与数据产能

现在用一个微信育儿专家兼销售的例子说明数据怎么自动标。

一位妈妈在微信里说，宝宝八个月，最近总是夜醒，她白天还要上班。

系统首先产生观察事实标签：宝宝八个月、存在夜醒、用户是上班族。这些信息来自用户原话，可以保留证据。

系统也会产生候选推断：可能处在睡眠倒退期，用户可能有较大压力，可能需要睡眠方案或相关商品。但这些都不能直接当真值，只能带着置信度进入候选区。

Learning Engine 会发现还缺夜醒频率、喂养方式、持续时间和白天作息，于是主动向用户追问。用户回答以后，系统才能把一部分候选升级为用户确认标签，并由 Panorama 补齐决策矩阵。

育儿专家给出方案并 Coach 用户执行。如果确有需要，再推荐商品或服务。后续用户是否采纳、是否下单、是否退款、方案是否有效、是否复购，形成结果标签。这些结果会反过来验证之前对需求、时机和方案的判断。

具体到一条训练轨迹，我们不只标一个“用户要不要买”。系统会标事实状态、需求与约束、问题阶段、根因候选、关系和情绪状态、模型选择的动作、用户是否采纳、七天后的效果、下单退款复购，以及每个标签的来源、时间、授权、置信度、风险和模型版本。模型候选绝不能自己给自己盖章。

涉及育儿健康、医疗或安全的高风险样本，会由主动学习系统送给专家复核。最终进入训练的数据都有来源、置信度、授权和版本；评测集只读，不进入训练。

这套机制如何支撑14.5B的主力版本？基底模型不是从零训练，我们要训练的是5亿参数的持续学习模块。我们拥有的是全网6000万可触达用户底座，微信只是其中一个渠道。首年按1%完成授权并形成有效使用测算，就是60万用户；每人20次有效交互，约1200万次交互。每次产生七到八个结构化信号，可以形成约9000万机器标签。

主动学习不会把9000万标签全部交给人。我们计划只选择约20万条高信息量样本做普通复核，约4万条育儿、医疗或安全样本做专家复核。需要10到15人的数据闭环团队，首年模型处理、数据工程、普通复核和专家复核预算约600万到1450万元。

我们需要合成数据，但它只解决冷启动、反事实、长尾失败和稀有安全场景，建议不超过训练混合的30%。合成数据不能进入评测集，也不能冒充真实用户结果。

所以6000万全网底座是非常有价值的分发和反馈出口，但不能直接说成6000万训练用户。跨平台用户要先去重，再经过触达、授权、有效交互和结果回流四层转化。即使只转化1%，也足以支撑Volvence 1.0第一阶段的控制器训练和产品验证。

## Page 12｜理论基础与原创边界

我们的理论基础来自主动学习、迁移学习、强化学习、层级决策和表征控制，但论文和产品之间的边界必须说清楚。

主动学习支撑 Learning Engine 如何少问、问对问题，但它不等于完整的持续学习闭环。

迁移学习支撑过去结构如何帮助新任务，但它不等于记忆本身。Memory Engine 还要负责保存、巩固、遗忘、隔离和治理。

Decision Engine 和 Representation Interface 则需要我们把长期决策、原始交互和残差流控制真正做成可运行系统。

所以 Volvence 不是给既有论文换一个名字，而是把长期理论积累集成为新的系统架构，并承担工程验证和商业结果。

## Page 13｜杨柳

杨柳是我们的联合创始人和首席科学家。

她毕业于美国卡内基梅隆大学计算机学院机器学习系，博士论文是 `Mathematical Theories of Interaction with Oracles`，研究人机交互与学习过程的复杂度。她的答辩委员会成员包括图灵奖得主 Manuel Blum。

根据团队履历，她在主动学习、强化学习和迁移学习方向发表顶会顶刊论文三十余篇。

她的研究长期回答两个问题：当标注很贵时，机器如何选择最有价值的反馈；当任务发生变化时，机器如何复用过去经验并获得泛化保证。

`Minimax Analysis of Active Learning` 用 Star Number 刻画主动学习的样本复杂度。`Reliable Active Apprenticeship Learning` 研究系统在不确定时如何向人求助并控制求助次数。`Active RLHF` 则把主动选样用于降低人类反馈成本。

这些工作不是装饰性背书，而是我们解决稀疏反馈和人机协同的科学基础。正式对外时，所有论文题录和发表状态会以最终学术简历逐项核验。

## Page 14｜迁移与记忆

这一页专门澄清一个容易混淆的问题：迁移学习不是记忆本身。

迁移学习回答的是，已经从过去任务学到的结构，能不能减少新任务从零学习的成本。杨柳相关工作的思路是，在先验还不可靠时使用不依赖先验的方法；随着任务增多、后验更可靠，再利用先验提升新任务的样本效率，并给出相应的数学保证。

Memory Engine 要做得更多。它要决定哪些信息只留在工作记忆，哪些模式经过反复验证后进入长期层；还要处理冲突、遗忘、隐私隔离和负迁移。

所以准确的表述是：迁移学习提供经验复用的理论方向，Memory Engine 把记住、稳定、复用和治理做成产品。

## Page 15｜产品与商业化

我们的产品和商业化路线很简单，就是发布模型、开源模型，然后提供 API。

融资后的前六个月，我们先发布 `Volvence-1 Mini`：30亿基底加1亿自有持续学习参数，总计31亿参数。它专门做两件事：通过 Panorama 帮用户进行复杂决策，通过高情商认知和 Coaching 陪用户把问题真正解决。我们先在自己的 AI 陪伴产品和少量合作场景里验证。

第六到第十二个月，我们开源31亿参数的 `Volvence-1 Open Mini`，包括可部署的模型权重、推理代码、基础接口和评测，让开发者构建自己的长期 Agent。同期发布主力版 Beta：140亿基底加5亿自有参数，总计145亿参数，在定向客户中验证开放域决策、长期关系和跨场景学习。

第十二到第十八个月，我们正式上线145亿参数的 `Volvence-1 Model API`，把持续学习、个人记忆、Panorama 决策支持、高情商 Coaching 和治理能力作为标准模型服务提供。开发者不需要自己部署整套系统，直接调用 API；企业客户也可以选择Mini或主力版私有化部署。

所以我们的最终产品非常明确：一个会持续学习、会辅助决策、会高情商解决问题的模型，以及任何产品都可以调用的 API。

## Page 16｜护城河

我们的护城河不是某一个秘密算法，而是闭环复利。

系统层面，我们把原始交互、潜状态、内部控制、真实结果、主动选样、记忆巩固和治理连成一条链。

数据层面，我们积累的是高价值反馈选择策略、长期结果标签和可迁移结构，而不是聊天记录的数量。

商业层面，更长的关系产生更可信的反馈，更可信的反馈改善服务，改善后的服务又提升留存和价值。

## Page 18｜融资用途与里程碑

本轮资金不是用来重训一个通用基础模型，而是用来验证持续学习闭环。

建议百分之四十投入核心模型与系统研发，百分之二十投入数据、标注和评测，百分之二十投入产品和标杆场景，百分之十投入算力、安全与基础设施，百分之十投入关键人才和运营。

未来十八到二十四个月，我们要完成三个可以被数字回答的问题。

第一，相同标注预算下，我们是否显著优于随机采样和普通人类反馈流程。

第二，在连续任务中，我们是否显著优于 LLM 加 RAG 或文本记忆，同时控制遗忘和错误写入。

第三，至少一个标杆场景能否证明持续学习提高任务成功率、留存或收入。

正式融资版还需要补上融资金额、资金跑道、当前基线和目标数字。这些数字不能用概念替代。
