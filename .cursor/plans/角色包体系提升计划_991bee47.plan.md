# 角色包体系提升计划（gap 收敛 + 首次真实训练）

## 现状基线

提交 `5c7ae986` 已闭合证据链主断点：evaluate / promotion 脚本入库、candidate v2 内容绑定、ungated proposal 约束、common-only 对照与 wrong-state 负控，17 个定向测试在 HEAD 通过（需 PYTHONPATH 强制本地源码，见包B）。剩余缺口按下面六个包收敛。

## 包A：启动安全收口（P0，约 3 个文件，半天）

Owner: 启动脚本 + vz-substrate

1. **封 legacy ACTIVE 绕门**：[start_browser_chat_qwen.sh](start_browser_chat_qwen.sh) 中 `ZHANG_WUJI_CHARACTER_PREFIX_MODE=active`（~575 行起）目前无门直接注入。改为：legacy active 路径直接 `RuntimeError`，提示迁移到 `CHARACTER_PACKAGE_MANIFESTS`（manifest 路径已有 `require_active()` 门）。legacy shadow 保留作为过渡观察。
2. **拆 wrapper 地雷**：[start_browser_chat_zhang_wuji.sh](start_browser_chat_zhang_wuji.sh) 41–43 行只要 residual 文件存在就导出路径，与 manifest 并存时 qwen.sh 必然 raise（现在没炸只因 common adapter bundle 未产出）。改为：manifest 可用时不导出 residual；residual 仅在显式 `ZHANG_WUJI_CHARACTER_RESIDUAL_PATH` 时作为 rollback-only 载体。
3. **target_modules 按模型族强制**：[rare_heavy_training.py](packages/vz-substrate/src/volvence_zero/substrate/rare_heavy_training.py) 第 49 行默认 `("c_attn",)`。去掉硬默认，改为必填或按 `base_model_source` 模型族推导（Qwen → `q_proj/v_proj/o_proj`），不匹配时 fail loudly（已有 no-trainable-params 检查兜底，但应在构造时就拦）。

验证：`pytest packages/vz-substrate/tests/test_common_adapter_pipeline.py` + 张无忌脚本 dry-run（shadow 模式启动到 manifest 加载日志）。

补充收口（2026-08-01）：修复 `COMMON_ADAPTER_BUNDLE_PATH` 单独配置却被静默忽略的问题；L1 现独立于 L2 加载并强制 ACTIVE/model 绑定，Unix/PowerShell browser-chat 入口都传入同一 common bundle、character registry 与 session assets。旧 prefix 与 residual 的 ACTIVE 环境变量均永久拒绝。

## 包B：环境修复（P0 级运维，与包A并行）

`.venv` 是从 `VolvenceDeploy/external/VolvenceZero` 搬来的，全部 editable 安装指向那个旧克隆——不加 PYTHONPATH 时 pytest 测的是旧仓库代码。处理：

- 删除现 `.venv`，用本仓库 uv workspace 重建（`uv sync` 或按 pyproject 重装 editable），逐包验证 `import` 解析到 `packages/*/src`。
- 重跑本计划涉及的定向测试确认环境干净。
- 在 `docs/known-debts.md` 记一条：过去在此 venv 下的验证结论可信度需注意。

## 包C：真 per-session 选角（P1，服务层主缺口，1–2 天）

Owner: lifeform-service

现状：`character_id` 只是"校验请求值 == vertical 硬编码值"，测试甚至断言不能动态选角；prefix/LoRA 靠进程级注册表 + synthesizer 硬编码 id 间接路由。改造：

1. `POST /v1/sessions` 的 `character_id` 变成真选角输入：SessionManager 据此从已加载 manifest 集合中解析角色 → 绑定 template（`give_birth`）+ prefix registry key + LoRA figure_id，session 内 synthesizer 的 character_id 来自 session 绑定而非 vertical 硬编码。
2. 支持同进程多 manifest：`CHARACTER_PACKAGE_MANIFESTS` 已支持多路径（`os.pathsep` 分隔），补第二个角色的最小 manifest（可用现有 bake 管线对另一 profile 出 SHADOW 包）打通验证。
3. 角色 LoRA 路由归位：从"default pool + synthesizer 硬编码"改为 session 绑定驱动 `_maybe_activate_character_lora`；明确 scoped figure pool 与角色包 LoRA 的优先级，防互相覆盖。
4. 补服务层测试（现为零）：loader ACTIVE 门、legacy 拒绝、同进程双角色 session、character LoRA 激活路径。改写 `test_character_session_binding.py` 中"拒绝动态选角"的断言为新语义。

## 包D：SHADOW 语义定案（P1，文档 + 少量测试，半天）

正式决定采用 **attestation-only**：SHADOW 校验并注册 manifest/binding，但不注入 Prefix/KV、不激活角色 LoRA，只写 `character_prefix_shadow_id`；数值 parity 由 evaluate 的离线 matched arms 承担，不做 registry 与 legacy 单包的在线双注入。配套：

- 修订本计划与 [docs/specs/character-prefix-package.md](docs/specs/character-prefix-package.md) 的表述，消除两处矛盾。
- legacy 单包路径（`ZHANG_WUJI_CHARACTER_PACKAGE_PATH`）的退出条件冻结为：包E 张无忌 manifest ACTIVE 后保留一个版本的显式 SHADOW 回滚观察窗，下一版本删除；legacy ACTIVE 永不恢复。
- 注意与在途的 docs 全面对账改动（大量未提交 spec 修改属于另一计划）划清边界，只动角色包相关章节。

## 包E：首次真实训练战役（里程碑，依赖包A/B，GPU 资源到位后启动）

当前 `artifacts/common-adapters/` 不存在，全链停在合成测试。战役步骤（手册 [docs/common-adapter-character-training.md](docs/common-adapter-character-training.md) 已就绪）：

1. `train_common_adapter_model.py train`：Qwen2.5-1.5B 真训 LoRA + 顺序蒸馏 State-KV（candidate v2 绑定数据 digest/seed）。
2. `evaluate`：held-out NLL（base vs candidate vs wrong-state）→ `ModificationGate.OFFLINE` 决策。
3. `publish`：bundle 落 `artifacts/common-adapters/qwen2.5-1.5b/`（wrapper 默认路径已预留）。
4. 张无忌链条：在 base + adapter v1 前向上重 bake prefix-KV → `evaluate_character_package.py`（common-only 对照 + wrong-state 负控）→ gate → manifest ACTIVE。
5. 旧 `artifacts/state_kv/projectors/*`（`training_order=None`）标记为顺序契约前产物，重蒸馏替换。

产出验收：bundle + evaluation report + gate record + ACTIVE manifest 全部内容寻址落库；失败则封存 deny 证据，不得降门槛。

执行记录（2026-08-01）：已用本地 Qwen2.5-0.5B、2-step rare-heavy 与最小 State-KV 配置跑通不晋级的 CPU smoke，`train → evaluate → publish → require_active` 全链闭合；Gate 正确给出 deny，runtime 正确拒绝 deny bundle ACTIVE。当前机器无 CUDA/MPS，仓库也尚无正式 `train.jsonl / held-out.jsonl / character-zhang-wuji-held-out.jsonl`，因此 1.5B 正式战役与张无忌 ACTIVE 晋升保持 pending，未伪造正式 artifact 或 allow 证据。复现命令与前置条件见训练手册第 12 节。

## 包F（后置）：角色 LoRA 多臂消融
