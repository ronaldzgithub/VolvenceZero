# 陪伴认知系统收窄计划（研究优先）

## 研究优先的第一个问题：真值从哪来

产品优先里真实用户免费提供外部真值。研究优先必须找到不依赖用户的真值源，否则就是回到 #92 的失败模式——自己出题、自己判卷。

**答案是未来本身。** 自监督预测下一轮对话的表示，标签免费、无需标注、无需用户。而这恰好就是陪伴的核心命题：

> 一个真正了解你的系统，应该越了解你、越能预测你。

这句话可直接测量：**held-out 预测性能随关系历史长度的增长曲线**。

这带来本方案最重要的结构性优势：**修复系统最深的缺陷与建立评估指标是同一件工作**。当前 PE 的 predicted 与 actual 来自同一批上游信号的两套固定权重投影（[error.py](packages/vz-cognition/src/volvence_zero/prediction/error.py) `_prediction_axes` / `_actual_axes`），度量的是自己读数的内部不一致。换成真正的前向预测后，它同时是：真实的学习信号、R2/R13 要求但当前不存在的 SSL 基底、以及论文的主指标。

## 两条硬前提：目前都不存在

调研确认了两个会让研究优先直接失效的缺口。

**一、长上下文对照臂从未跑过。** Gate 11 的对照是 stateless / swapped-user / shuffled-history，Gate 8 是 sleep / no-sleep，同基底消融是 raw / ref-harness / camel。**没有任何一臂是"把全部历史直接塞进上下文窗口"**——也就是现代长上下文模型的默认做法，以及任何评审者会问的第一个问题。

更严重的是实验台结构上无法产生这一臂：

```217:217:packages/companion-bench/src/companion_bench/arc_runner.py
            transcript_messages = _fresh_history()  # session_id changes; reset history view
```

产品路径也刻意只发最新一条（[session_bridge.py](packages/lifeform-openai-compat/src/lifeform_openai_compat/session_bridge.py) L178-181）。`companion-ref-harness` 三档最多注入 5 条摘要，CAMEL 基线是 LLM 压缩记录，都不是全量历史。

**二、没有真实的多 session 人类对话语料。** `data/encoder/traj-fsm/` 是 `source: synthetic_fsm`；Companion Bench 的 24+96 scenario 是人写 FSM 剧本 + 模拟用户；`CONSENTED_FIRST_PARTY` 只是 schema 占位符。MSC / LoCoMo 只出现在 `research/` 的论文笔记里，不在数据管线中。

**这两条必须作为前置工作包，不能跳过。** 在合成剧本上打败自己设计的弱对照，正是产生 #92 的那套方法。

## 纪律约束

- **治理冻结**：R4 结束前不新增 wheel、不新增 spec（删除除外）。
- **不重开 #92 的 8 条死门**：多频 CMS、SSL→RL takeover、M3、nested init、主动学习均已 kill。

## R0：校正判断与研究通道（第 1 周）

[docs/currentstatus.md](docs/currentstatus.md) 顶部写 `thesis-rejected`，§6 却仍写"瓶颈已从代码转移到证据"并建议去跑 `run_learned_active_evidence.sh`。**那条建议在 7/31 已被执行并证伪。** 改判为：瓶颈是信号真实性、学习器容量、外部真值三项。

同时解决一个研究优先特有的工程问题：**当前每 turn 走契约式 async `propagate` 的主链，跑不动数十万 turn 的训练与评估。** 需要一条离线批量通道，复用同样的 owner 与快照契约但绕开逐 turn 编排开销。这是研究优先的隐性前置，不解决会拖垮 R3/R4 的迭代速度。

## R1：外部真值地基（第 1–3 周，最关键）

**R1a — 真实语料。** 选型标准：真人对真人、每 dyad ≥3 个 session、身份持续、license 允许、可切 held-out。候选是 MSC（Multi-Session Chat，众包真人多 session 带 persona 连续性）与 LoCoMo（超长程）。产出：语料接入、冻结的 held-out 划分、license 合规结论。若中文场景是目标，需单独评估中文语料可得性。

**R1b — steelman 长上下文对照臂。** 同一冻结基底、全量历史入 context、认真调过的 prompt；超窗时按 recency 截断并如实记录。必须做强，不能建稻草人——这一臂决定整个架构是否值得存在。需改 `arc_runner` 的 session 边界 reset。

## R2：PE 真实化（第 2–6 周，与 R1 并行）

单 owner `prediction_error`，两个独立收敛包。

**包 A — 切断 evaluation 回灌。** `VZ_PE_EVALUATION_DECOUPLED` 默认翻 ACTIVE 并跑 matched ablation。若行为无差异，说明 PE 从来不是 load-bearing——这个结论本身值得拿到。单 env flag = 单回滚点。

**包 B — 真正的前向预测（本方案核心）。** turn N 预测 turn N+1 的表示，turn N+1 与实际观测结算：

```
turn N:   store forecast(z_N, state_N) -> predicted_representation_{N+1}
turn N+1: settle against observed representation -> 真实误差
```

复用 PE owner 已有的 CP-11 `_pending_head_forecast` 机制，**不建第二个 owner**。先与手工 head SHADOW 双跑，胜出后 promote 为 live prediction chain。

这一个目标同时是训练信号与评估指标，因此 R2 完成即意味着 R4 的度量工具就绪。

## R3：容量阶梯（第 5–10 周，用 GPU）

顺序很重要：**先有真实目标，再谈容量**——没有真实目标时扩容不可判定，这正是此前 synthetic ladder 无信息量的原因。

在 R1 语料 + R2 目标上跑 `n_z ∈ {3, 16, 64, 256}`。有增益则让 `n_z≥16` + torch runtime 成为默认，退役 `_step_impl_legacy`（[interface.py](packages/vz-temporal/src/volvence_zero/temporal/interface.py)，其注释自陈 "NOT the learned metacontroller"）。真实条件下仍平坦，则按纪律 kill ETA 主张。

顺带修缺陷：`math.sin` 确定性伪噪声换成真实随机探索（[sandbox.py](packages/vz-temporal/src/volvence_zero/internal_rl/sandbox.py) `_policy_noise`）。

## R4：主实验（第 8–14 周）

**因变量**：held-out 真实对话上的预测性能。**自变量**：关系历史长度。**四臂**：Volvence 全栈 / 无状态 / 全量历史长上下文 / 摘要检索。多 seed、预注册、冻结最小效应量。

同时记录**每臂的 token 消耗与延迟随历史长度的标度曲线**。这一条不是附属指标——见下。

## 预期结果与两种胜利条件

需要坦白一个风险：在百万 token 上下文的今天，朴素长上下文基线非常强，**很可能在中短历史上直接赢**。若把方案押在"质量全面超越"上，失败概率不低。

但有第二种胜利条件，而且很可能是真正可辩护的那个：

- **胜利条件一（质量）**：超过某个历史长度后，Volvence 的预测优势超过长上下文基线，且差距随时长扩大。
- **胜利条件二（标度）**：质量持平，但 token 与延迟成本低一个数量级，且成本差距随关系时长扩大。

条件二同样可发表、同样有产品意义，而且直接对应长上下文架构的真实弱点——它没有巩固机制，历史只能线性堆积。**两个条件都在同一套实验里测得，无需额外设计。** 建议预注册时同时冻结两条，不要只赌条件一。

## R5：thesis v3

按主实验结果择一预注册，独立总 EXIT，不改写 #92。不使用 AGI 措辞。

## Kill 条件

- 包 B 的真实 PE 在真实语料上仍不优于手工 head → 承认 PE-as-primary-signal 不成立，停止 R-PE 叙事，改为显式多信号架构。
- 真实语料 + 真实目标下 capacity ladder 平坦 → 删除 ETA 主张。
- 两种胜利条件在任何历史长度上都不成立 → 记忆与 owner 架构未能挣得其复杂度，应大幅简化或转产品路线。

## 与产品优先方案的取舍

研究优先放弃的：真实用户外部结果通道、#93 人类锚定、关系质量主张（人类感知只能由人给出）。因此**研究优先的终局主张只能是预测性与成本，不能是"用户感到被记住"**。这一点必须在预注册时写死，否则会重蹈 #92 用 owner readout 冒充关系质量的覆辙。

若 GPU、真实用户、评审者、增援人力四项资源确实都在，R1/R2/R3 与一条小规模 closed alpha 其实可以并行——真实用户不占研究人力，却能在 R4 之后为人类锚定留出接口。建议至少保留这条并行支线。
