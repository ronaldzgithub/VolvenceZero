## 独立命令行入口（MPS）

本计划只由 `scripts/run_msc_prediction_test_plan.py` 启动；与七日计划共享
`artifacts/.companion-evidence-mps.lock`，并强制 `PYTORCH_ENABLE_MPS_FALLBACK=0`。CLI
把“可以做的 MPS mechanism smoke”和“尚无资格做的 formal adjudication”分成不同阶段：
`formal` 在三个 blocker 未清除前固定返回退出码 `3`，不得调用旧 pilot 冒充正式实验。
共享锁只覆盖经两个新入口启动的任务；控制面落地前已经手工启动的七日进程必须先在原
终端结束，不能因为锁文件空闲就推断 MPS 空闲。

查看资格状态（不占用 MPS）：

```bash
.venv/bin/python scripts/run_msc_prediction_test_plan.py status
```

已启动后只查看完成单元数、最后单元和分析门（不读效应值）：

```bash
.venv/bin/python scripts/run_msc_prediction_test_plan.py status \
  --output-dir artifacts/msc_n_plus_one_mps_smoke_20260801
```

token 上界。报告不可变，已有同名不同内容会 fail loudly：

```bash

  --msc-root data/external/msc/v0.1/extracted \
  --preflight-report artifacts/msc_n_plus_one_mps_preflight_20260801.json
```

运行当前允许的真实 target mechanism smoke；MiniLM context、256/512-token prototype 与
完整 runtime 缺失都在 artifact 中保持 `mechanism-only-pilot / thesis_status=not-evaluated`：

```bash

  --msc-root data/external/msc/v0.1/extracted \
  --output-dir artifacts/msc_n_plus_one_mps_smoke_20260801
```

运行器会自动将语料索引、context/target 数值张量、每个
`arm × split`、`forward_head_n_z × seed` 和 `arm × heldout seed` 写成独立不可变
checkpoint，`run_state.json` 只记录控制进度。中断后用完全相同的参数续跑：

```bash
.venv/bin/python scripts/run_msc_prediction_test_plan.py smoke \
  --msc-root data/external/msc/v0.1/extracted \
  --output-dir artifacts/msc_n_plus_one_mps_smoke_20260801 \
  --resume
```

resume 会重新校验语料 provenance、模型/源码/参数 fingerprint 和所有已登记
checkpoint SHA；任一漂移立即失败。checkpoint 不保留 MSC 原文。只有最终
manifest 封口后 `analysis_allowed=true`；运行中材料只能用于续跑和完整性
检查，禁止据此选容量、换 seed 或得出效应判词。完成后仍固定
`formal_claim_allowed=false`，因为当前只是 mechanism pilot。

以下命令现在应返回 `3`；只有 R3/R4/R5 完成、正式 runner 和 prereg 冻结后才允许改为执行：

```bash
.venv/bin/python scripts/run_msc_prediction_test_plan.py formal
```

## 研究优先的第一个问题：真值从哪来

产品优先里真实用户免费提供外部真值。研究优先必须找到不依赖用户的真值源，否则就是回到 #92 的失败模式——自己出题、自己判卷。

**答案是未来本身。** 自监督预测下一轮对话的表示，标签免费、无需标注、无需用户。而这恰好就是陪伴的核心命题：

> 一个真正了解你的系统，应该越了解你、越能预测你。

这句话可直接测量：**held-out 预测性能随关系历史长度的增长曲线**。

这带来本方案最重要的结构性优势：**修复系统最深的缺陷与建立评估指标是同一件工作**。当前 PE 的 predicted 与 actual 来自同一批上游信号的两套固定权重投影（[error.py](packages/vz-cognition/src/volvence_zero/prediction/error.py) `_prediction_axes` / `_actual_axes`），度量的是自己读数的内部不一致。换成真正的前向预测后，它同时是：真实的学习信号、R2/R13 要求但当前不存在的 SSL 基底、以及论文的主指标。

## 两条硬前提：语料已完成，steelman 仍不存在

调研确认了两个会让研究优先直接失效的缺口。

**一、长上下文对照臂从未跑过。** Gate 11 的对照是 stateless / swapped-user / shuffled-history，Gate 8 是 sleep / no-sleep，同基底消融是 raw / ref-harness / camel。**没有任何一臂是"把全部历史直接塞进上下文窗口"**——也就是现代长上下文模型的默认做法，以及任何评审者会问的第一个问题。

更严重的是实验台结构上无法产生这一臂：


正式外部真值现由已校验的 MSC v0.1 提供，但“语料存在”不代表 substrate target、

**这两条必须作为前置工作包，不能跳过。** 在合成剧本上打败自己设计的弱对照，正是产生 #92 的那套方法。

Day-7 `continuity_metrics` 跨臂近乎平坦：`callback_hit_rate` 所有臂均为 `1.0`

出现 arm 差异。该矩阵因源码漂移作废，**不能作为效应判词**，但作为仪器诊断成立。

替代矩阵 `..._frozen_20260801T122037Z/` 目前 2/36。让它跑完会占用数日 MPS

结果；不换 seed、不降阈值、不改预注册。

### S2：为什么这七项测不出来（写成 diagnostic artifact）

- **两项是脚本常数。** `user_correction_rate` 与 `remembered_item_usefulness` 源自
  每日固定 console 探针（keep 第一、delete 第二），所有臂逐字节相同，数学上被钉在
  `0.5`，**永远不可能区分任何臂**。
- **`callback_hit_rate` 测的不是回忆。** 它比较 owner 对自身 compact readout 的
  forecast 与 realized readout（`owner_prediction_settlements` 的
  `COMMITMENT_FOLLOW_THROUGH` / `OPEN_LOOP_CLOSURE`），是自洽性而非「SUT 文本是否
  用上了 Day-3 的事实」。stateless 反而拿到 `1.0`：状态越少，owner 的预测越少越平凡，
  越容易自洽——**该指标可以朝反方向动**。
- **`trust_delta` 实测恒为 `0.0`**；`boundary` / `open_loop` 亦为被消融 owner 的内部
  readout。
- **唯一非循环通道无数据。** `fsm_probe_pass_rate` 是设计中唯一从 SUT 行为观测的量，
  所有 run 中均为 `null`。因此「SUT 表现得像记得你」在本装置里没有任何观测通道。
- 叠加约束：无 long-context 臂、无 persistence-only 基线、SUT 为
  `SmolLM2-360M-Instruct` 且 `max_new_tokens=96`。

产出物是一份 `instrument-diagnostic-only` artifact，逐项列出上述判断与支撑数据，
硬标记 `effect_claim_allowed=false`、`causal_claim_allowed=false`。它的价值是：
在花掉下一份算力之前，先证明尺子没有刻度。

### S3：改造为 N+1 预测测量台

七日装置有一样 MSC 给不了的东西：**35 个逐字节冻结、跨臂完全相同的用户话语，
跑在真实 persist/restart/hydrate 产品生命周期上**（每日新 service 进程、正式
owner hydration、跨进程状态归档）。这是比 MSC 更强的配对——MSC 各臂历史不同、
目标相同；七日装置连用户输入都完全相同，唯一变量就是可用状态。

改造只换测量，不换装置：把主判据从七项 owner readout 换成 R2 包 B 已冻结的
**N+1 substrate 表示预测误差**——给定同一串冻结用户话语，各臂对下一句用户话语的
substrate 表示预测得多准。该 target 由 `vz-substrate` 拥有并发布，与臂无关、
与 owner 内部状态无关，因此非循环。七项 owner readout 降为 secondary readout。

改造后仍受既有边界约束：模拟用户 → 措辞上限仍是 `simulated-user-real-lifecycle-only`，
不授权 production promotion，不改任何 `WiringLevel`，结果禁止回流 PE/credit/reward。

### S4：它可能是 blocker 3 的最短路径

R4 要求 `volvence` 臂经真实 runtime owner/snapshot/propagate 主链。**七日装置已经
满足这一条**——它走公开 HTTP service、真实 propagate、跨进程 hydration，正是 MSC
研究脚本缺的那部分。反过来，MSC 线有真实语料与真实 target，缺的是真实系统。

两条线的缺口正好互补，因此 S3 完成后应评估：正式 `volvence` 臂的 runtime collector
是否直接复用七日装置的 service 通路，而不是为 MSC 另建一套。判据是 attestation
能否覆盖 R4 要求的模块身份、wiring level、snapshot fingerprint 与 turn lineage。

**分工不得混淆**：MSC heldout 仍是 thesis v3 的唯一正式证据基座（真人语料）；
七日线是提供真实产品生命周期的补充 lane，其 simulated-user 属性使它永远不能替代
MSC heldout 做正式 adjudication。

## R5：ETA 容量阶梯（前三个 blocker 完成后，用 GPU）

顺序很重要：**先有真实目标，再谈容量**——没有真实目标时扩容不可判定，这正是此前 synthetic ladder 无信息量的原因。

现有 pilot 的 `n_z ∈ {3,16,64,256}` 改的是 PE forward head，不是 ETA，永久禁止
据此修改 temporal 默认值。正式 ladder 必须冻结 substrate、PE head、训练样本与
预算，唯一变量是 temporal owner 的 controller `n_z`；train 更新，validation
选择，heldout 禁止参与容量选择。配置与 artifact 中分别命名 `head_n_z` 和
`temporal_n_z`，禁止再使用歧义裸字段。

有增益则让 `temporal_n_z≥16` + torch runtime 成为候选，并经 SHADOW/ACTIVE
迁移后才允许退役 `_step_impl_legacy`（[interface.py](packages/vz-temporal/src/volvence_zero/temporal/interface.py)）。
真实条件下仍平坦，则按纪律 kill ETA 主张。`math.sin` 伪噪声与 RNG checkpoint
修复已完成，只是机制前提，不计作 ETA capacity evidence。

## R6：主实验

**因变量**：held-out 真实对话上的预测性能。**自变量**：关系历史长度。**四臂**：Volvence 全栈 / 无状态 / 全量历史长上下文 / 摘要检索。多 seed、预注册、冻结最小效应量。

同时记录**每臂的 token 消耗与延迟随历史长度的标度曲线**。这一条不是附属指标——见下。

## 预期结果与两种胜利条件

需要坦白一个风险：在百万 token 上下文的今天，朴素长上下文基线非常强，**很可能在中短历史上直接赢**。若把方案押在"质量全面超越"上，失败概率不低。

但有第二种胜利条件，而且很可能是真正可辩护的那个：

- **胜利条件一（质量）**：超过某个历史长度后，Volvence 的预测优势超过长上下文基线，且差距随时长扩大。
- **胜利条件二（标度）**：质量持平，但 token 与延迟成本低一个数量级，且成本差距随关系时长扩大。

条件二同样可发表、同样有产品意义，而且直接对应长上下文架构的真实弱点——它没有巩固机制，历史只能线性堆积。**两个条件都在同一套实验里测得，无需额外设计。** 建议预注册时同时冻结两条，不要只赌条件一。

## R7：独立 adjudication

thesis v3 的命题、阈值与两个 EXIT 已在正式运行前冻结。主实验完成后只允许由
独立 evaluator 读取完整 bundle，输出 `QUALITY_ADVANTAGE`、
`SCALING_ADVANTAGE` 或 `REJECT_AND_SIMPLIFY`；结果写入独立 evidence report，
禁止回填或改写预注册正文，也不改写 #92。不使用 AGI 措辞。

## Kill 条件

- 包 B 的真实 PE 在真实语料上仍不优于手工 head → 承认 PE-as-primary-signal 不成立，停止 R-PE 叙事，改为显式多信号架构。
- 冻结 substrate/PE 后只改变 `temporal_n_z` 的 capacity ladder 仍平坦 → 删除 ETA 主张。
- 两种胜利条件在任何历史长度上都不成立 → 记忆与 owner 架构未能挣得其复杂度，应大幅简化或转产品路线。
- 七日装置改用 N+1 预测 target 后仍不能区分 state 消融 → 该装置退役，不再为它投入算力；真实产品生命周期证据改由 closed alpha 承担。

## 与产品优先方案的取舍

研究优先放弃的：真实用户外部结果通道、#93 人类锚定、关系质量主张（人类感知只能由人给出）。因此**研究优先的终局主张只能是预测性与成本，不能是"用户感到被记住"**。这一点必须在预注册时写死，否则会重蹈 #92 用 owner readout 冒充关系质量的覆辙。

closed alpha 可作为独立产品支线，但不得向本研究提供选择阈值、修改 heldout 或
把用户主观反馈混入 predictive-continuity thesis；四个 blocker 仍按本计划顺序推进。
