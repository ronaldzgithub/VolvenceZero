## 4. Codex（最终答复）

_2026-07-25T15:20:21.599Z_

好，我们把 ETA 的核心数学先压成一个清晰骨架。我的判断是：ETA 不应该被理解成“多了一个策略模块”，而是一个**在冻结基底上学习时间抽象的 latent control system**。核心变量只有几组：

1. `e_t`：冻结 substrate 在时刻 `t` 暴露的 residual / feature state
2. `z_t`：低维控制器代码，也就是抽象动作状态
3. `beta_t`：切换门，决定继续当前抽象动作还是开启新段
4. `U_t = Decoder(z_t)`：把抽象代码映射回 residual control
5. `PE_t` / reward / credit：从预测误差派生的学习信号

**最核心方程**

ETA 的主循环可以写成：

```text
q_phi(z_tilde_t | e_1:t, m_t) = N(mu_t, Sigma_t)

beta_t = Switch_phi(e_1:t, z_{t-1}, m_t)

z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}

U_t = Decoder_phi(z_t)

e'_t = e_t + Apply(U_t, e_t)
```

这里 `beta_t` 是时间抽象的关键。  
`beta_t ≈ 0` 表示“继续同一个 option / abstract action”；`beta_t ≈ 1` 表示“切换到新的 abstract action”。所以 ETA 的 segment 不是外部 ledger 划出来的，而是由 `beta_t` 自己涌现出来的。

**自监督目标**

ETA 的第一阶段不是 RL，而是 SSL 压缩历史，让系统学到“什么 latent controller 能解释/预测行为”。

可以写成：

```text
L_SSL =
sum_t [
  - log p_theta,phi(a_t | o_1:t, z_1:t)
  + alpha * KL(q_phi(z_tilde_t | e_1:t) || N(0, I))
  + lambda_switch * Sparse(beta_t)
  + lambda_smooth * ||z_t - z_{t-1}||^2
]
```

其中最重要的是 KL bottleneck：它逼迫 `z_t` 不要记住所有细节，而只保留能跨时间解释行为的压缩结构。  
如果没有这个瓶颈，`z_t` 会退化成“每步特征副本”；有了它，才可能形成抽象动作。

**Internal RL 目标**

第二阶段才是在 `z_t` 空间做 RL，而不是 token/action 空间：

```text
pi_psi(z_t | e_1:t, m_t)

J_RL(psi) = E[ sum_t gamma^t r_t ]
```

但这里的动作不是文本 token，也不是具体工具调用，而是 latent controller code。更完整一点：

```text
A_t = GAE(r_t, V(e_1:t, z_t))

L_PPO =
E_t [
  min(
    rho_t A_t,
    clip(rho_t, 1-eps, 1+eps) A_t
  )
  - c_v * (V_t - R_t)^2
  + c_ent * H(pi_psi)
]
```

其中：

```text
rho_t = pi_psi(z_t | state_t) / pi_old(z_t | state_t)
```

这就是你仓库里说的 Internal RL：强化发生在 `z_t`，不是 token 空间。

**ETA 最关键的数学命题**

我觉得 ETA 的核心不是“有 GRU、有 decoder、有 PPO”，而是这三个约束同时成立：

```text
dim(z_t) << dim(e_t) << dim(token/action space)
```

```text
z_t changes sparsely through beta_t
```

```text
credit is assigned over beta-defined segments, not raw turns
```

也就是：

```text
segment_k = {t_i ... t_j}
where beta_t_i is switch/open
and beta_t_j or terminal closes it
```

然后 delayed credit 应该写到：

```text
Credit(segment_k)
  = f( PE_t_i:t_j, outcome_t_j, z_digest_k )
```

而不是简单写给最近一轮 response。

**我建议我们把 ETA 数学定成四层**

1. **Latent State Inference**
   `e_1:t -> q(z_tilde_t)`  
   负责从 residual/history 推断候选控制代码。

2. **Temporal Segmentation**
   `(z_{t-1}, z_tilde_t, e_1:t) -> beta_t`  
   负责 option boundary / segment closure。

3. **Residual Control**
   `z_t -> U_t -> e'_t`  
   负责让 latent abstract action 真正影响 substrate 表达。

4. **PE-first Learning**
   `prediction -> outcome -> PE -> credit -> update z-policy / priors`  
   负责学习，但 PE 是原始信号，evaluation 只是 readout/gate。

如果一句话概括：**ETA = 用变分瓶颈发现低维时间控制代码，用切换门把连续经历切成抽象动作段，再在这些 latent 段上做 PE-first credit 与 RL。**

我觉得下一步最值得讨论的是：`beta_t` 到底应该由什么压力塑形。这里是 ETA 是否真的“涌现”的核心。我的倾向是 `beta_t` 至少要吃四类信号：posterior drift、prediction error spike、memory/regime context change、action-family competition。

## 15. Codex（最终答复）

_2026-07-25T16:40:52.396Z_

可以。我们用一个非常具体的例子贯穿整篇论文：

> 任务：一只 ant 机器人要按顺序完成  
> **去红色点 -> 去蓝色点 -> 去绿色点**  
> 只有全部完成后才给 1 分奖励，中间没有奖励。

论文里的 ETA/内部 RL 原理，可以一一对应成下面这些东西。

**1. 原始动作：每一步关节怎么动**

ant 的底层动作是：

```text
第 1 步：左前腿关节 +0.2，右后腿关节 -0.1...
第 2 步：左前腿关节 +0.25，右后腿关节 -0.08...
第 3 步：...
```

这就像 LLM 一个 token 一个 token 输出。  
如果 RL 在这个层面探索，它必须碰巧生成几百步正确关节动作，先走到红点，再走到蓝点，再走到绿点，最后才拿到奖励。

这就是论文说的 **token-by-token / raw-action exploration 很低效**。

对应到 Volvence：

```text
raw action / token 层不是长期策略学习的主空间
```

**2. 抽象动作：不是“关节怎么动”，而是“去红色点”**

人不会这样规划：

```text
第 1 毫秒腿怎么动
第 2 毫秒腿怎么动
...
```

人会说：

```text
先去红色点
再去蓝色点
再去绿色点
```

论文里的 temporally-abstract action 就是这种东西。

对应关系：

```text
原始动作：每一步关节力矩
抽象动作：go red / go blue / go green
```

ETA 的目标就是让模型自己从行为序列里发现：

```text
这一大段关节动作其实是在“去红色点”
下一大段动作其实是在“去蓝色点”
```

而不是靠人手写标签。

**3. 残差流 e_t：模型脑子里当前“怎么看局面”**

自回归模型每一步都有内部激活。论文叫 residual stream activations，记作：

```text
e_t
```

具体例子：

```text
e_t 里可能隐含：
- ant 当前在哪里
- 红点大概在哪
- 当前轨迹像是在追红点还是蓝点
- 墙的位置
- 接下来专家大概率会往哪走
```

虽然模型只被训练预测下一步动作，但它内部为了预测动作，会形成对“当前子目标”的隐式 belief。

所以线性 probe 可以从 `e_t` 里读出：

```text
当前正在去红点：概率 0.82
当前正在去蓝点：概率 0.10
当前正在去绿点：概率 0.08
```

这就是论文第一部分：**下一个动作预测器内部自然涌现出子目标表征**。

**4. 线性控制器 U：轻轻推一下模型脑子，让它换目标**

论文发现，如果在模型中层残差流加一个线性控制器：

```text
e_t <- e_t + U e_t
```

就能 steering 模型。

具体例子：

```text
U_red  让模型倾向执行“去红点”的动作序列
U_blue 让模型倾向执行“去蓝点”的动作序列
U_green 让模型倾向执行“去绿点”的动作序列
```

如果人工按顺序插入：

```text
U_red -> U_blue -> U_green
```

模型就能完成没见过的新组合任务。

这说明两件事：

```text
模型内部有抽象目标表征
这些表征可以被简单线性控制器操纵
```

对应 Volvence 里的意思：

```text
substrate 冻结
temporal owner 只通过 residual/control surface 调制
不直接改基底
```

**5. z_t：不是直接存 U，而是存“控制器代码”**

每个控制器 `U` 很大。论文不直接让 RL 操作 `U`，而是学一个低维代码：

```text
z_red   -> Decoder -> U_red
z_blue  -> Decoder -> U_blue
z_green -> Decoder -> U_green
```

具体类比：

```text
z_t = “当前抽象动作的压缩编码”
Decoder(z_t) = 生成对应残差流控制器
```

所以：

```text
z_t 不是一句话标签
z_t 不是 prompt
z_t 是低维 latent controller code
```

对应 Volvence：

```text
ControllerState.code == z_t
```

**6. beta_t：什么时候继续，什么时候切换**

这是 ETA 最核心的东西。

假设 ant 正在去红点。连续很多步里，应该保持同一个 `z_red`：

```text
t=1   beta=1    切换到 z_red
t=2   beta=0    继续 z_red
t=3   beta=0    继续 z_red
...
t=40  beta=0    继续 z_red
t=41  beta=1    到达红点，切换到 z_blue
```

公式就是：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

具体解释：

```text
beta_t = 0：
不要理会新的候选 z，继续之前的抽象动作。

beta_t = 1：
采用新的候选 z，开启新抽象动作。

beta_t = 0.3：
部分更新，介于继续和切换之间。
```

所以 `beta_t` 不是普通 gate。它定义了时间段：

```text
Segment 1: 去红点
Segment 2: 去蓝点
Segment 3: 去绿点
```

对应 Volvence：

```text
closed_segments 必须来自 beta_t
delayed credit 不应该靠最近 turn 猜
```

**7. 自监督训练：没有“去红点”标签，也能学出来**

训练数据里只有：

```text
观测，动作，观测，动作...
```

没有：

```text
这里是在去红点
这里切换到蓝点
```

元控制器训练时要做的是：生成 `z_t` 和 `U_t`，让冻结基础模型更好预测下一步动作。

损失是：

```text
动作预测损失 + KL 正则
```

具体例子：

```text
如果 z_t 乱切：
模型预测动作变差。

如果 z_t 每一步都记所有细节：
KL 惩罚变大。

最优解：
把一大段共用目标的动作压成一个 z，比如 z_red；
到目标变了再切换。
```

所以它会自然学到：

```text
第 1-40 步：一个 z 就够，因为都在去红点
第 41-80 步：另一个 z，因为开始去蓝点
```

这就是论文里最漂亮的地方：  
**稀疏切换不是手写出来的，是瓶颈压力下涌现出来的。**

**8. KL 瓶颈：防止 z_t 变成逐步作弊小抄**

如果没有 KL，`z_t` 可能这样：

```text
z_1 = 第 1 步该怎么动
z_2 = 第 2 步该怎么动
z_3 = 第 3 步该怎么动
```

这就不是时间抽象，只是把原始动作藏进 latent 里。

KL 正则逼它接近：

```text
N(0, I)
```

实际效果：

```text
z_t 容量有限
不能记住每一步细节
只能记住最有压缩价值的结构
```

于是模型倾向学：

```text
z_red = 一整段“去红点”的共同原因
```

而不是：

```text
z_17 = 第 17 步腿怎么动
```

对应 Volvence：

```text
z_t 必须是 compressed control code
不能变成语义状态第二 owner
也不能变成 action trace
```

**9. 为什么必须冻结基础模型**

论文比较了两种情况：

```text
A. 冻结基础模型，只训练元控制器
B. 基础模型和元控制器一起训练
```

具体例子：

在 A 中，基础模型已经形成了稳定内部表征：

```text
红点方向、当前子目标、动作模式
```

元控制器只能学习如何读写这些已有结构，所以容易发现：

```text
z_red / z_blue / z_green
```

在 B 中，基础模型也在变。它可能找到更偷懒的解：

```text
整段序列开始时切一次
后面靠基础模型内部自己吸收所有信息
```

结果 `beta_t` 不再对齐子目标，时间抽象退化。

对应 Volvence 的铁律：

```text
冻结基底 + 自适应控制器
online 不端到端更新整个 base model
```

**10. Internal RL：RL 不选关节动作，而选 z**

现在进入强化学习。

标准 RL 需要探索：

```text
每一步关节动作怎么选
```

内部 RL 探索的是：

```text
这段选 z_red 还是 z_blue？
什么时候切换？
下一段选哪个 z？
```

也就是：

```text
raw RL:
第 1 步动作、第 2 步动作、第 3 步动作...

internal RL:
第 1 段 go red
第 2 段 go blue
第 3 段 go green
```

搜索空间瞬间变小。

具体比较：

```text
原始动作空间：
300 个低层时间步，每步 8 个连续关节维度。

z 空间：
3-5 个抽象段，每段选一个 16 维 latent code。
```

所以稀疏奖励终于能学：

```text
成功奖励 1 分
可以回传给 z_red -> z_blue -> z_green 这个抽象序列
```

而不是淹没在几百步关节噪声里。

**11. delayed credit：奖励给 segment，不给最近一步**

假设 ant 第 120 步终于完成任务，得到奖励。

错误做法：

```text
奖励最近一步动作。
```

这会错，因为成功来自整个序列：

```text
先去红点
再去蓝点
再去绿点
```

ETA 正确做法：

```text
Segment 1: z_red
Segment 2: z_blue
Segment 3: z_green
```

奖励/PE 通过 segment 分配：

```text
z_red 有贡献
z_blue 有贡献
z_green 有贡献
```

对应 Volvence：

```text
EnvironmentOutcome -> PredictionError
PredictionError + temporal.closed_segments -> Credit
Credit 再进入 temporal owner 更新
```

这也是为什么你仓库里“不新增 delayed ledger owner”是对的：  
时间边界已经由 `beta_t` owner 产生。

更具体一点。

在 Transformer/SSM 每一层，每个时间步都会有一个隐藏向量：

```text
e_{t,l} in R^{n_e}
```

你可以把它想成模型当下的“工作记忆状态”。它不是自然语言，也不是符号表，而是一串浮点数：

```text
e_{t,l} = [0.13, -0.42, 1.07, ..., 0.08]
```

但这串浮点数里可能编码了很多东西：

```text
当前位置
墙在哪里
红点方向
当前专家似乎想去哪个颜色
下一步动作倾向
当前子目标是否快完成
```

论文说的“残差流里面有 temporally-abstract action representation”，意思不是里面有一个字段：

```text
current_goal = red
```

而是说存在某个线性读出器：

```text
probe(e_{t,l}) -> 当前子目标概率
```

它能从残差流里读出：

```text
P(go red)   = 0.91
P(go blue)  = 0.04
P(go green) = 0.03
P(go yellow)= 0.02
```

这说明 `e_{t,l}` 里确实包含了“当前正在追哪个抽象目标”的信息。

再进一步，论文不只证明它“可读”，还证明它“可控”。

```text
e_{t,l} <- e_{t,l} + U_red e_{t,l}
```

然后模型后续动作就开始朝红点走，那说明这个内部表征不是旁观信息，而是进入了动作生成因果链。

所以完整说法是：

```text
残差流里有一个分布式 latent state。
这个 latent state 线性可读出当前抽象动作 belief。
并且在中层对它做线性干预，可以 causally steer 后续行为。
```

这就是论文最重要的实验证据。

用一个非常具体的例子：

ant 机器人在场景里，红点在左上，蓝点在右下。专家当前正在去红点。

模型每一步预测专家动作。为了预测得准，它必须隐式回答：

```text
专家现在为什么往左上走？

```

```text
e_t ≈ base_state + red-goal-direction
```

```text
w_red · e_t 高 -> 当前是 red goal
w_blue · e_t 高 -> 当前是 blue goal
```

```text
把 e_t 往 red-goal 子空间推一点
```

于是后续模型预测动作时，就更像“正在去红点”的专家轨迹。

也就是说：

```text
不是人告诉模型：这叫 red subgoal。
而是模型发现：有一类长时间动作序列共享某个隐藏原因。
```

这个隐藏原因在实验者看来对应“去红点”。

所以 ETA 里的内部表征可以这样定义：

> 在冻结自回归模型的残差流中，存在一种可线性解码、可因果干预、跨多个时间步稳定存在的 latent variable；它解释一整段低层动作序列的共同生成原因。这个 latent variable 就是时间抽象动作的内部表征。

为什么它会在残差流里？因为自回归模型要预测下一步动作，而下一步动作往往取决于长程目标。

如果模型只知道当前位置，不知道当前目标，它无法判断：

```text
同一个位置，下一步该往左还是往右？
```

例如：

```text
当前位置相同
红点在左
蓝点在右

如果任务是 go red：下一步向左
如果任务是 go blue：下一步向右
```

训练数据里没有显式目标标签，但动作历史会透露目标。模型为了降低 next-action loss，就会从历史中推断一个 latent goal belief，并把它放进内部状态。

所以流程是：

```text
历史动作/观测
  -> 模型推断“这个专家大概在追红点”
  -> 残差流中形成 red-goal belief
  -> 用这个 belief 预测下一步动作
```

ETA 把这个东西利用起来：

```text
读出它：probe / encoder
压缩它：z_t
控制它：U_t = Decoder(z_t)
分段它：beta_t
强化它：internal RL
```

对，问到骨头上了。我们拆开。

**1. 残差流具体是什么**

在 Transformer 里，每一层大概是这样：

```text
x_l
 -> Attention
 -> x_l + Attention(x_l)
 -> MLP
 -> x_l + MLP(x_l)
 -> x_{l+1}
```

这里那条一直被加来加去、往下一层传的主干向量，就是 **residual stream**。

更具体：

```text
x_0 = token embedding + position embedding

第 1 层：
x_1 = x_0 + Attn_1(norm(x_0)) + MLP_1(norm(...))

第 2 层：
x_2 = x_1 + Attn_2(norm(x_1)) + MLP_2(norm(...))

...

第 L 层：
x_L -> logits -> next token/action
```

每个时间步 `t`、每一层 `l` 都有一个残差流向量：

```text
e_{t,l}
```

它就是模型在“第 t 个 token/动作位置、第 l 层处理到一半或处理完”的内部状态。

如果是语言模型：

```text
e_{t,l} = 模型在第 t 个 token 位置、第 l 层的隐藏向量
```

如果是 ant 行为模型：

```text
e_{t,l} = 模型在第 t 个观测-动作位置、第 l 层的隐藏向量
```

所以残差流不是额外模块。它就是 Transformer 主干里每层传递信息的隐藏状态通道。

**2. ETA 控制的是哪里**

论文不是控制所有层，也不是每一层都加控制器。它主要发现：**中层附近最好控**。

形式是：

```text
e_{t,l} <- e_{t,l} + U_t e_{t,l}
```

也就是在某一层 `l` 的残差流上插入一个线性干预。

你可以想象成：

```text
embedding
  -> 前几层：解析局面、历史、局部信息
  -> 中层：形成“当前目标/子任务”这种抽象状态
  -> 后几层：把抽象状态翻译成具体下一步动作/logits
```

所以在中层控制最有效：

```text
太早：信息还没整理好，控制方向不稳定
太晚：动作 logits 快出来了，来不及影响完整行为
中层：正好是“抽象意图 -> 低层动作”转换的地方
```

论文图 4 的意思就是：控制器插在中层，成功率最高。

所以答案是：

```text
不是每一层都控制。
通常选一个中间层 residual stream 做 read/write。
```

但元控制器可以“读”序列里的残差激活，再“写”到某个选定层。

**3. 每个时间步都控制吗**

控制器可以每个时间步都应用，但不是每个时间步都换一个控制器。

例如：

```text
t=1   使用 U_red
t=2   继续使用 U_red
t=3   继续使用 U_red
...
t=40  继续使用 U_red
t=41  切换成 U_blue
```

也就是说：

```text
控制发生在每步
切换不是每步
```

这个区别很关键。

每一步 residual 都被当前控制器轻推一下：

```text
e_{t,l} <- e_{t,l} + U_red e_{t,l}
```

但 `U_red` 可以持续很多步。

**4. 为什么要分段**

因为现实任务不是每一步都重新决定“我要成为什么”。

还是 ant 的例子：

```text
任务：去红点 -> 去蓝点 -> 去绿点
```

低层动作可能有 300 步：

```text
1,2,3,...,300
```

但真正的高层结构只有 3 段：

```text
1-80:   去红点
81-190: 去蓝点
191-300: 去绿点
```

如果不分段，RL 要在 300 个时间步上探索和归因。奖励只在最后给：

```text
第 300 步成功，reward = 1
```

那问题是：到底哪几步有贡献？

```text
第 299 步？
第 230 步？
第 90 步？
第 12 步？
```

信用分配会非常难。

分段之后，问题变成：

```text
Segment 1: go red
Segment 2: go blue
Segment 3: go green
```

成功奖励可以归因给这三个抽象动作段，而不是 300 个低层动作。

这就是分段的第一个原因：**降低信用分配难度**。

第二个原因：**降低探索空间**。

不分段时，探索是：

```text
每一步都采样低层动作
```

分段后，探索是：

```text
每一段采样一个抽象动作 z
```

从：

```text
300 次决策
```

变成：

```text
3 次决策
```

这对稀疏奖励是生死差别。

第三个原因：**复用子程序**。

如果学到了：

```text
go red
go blue
go green
```

以后新任务：

```text
go blue -> go red -> go green
```

就可以复用已有段，只需要重新排序。

没有分段，就没有明确的可复用单位。

**5. beta_t 就是分段器**

论文里的 `beta_t` 做这个事：

```text
beta_t ≈ 0：继续当前段
beta_t ≈ 1：开启新段
```

公式：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

具体：

```text
t=1: beta=1   新段：go red
t=2: beta=0   继续 go red
...
t=80: beta=0  继续 go red
t=81: beta=1  新段：go blue
```

所以 `beta_t` 不只是一个神经网络 gate。它定义了：

```text
哪个 z 从哪里开始
哪个 z 到哪里结束
哪个 reward 应该回传给哪段
```

**一句话**

残差流就是 Transformer 每层里那条主隐藏状态通道；ETA 通常在中层残差流上读写，用线性控制器持续影响每一步行为，但只在 `beta_t` 指示时切换控制器。分段是为了把几百步低层动作压成几个可复用、可探索、可归因的抽象动作段。

```text
z_t 负责“现在是什么抽象动作”
```

```text
t=1    beta=1   z = z_red

t=42   beta=0   z = z_blue
```

```text
z_t 突然跳变处 ~= segment boundary
```

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

```text
如果 beta_t = 0：
```

```text
如果 beta_t = 1：
```

```text
beta_t 是切换门
segment 是同一个控制器代码持续控制的时间片
```

_2026-07-25T17:54:00.209Z_

`beta_t` 是一个**切换单元 switch unit** 算出来的，不是人工标注出来的。

论文里的结构大概是：

```text
残差流历史 e_1:t
当前 encoder hidden state
上一刻 z_{t-1}
候选 z_tilde_t
        |
        v
Switching unit
        |
        v
beta_t in [0, 1]
```

然后它进入公式：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

所以 `beta_t` 本质上是神经网络输出的一个 gate。

**非常具体一点**

假设元控制器里有一个 GRU encoder。每个时间步它看到残差流：

```text
e_t
```

并更新内部状态：

```text
h_t = GRU(h_{t-1}, e_t, sequence_context)
```

然后从 `h_t` 产生两个东西。

第一个是候选新控制器代码：

```text
mu_t, Sigma_t = EncoderHead(h_t)
z_tilde_t ~ N(mu_t, Sigma_t)
```

第二个是切换门：

```text
beta_t = sigmoid(W_beta h_t + b_beta)
```

或者更一般：

```text
beta_t = SwitchNet(h_t, z_{t-1}, e_t)
```

输出范围是 `[0, 1]`。

所以它不是规则：

```text
如果到红点就 beta=1
```

而是可学习函数：

```text
beta_t = f_switch(...)
```

**它怎么学会什么时候切？**

关键在训练目标。

训练时没有子目标标签：

```text
没有告诉它：第 40 步从红切蓝
```

它只有动作预测损失和 KL 正则：

```text
L = next-action prediction loss + alpha * KL
```

如果它太少切：

```text
一直用同一个 z
```

那一个控制器要解释整条轨迹：

```text
去红点 -> 去蓝点 -> 去绿点
```

动作预测会变差，因为不同阶段需要不同控制策略。

如果它太频繁切：

```text
每一步都换 z
```

它可以预测得更细，但每次新 `z_tilde_t` 都要从 posterior 带信息过来，会被 KL 瓶颈惩罚，而且不能形成好的标准正态先验采样结构。

于是最划算的解变成：

```text
在真正的子目标边界切
段内保持
```

比如：

```text
去红点期间，继续 z_red
到红点后，动作模式突然变成去蓝点
这时继续 z_red 会让预测损失上升
所以 switch unit 学会 beta_t -> 1
```

这就是 `beta_t` 涌现的机制。

**更直观的训练压力**

看这个序列：

```text
t=1-40:  专家持续朝红点走
t=41-80: 专家持续朝蓝点走
```

如果 `beta_t` 在 t=20 切：

```text
前后其实都还在去红点
新 z 没必要
KL 成本增加
```

不划算。

如果 `beta_t` 到 t=60 才切：

```text
t=41-60 已经开始去蓝点
但还用 z_red
动作预测变差
```

也不划算。

所以最优位置自然靠近：

```text
t=41
```

即真实抽象动作切换点。

**论文里还有一个重要点：训练时 beta 基本是连续的**

训练时：

```text
beta_t in [0, 1]
```

可以是：

```text
0.03, 0.08, 0.92
```

论文说实际训练后它会变得 quasi-binary：

```text
大多数时候接近 0
切换时接近 1
```

也就是近似二值。

内部 RL 时，为了让抽象动作段更明确，还会 harden：

```text
hard_beta_t = H(beta_t - beta_threshold)
```

例如：

```text
if beta_t > 0.5:
    hard_beta_t = 1
else:
    hard_beta_t = 0
```

然后：

```text
hard_beta=0 -> 继续旧 z
hard_beta=1 -> 换新 z
```

**它用不用未来信息？**

论文里比较细。

元控制器训练时 encoder 是非因果的，可以用整段序列 embedding：

```text
s(e_1:T)
```

所以训练时它更容易发现“这里应该切”，因为它能看到未来动作变了。

但内部 RL 阶段不能看未来，所以会替换成因果策略：

```text
pi(z_t | e_1:t)
```

而论文附录里也说，实验中他们让 switch 近似只依赖因果信息：

```text
q(beta_t | e_1:t, a_1:T) ≈ q(beta_t | e_1:t)
```

目的就是让 beta 在 RL 时可以真实在线发出。

**一句话**

`beta_t` 是 switch unit 从残差流/encoder 状态里学出来的一个连续切换门。它通过动作预测损失和 KL 瓶颈共同训练：切太少会预测不准，切太多会付出信息成本，所以最优解自然变成“段内保持、子目标边界切换”。

换句话说：

```text
base model = 稳定身体/大脑基底
user/profile/memory/controller state = 持续变化的生命史
```

如果只有一个训练完的死模型：

```text
p_theta
```

```text
p_theta frozen
+ per-user memory
+ per-user relationship state
+ per-user temporal controller state
+ per-user regime preferences
+ prediction-error history
+ credit / consolidation traces
```

这一整套才是“持续的主体”。

**1. BP 输出的模型应该是什么**

我会把 BP 输出分成两类：

```text
A. frozen foundation artifact
B. bootstrap/adaptation artifact
```

A 是死参数：

```text
base model weights
substrate adapter
initial metacontroller parameters
initial memory tower priors
initial regime priors
```

它们可以随版本发布，默认不因单个用户在线改变。

B 是“初始生命体配置”：

```text
default z_t prior
default beta switch behavior
default CMS initialization
default relationship regime priors
default safety/boundary policy
```

这也可以是参数，但它只是出生配置，不是持续性本身。

**2. 持续性在哪里**

持续性应该在 session/user scope 的状态里。

比如一个用户 A 长期和系统互动，系统逐渐形成：

```text
UserProfile_A:
  - 用户偏好短回答还是长推理
  - 用户更信任数学公式还是例子
  - 用户项目 Volvence 的核心语义
  - 用户讨厌哪些表达方式
  - 用户当前长期目标
```

还有：

```text
RelationshipState_A:
  - 信任水平
  - 熟悉度
  - 共同语境
  - 互动节奏
  - 边界和 consent
```

还有：

```text
TemporalControllerState_A:
  - 哪些 z-family 对这个用户有效
  - 什么时候应该深入推理
  - 什么时候应该陪伴式回应
  - 什么时候应该切到执行模式
```

这些是动态的。

所以同一个 frozen model，面对不同用户，会有不同持续状态：

```text
p_theta + state_A -> Agent_A
p_theta + state_B -> Agent_B
```

持续性不是：

```text
theta 每轮都变
```

而是：

```text
state_A 跨时间保持、更新、被召回、影响行为
```

**3. 为什么不要直接让 base model 每个用户都变**

如果每个用户都在线更新 base model：

```text
theta_A, theta_B, theta_C...
```

会有几个问题：

```text

安全不可控
回滚困难
用户间污染
调试困难
训练成本爆炸
身份边界混乱
```

所以更稳的结构是：

```text
base theta frozen
per-user adaptive state mutable
rare-heavy 才产出新 artifact
```

```text
online-fast:

session-medium:
  user/session patterns, action-family credit

background-slow:
  memory consolidation, profile refinement, regime priors

rare-heavy:
  offline artifact update, adapter distillation, model version upgrade
```

```text

2. Relationship State
```

比如你现在问 ETA 数学，我们已经形成一个局部动态：


这不只是 profile 文本：

```text
beta_t 更容易切到“严密定义”模式
z_t family 偏向“具体例子 -> 数学归纳 -> 架构映射”
回答策略少寒暄、多结构
```

这才叫“动态懂得”。

**5. 死参数与活状态的关系**

可以这么看：

```text
死参数 = 物种能力
活状态 = 个体生命史
```

基础模型提供：

```text
推理能力
世界知识
代码能力
一般情感能力
```

```text
这个人是谁
我们经历过什么
现在这段关系是什么状态
```

没有活状态，模型只是泛化智能。

```text
Volvence uses a frozen or slow-updated foundation substrate,

memory, profile, relationship state, temporal controller state,

Continuity emerges from stateful adaptation, not from unrestricted online mutation of base weights.
```

中文就是：

> Volvence 的持续性不来自实时改写基础模型权重，而来自每个用户独立持久化的自适应状态。冻结基底提供稳定能力，用户侧记忆、关系状态、时间控制器和 PE-derived credit 形成随互动演化的个体生命史。

```text
regime_state

boundary_consent
```

真正持续的是：

```text
frozen model + evolving user-specific state
```

不是单独的 frozen model。

```text
rare-heavy：
```

```text
这个 error 属于哪个 owner？
应该在线适应、会话沉淀、后台反思，还是进入 rare-heavy？
```

所以它应该像一个 **ActiveLearningScheduler / LearningIntent owner**，消费：

```text
prediction_error
credit
evaluation readout
memory novelty
user_model uncertainty
relationship_state uncertainty
temporal beta/z evidence
boundary_consent
cost/risk budget
```

然后产出 typed proposals：

```text

UserModelUpdateProposal
TemporalPriorUpdateProposal
RegimeUpdateProposal
RareHeavyCandidateProposal
ClarifyingQuestionProposal
```

```text
我不确定你说的“主力模型”是部署产品模型，还是 rare-heavy teacher model。
```

如果这个不确定性影响很大，系统应该主动澄清，而不是自己乱学。

**1. 在线主动学习：调行为，不调权重**

```text
online-fast / temporal + regime + response policy
```

```text
  从“数学总述”
```

这里学习的是：

```text
这个用户当前需要更具体、更底层的解释
```

但不改 500M。

**2. 会话级主动学习：更新用户模型和关系状态**

位置：

```text
session-medium / user_model + relationship_state + credit
```

你一路追问 ETA：


```text
user prefers first-principles mechanism

user wants concrete one-to-one mappings
user dislikes vague product language
```

这不是普通 memory 一句话，而是 user_model 的结构化更新。

**3. 后台主动学习：整理成稳定 prior**


这可以变成 response/regime/temporal 的 prior，而不是每次重新从 raw chat 猜。

**4. rare-heavy 主动学习：挑样本，不直接在线训练**

位置：

```text
rare-heavy / ModificationGate
```

例子：

大量用户都在同一类问题上出现 PE：

```text
不理解“动态状态 + 冻结模型”的关系
不理解 ETA 的 beta_t
不理解主动学习层次
```

```text
high-value curriculum sample
distillation example
adapter training candidate
benchmark regression case
```

> 主动学习不是一个会在线改写基础模型的功能，而是 PE-first 的学习调度层。它根据 prediction error、uncertainty、novelty、credit 和 risk，把学习动作路由到 memory、user model、relationship state、temporal controller、regime 或 rare-heavy artifact pipeline。


残差流控制的具体算法，可以拆成两步：

```text
1. 在 Transformer 某一层拿到残差流向量 e_{t,l}
2. 用一个控制器 U_t 对它做线性干预
```

核心公式就是论文里的 Eq. 1：

```text
e_{t,l} <- e_{t,l} + U_t e_{t,l}
```

也就是：

```text
新残差流 = 原残差流 + 控制器作用后的残差流增量
```

**1. Transformer 里的位置**

假设一层 Transformer 是：

```text
x_l
 -> Attention
 -> x_l + Attention(...)
 -> MLP
 -> x_l + Attention(...) + MLP(...)
 -> x_{l+1}
```

残差流就是这条 `x_l -> x_{l+1}` 的主隐藏状态。

控制发生在某个中间层 `l`：

```text
x_l = residual stream at layer l
x_l_controlled = x_l + U_t x_l
```

然后模型继续跑后面的层：

```text
x_l_controlled -> layer l+1 -> ... -> logits -> action
```

所以不是直接改输出动作，而是改中间表示，让后续层自然生成不同动作。

**2. U_t 是什么**

`U_t` 是一个线性矩阵：

```text
U_t in R^{n_e x n_e}
```

如果残差流维度是 768：

```text
e_t in R^768
U_t in R^{768 x 768}
```

直接学完整矩阵太大，所以通常用低秩形式：

```text
U_t = A_t B_t
```

其中：

```text
A_t in R^{n_e x r}
B_t in R^{r x n_e}
r << n_e
```

例如：

```text
n_e = 768
r = 8
```

那么：

```text
U_t e_t = A_t (B_t e_t)
```

这和 LoRA 很像。

完整控制变成：

```text
e'_{t,l} = e_{t,l} + A_t B_t e_{t,l}
```

**3. 最简单的监督版算法**

先看最简单版本：假设你有人类标签，知道当前该去哪个子目标。

比如有 4 个子目标：

```text
red, blue, green, yellow
```

训练 4 个控制器：

```text
U_red
U_blue
U_green
U_yellow
```

训练时冻结基础模型 `theta`，只训练这些 `U_g`。

每条训练样本：

```text
当前目标是 red
观测历史 o_1:t
专家动作 a_t
```

前向：

```text
e_{t,l} = BaseModelResidual(o_1:t, layer=l)

e'_{t,l} = e_{t,l} + U_red e_{t,l}

p(a_t | o_1:t, U_red) = 后续层输出动作分布
```

损失：

```text
L = - log p(a_t | o_1:t, U_red)
```

反向传播时：

```text
冻结 base model 参数 theta
只更新 U_red
```

伪代码：

```python
for batch in data:
    goal = batch.goal_label          # red / blue / green...
    action = batch.expert_action

    with freeze(base_model):
        e = base_model.forward_to_layer(batch.obs_history, layer=l)

        U = controllers[goal]
        e_controlled = e + U @ e

        logits = base_model.forward_from_layer(e_controlled, layer=l)
        loss = cross_entropy(logits, action)

    loss.backward()
    optimizer.step(controllers[goal])
```

这个版本证明：

```text
残差流里确实有可控的子目标表征
```

但它用到了标签，不是最终 ETA。

**4. ETA 版：U_t 由 z_t 生成**

无监督 ETA 不再维护：

```text
U_red, U_blue, U_green
```

而是：

```text
z_t -> Decoder -> U_t
```

也就是说，元控制器生成控制器。

流程：

```text
残差流历史 e_{1:t}
      ↓
Encoder
      ↓
候选 controller code z_tilde_t
      ↓
Switch unit 得到 beta_t
      ↓
z_t = beta_t z_tilde_t + (1-beta_t) z_{t-1}
      ↓
Decoder(z_t)
      ↓
U_t
      ↓
e'_{t,l} = e_{t,l} + U_t e_{t,l}
```

算法上就是：

```python
e_t = base_model.forward_to_layer(obs_history, layer=l)

mu_t, sigma_t = encoder(e_history, future_context_during_ssl)
z_tilde = sample_normal(mu_t, sigma_t)

beta_t = switch_unit(e_history, z_prev)

z_t = beta_t * z_tilde + (1 - beta_t) * z_prev

U_t = decoder(z_t)

e_controlled = e_t + U_t @ e_t

logits = base_model.forward_from_layer(e_controlled, layer=l)

loss = action_prediction_loss(logits, expert_action) \
     + alpha * kl_normal(mu_t, sigma_t, standard_normal)

update(meta_controller_params)
```

其中 base model 仍然冻结。

**5. Decoder 怎么生成 U_t**

最直接：

```text
Decoder(z_t) -> full matrix U_t
```

但太大。

更实际是生成低秩因子：

```text
Decoder_A(z_t) -> A_t
Decoder_B(z_t) -> B_t
U_t = A_t B_t
```

控制：

```text
e' = e + A_t (B_t e)
```

也可以加 scale / clamp：

```text
delta = A_t (B_t e)
delta = clamp_norm(delta, max_delta)
e' = e + eta * delta
```

这样避免控制过强，把模型激活推爆。

**6. 为什么是乘 `U_t e_t`，不是加一个固定向量**

可以有两种控制：

```text
additive steering:
e' = e + v

linear controller:
e' = e + U e
```

论文用的是线性控制器：

```text
e' = e + U e
```

因为它是状态依赖的。

具体区别：

```text
固定向量 v：
无论当前位置在哪里，都推同一个方向。

线性控制器 U：
根据当前 e_t 的不同，产生不同增量。
```

例如同样是 `go red`：

```text
如果 ant 在红点左边，需要向右走。
如果 ant 在红点右边，需要向左走。
```

固定向量很难表达这个；`U e_t` 可以根据当前状态产生不同控制增量。

所以 `U_t` 不是“直接命令往左”，而是一个小策略变换：

```text
在当前局面下，把内部状态改造成更像正在执行某个抽象目标的状态。
```

**7. 控制哪一层**

论文发现中层最好。

算法上可以 sweep：

```python
for layer in candidate_layers:
    train_controller_at(layer)
    evaluate_success()
```

结果通常是：

```text
浅层：信息太原始，不好控制
中层：抽象目标表征强，可控性最好
深层：太接近输出，干预窗口太短
```

所以实践里选：

```text
layer = middle_layer
```

例如 12 层模型选第 5/6 层附近。

**8. 内部 RL 阶段的残差流控制**

SSL 训练完后，encoder 可以被替换为因果策略：

```text
pi(z_t | e_{1:t})
```

然后 RL 选择 `z_t`，decoder 生成 `U_t`，继续控制残差流：

```text
z_t ~ pi(z_t | e_{1:t})
U_t = Decoder(z_t)
e' = e + U_t e
action = base_model_after_control(e')
reward = environment(action)
```

内部 RL 不直接更新 base model，也不直接输出 raw action。它更新的是：

```text
pi(z_t | e_{1:t})
```

也就是如何选择 latent controller code。

**9. 完整算法小结**

训练阶段：

```text
输入：无标签专家轨迹
冻结：base model theta
训练：metacontroller phi

for each trajectory:
  for each time t:
    e_t = residual at layer l
    z_tilde = encoder(e_history, sequence_context)
    beta_t = switch(e_history, z_prev)
    z_t = beta_t z_tilde + (1-beta_t) z_prev
    U_t = decoder(z_t)
    e'_t = e_t + U_t e_t
    predict action a_t
    loss = -log p(a_t) + alpha KL
```

RL 阶段：

```text
冻结：base model + decoder + switch mostly fixed
训练：causal policy pi(z | e_history)

while episode:
  e_t = residual at layer l
  if beta says switch:
      z_t ~ pi(z | e_history)
  else:
      z_t = z_prev
  U_t = decoder(z_t)
  e'_t = e_t + U_t e_t
  action = model output
  environment returns outcome/reward
  update pi with RL on z-space
```

**一句话**

残差流控制算法就是：在 Transformer 中层残差流取出隐藏向量 `e_t`，用由 `z_t` 生成的低秩线性控制器 `U_t` 做 `e_t <- e_t + U_t e_t`，再让后续冻结模型层把被控制后的内部状态转成动作；训练时用动作预测损失和 KL 学出 `z_t/beta_t/U_t`，强化学习时只在 `z_t` 空间探索。

_2026-07-26T21:53:16.749Z_

对，必须有一个**原始 PE 数值**，否则后面 credit、主动学习、ETA 更新都没有地基。

我建议 Volvence 里把 prediction error 拆成两层：

```text
原始 PE 数值：prediction vs actual 的可计算 mismatch
语义 PE 解释：这个 mismatch 属于什么 owner、意味着什么
```

核心原则是：

> 先算可复现的原始误差，再解释它。不能先解释再造分数。

**1. 最底层 PE 怎么算**

每次行动前，系统必须发布一个预测：

```text
PredictedOutcome
```

行动后，环境返回实际结果：

```text
ActualOutcome / EnvironmentOutcome
```

然后 PE owner 做比较：

```text
PE = distance(predicted, actual)
```

最简单统一公式可以是：

```text
pe_raw = weighted_sum(component_errors)
```

例如：

```text
pe_raw =
  0.30 * outcome_error
+ 0.20 * latency_error
+ 0.20 * user_response_error
+ 0.15 * commitment_error
+ 0.15 * relationship_error
```

但每个 component 必须来自 typed 字段，而不是靠文本关键词猜。

**2. 具体例子：工具调用**

预测：

```text
predicted:
  success_probability = 0.85
  expected_latency_ms = 1200
  expected_cost = 0.01
  expected_state_delta = "file_created"
```

实际：

```text
actual:
  success = false
  latency_ms = 4800
  cost = 0.02
  state_delta = "none"
```

原始 PE：

```text
success_error = |1 - 0.85| if success else |0 - 0.85| = 0.85
latency_error = normalized_abs_log_error(4800, 1200)
cost_error = normalized_abs_error(0.02, 0.01)
state_delta_error = 1.0 because predicted file_created but got none
```

合成：

```text
pe_raw = 0.85*w1 + latency*w2 + cost*w3 + state*w4
```

这个数将来可以直接和实际 outcome 对比，因为每一项都有 prediction 和 actual。

**3. 具体例子：对话理解**

预测不是“我觉得用户会满意”这种虚话，而要结构化：

```text
predicted:
  user_next_state:
    confusion_probability = 0.20
    clarification_needed_probability = 0.10
    likely_intent_resolved = 0.80
```

实际下一轮用户说：

```text
“这个和上面的说法矛盾吧？”
```

这由 environment/perception owner 转成 typed observation：

```text
actual:
  clarification_requested = true
  contradiction_challenge = true
  intent_resolved = false
```

PE：

```text
clarification_error = |1 - 0.10| = 0.90
intent_resolved_error = |0 - 0.80| = 0.80
contradiction_error = |1 - predicted_contradiction_probability|
```

这里不是用“矛盾”关键词直接学策略，而是把下一轮事件归一成 typed conversational outcome，再和上一轮预测比。

**4. 具体例子：关系状态**

预测：

```text
predicted:
  trust_delta = +0.05
  rapport_delta = +0.03
  boundary_risk = 0.05
```

实际由 relationship_state owner 的 pre/post snapshot 算：

```text
actual:
  trust_delta = -0.02
  rapport_delta = 0.00
  boundary_risk = 0.20
```

PE：

```text
relationship_pe =
  |actual_trust_delta - predicted_trust_delta|
+ |actual_rapport_delta - predicted_rapport_delta|
+ |actual_boundary_risk - predicted_boundary_risk|
```

重点：relationship PE 不是环境 outcome 自己写的，而是 relationship owner 发布 pre/post delta 后，PE owner 比较预测和实际。

**5. 推荐的原始 PE 数据结构**

可以这样想：

```text
PredictionErrorRecord:
  prediction_id
  owner
  predicted_value
  actual_value
  value_type
  raw_error
  normalized_error
  confidence
  surprise
  severity
  lineage
```

其中：

```text
raw_error:
  原始距离，比如 abs diff / NLL / 0-1 mismatch

normalized_error:
  归一化到 0..1，方便跨 component 聚合

confidence:
  当初预测有多自信

surprise:
  confidence * normalized_error

severity:
  这个误差影响有多大，不等于 surprise
```

我会把真正驱动学习的主量设为：

```text
learning_signal = surprise = confidence * normalized_error
```

因为：

```text
低置信预测错了：可接受
高置信预测错了：值得学
```

**6. 不同类型 PE 的算法**

```text
数值型：
  error = abs(actual - predicted) / scale

概率型：
  error = -log p_pred(actual)

分类型：
  error = 1 - p_pred(actual_class)

集合/状态型：
  error = Jaccard / edit distance / enum mismatch

向量型：
  error = 1 - cosine_similarity(predicted_vec, actual_vec)

分布型：
  error = KL(actual_distribution || predicted_distribution)
```

对 ETA 最重要的通常是：

```text
action/outcome prediction NLL
segment terminal outcome mismatch
user response prediction mismatch
owner state delta mismatch
```

**7. 和实际去比是什么意思**

将来要做验证时，每条 prediction 都要有可回放 lineage：

```text
prediction_id
predicted_at_turn
predicted_owner
action_context
z_t_digest
segment_id
environment_event_id
environment_outcome_id
actual_observed_at
```

这样你可以离线问：

```text

后来实际发生什么？
误差怎么算的？
这个误差归因给哪个 z segment？
更新有没有降低后续同类误差？
```

这才是真 PE，不是评估分。

**8. 和 ETA 的连接**

在 ETA 里：

```text
z_t segment 做了一段行为
系统对该段 outcome 有预测
实际 outcome 到来
PE owner 算 raw PE
credit owner 把 PE 分配给 segment
temporal owner 用 segment credit 更新 z-family / beta prior
```

所以链路是：

```text
Prediction
 -> Actual
 -> raw PE
 -> segment credit
 -> active learning / temporal update
```

**一句话**

预测误差的原始数，应该由“行动前结构化预测”和“行动后结构化实际结果”的距离算出；按类型用 NLL、绝对误差、分类误差、状态差异或向量距离，归一化后乘以预测置信度形成 surprise。语义解释和 credit 都在这个原始数之后，不能替代它。

够不够，关键取决于你说的是**单个位置的残差流**，还是**带上下文历史的残差流序列**。

短答案是：

> 单个 token 位置的残差流不一定够；但自回归模型在预测下一个 token 时，当前位置残差流已经聚合了前文上下文，所以它通常包含“为了预测下一步所需的足够统计量”。ETA 进一步不是只看一个点，而是用 `e_{1:t}` 或 `e_{1:T}` 的残差流序列来推断 `z_t / beta_t`。

具体拆。

**1. 自回归确实每次只预测下一个 token**

标准 LM 是：

```text
p(x_{t+1} | x_{1:t})
```

它只输出下一个 token 分布。

但为了输出这个分布，Transformer 在位置 `t` 的隐藏状态并不是只看 `x_t`，而是通过 causal attention 看了：

```text
x_1, x_2, ..., x_t
```

所以第 `t` 位残差流其实是：

```text
e_t = f(x_1:t)
```

它是整段前缀压缩后的当前状态。

这就像人说下一句话前，脑子里的当前状态不是最后一个字，而是整段上下文的压缩。

**2. 为什么它可能包含高层信息**

如果下一步动作依赖当前高层目标，那么模型为了预测下一步，就必须推断这个目标。

例子：

同一个位置、同一个画面：

```text
红点在左，蓝点在右
```

下一步往左还是往右，取决于：

```text
当前目标是 go red 还是 go blue
```

训练数据没有显式目标标签，但动作历史透露了目标。模型为了预测下一步动作，只能从历史里推断：

```text
这个专家现在大概率在追红点
```

于是这个 belief 会进入残差流，因为不用它就预测不准。

所以残差流的信息不是来自“下一个 token 本身”，而是来自：

```text
为了预测下一个 token，必须压缩历史中的潜在原因
```

**3. 但单步残差流确实有局限**

你这个怀疑是对的。单个 `e_t` 可能不够，尤其在：

```text
长程任务
隐含目标
多段计划
未来边界
关系状态
```

这些场景中，一个瞬时 hidden state 可能只保留对下一步最有用的信息，而不保留完整长期结构。

所以 ETA 论文里不是只用单个残差流点。它有：

```text
residual stream sequence e_{1:T}
internal sequence embedder s(e_{1:T})
GRU encoder over time
```

训练时甚至用非因果 future-conditioning：

```text
s(e_{1:T})
```

也就是说，它先看完整轨迹，把长段结构压出来，再训练 metacontroller 学会 `z_t / beta_t`。

运行时内部 RL 才替换成因果策略：

```text
pi(z_t | e_{1:t})
```

所以完整说法是：

```text
单个 e_t 是前缀压缩；
ETA 用 e 序列发现时间抽象；
RL 阶段再学习用因果前缀近似这个抽象选择。
```

**4. 信息量够不够由任务决定**

如果任务是：

```text
下一步语法补全
```

残差流里主要会有局部语法、语义。

如果任务是：

```text
专家在导航中追某个隐藏目标
```

残差流里会被迫编码目标 belief。

如果任务是：

```text
长期关系连续性
```

单轮残差流肯定不够，因为关系状态跨 session。那就必须加：

```text
memory snapshot
user_model snapshot
relationship_state snapshot
temporal controller state
```

所以 Volvence 不能只依赖 LLM 当前 residual stream。我们需要：

```text
residual stream
+ memory state
+ user model
+ relationship state
+ PE history
+ z/beta state
```

一起作为 controller 输入。

**5. 残差流不是记忆库**

这点很重要。

残差流是当前前向传播里的激活：

```text
短暂、即时、上下文相关
```

它不是长期记忆。

所以：

```text
残差流适合读“当前模型如何理解这一段上下文”
不适合单独保存“这个用户长期是谁”
```

长期持续性必须在外部 owner state：

```text
memory
relationship_state
user_model
commitment
```

运行时再把这些状态注入上下文或控制器输入，让残差流在当前 forward 里承载它们的影响。

**6. 为什么论文实验里够**

因为论文任务设计得很清楚：

```text
专家轨迹里当前子目标强烈决定下一步动作
历史动作能透露子目标
任务 horizon 虽长，但子目标结构简单
```

所以模型为了 next-action prediction，会自然学：

```text
当前在 go red / go blue / go green
```

线性 probe 能读出来，控制器能操纵它。

但这不意味着所有现实智能都能只靠一个模型 residual stream 解决。论文证明的是：

```text
在有层级结构的行为序列中，
自回归模型的残差流可以涌现可读可控的时间抽象表征。
```

不是说：

```text
残差流自动包含所有长期事实和关系状态。
```

**7. 对我们架构的结论**

所以你这个问题对 Volvence 的设计约束很关键：

```text
不要把 residual stream 当作唯一状态。
```

应该是：

```text
substrate residual stream:
  当前上下文里的即时 latent representation

persistent organism state:
  用户、关系、记忆、承诺、边界、长期 PE

temporal controller:
  把两者合起来，产生 z_t / beta_t
```

也就是：

```text
z_t = Encoder(residual_sequence, memory_snapshot, user_model, relationship_state, PE_carryover)
```

而不是：

```text
z_t = Encoder(single residual vector only)
```

一句话：

> 自回归模型虽然只预测下一个 token，但当前位置残差流已经是前文上下文的压缩状态，因此能包含预测下一步所需的潜在目标信息；不过单个残差流不保证足够，ETA 用残差流序列发现抽象，Volvence 还必须把持久记忆、用户模型、关系状态和 PE 历史一起纳入控制器输入。




```text

policy improvement:
  RL 是否利用新 abstraction

stability:
  交替是否不破坏旧结构

sample efficiency:
  同等 episode 下是否更快降低 PE
```

retain 条件：

```text
交替循环比单次 SSL/RL 更能发现新抽象并降低 PE。
```

## 68. Codex（最终答复）

_2026-07-28T12:21:32.259Z_

可以，但必须非常严谨地说：

**语言场景中的 Internal RL 是一个高度合理、但尚未被原论文证明的假设。**原论文证明的是游戏/连续控制环境中的可行性，不能直接外推到开放语言和长期关系。

而且有一个关键术语要纠正：

> 不是 Internal RL 自己“涌现”。  
> 真正涌现的是 SSL 阶段学出的 `z_t / beta_t` 时间抽象；Internal RL 是随后在这个抽象空间里进行策略优化的方法。

**为什么语言里理论上可以出现**

语言行为本身就存在持续多步的高层动作，例如：

- 探索用户真正的问题
- 澄清歧义
- 情绪承接
- 提供方案
- 检查用户是否接受
- 修复误解
- 设置安全边界
- 维持一个长期承诺

这些都不是单个 token，而是持续若干句、若干轮的“抽象动作”。因此语言天然满足 ETA 所需要的结构：

\[
\text{抽象动作 } z
\rightarrow
\text{持续生成若干 token/turn}
\rightarrow
\text{用户或环境产生结果}
\]

数学上可以写成：

\[
h_t = F_\theta(x_{1:t})
\]

\[
z_t=(1-\beta_t)z_{t-1}+\beta_t\tilde z_t
\]

\[
U_t=D(z_t),\qquad h'_t=h_t+U_t
\]

\[
y_t\sim LM_\theta(h'_t)
\]

然后在未来得到真实结果：

\[
o_{t+k}
\]

系统之前已经预测：

\[
\hat o_{t+k}=G(h_t,z_t)
\]

于是产生：

\[
PE_{t+k}=d(\hat o_{t+k},o_{t+k})
\]

再把这个误差归因给此前持续的一整个 `beta` segment，而不是归因给某个 token：

\[
C_s=\sum_{t\in segment_s}\gamma^{T-t}\,
Credit(PE_t, outcome_t)
\]

Internal RL 优化的是：

\[
\pi_\phi(z_t\mid h_{1:t})
\]

而不是直接优化 token。

这就是它在语言里真正有价值的地方：**基础模型继续逐 token 生成，但探索和信用分配可以在“对话策略”层发生。**

**一个具体例子**

用户说：

> 最近工作压力很大，我不知道要不要辞职。

系统内部可能存在几个没有人工命名的 `z-family`：

- `z_A`：继续探索事实
- `z_B`：承接情绪并降低压力
- `z_C`：结构化分析选择
- `z_D`：推动制定下一步行动
- `z_E`：检测风险并切换安全策略

注意，训练时不需要给它们这些中文标签。理想情况下，这些功能是从行为后果中涌现出来的。

第一轮系统选择 `z_A`，预测：

```text
用户会补充压力来源；
用户不会感觉被过早建议；
风险状态不会恶化。
```

接下来两轮用户确实开始说明老板、收入和家庭负担。`beta_t` 保持低值，系统继续处于同一个探索段。

后来用户说：

> 其实我已经三天没睡了，感觉快撑不住了。

此时原抽象动作不再能准确预测下一状态，PE 突然升高，`beta_t` 应该变大：

\[
\beta_t \rightarrow 1
\]

控制器切换到另一个 `z-family`，进入风险确认或安全支持策略。

Internal RL 最终学习的不是“哪句话分数高”，而是：

> 在什么内部状态下，应该持续哪种抽象动作；什么时候应该切换；哪种动作序列能降低未来预测误差并产生更好的真实结果。

**游戏到语言的四个重大鸿沟**

| 游戏环境 | 开放语言环境 |
|---|---|
| 状态较清晰 | 用户真实状态只能部分观察 |
| 动作有固定集合 | 一句话可以同时包含多个行为功能 |
| reward 较客观 | 用户回复、关系变化不是天然 reward |
| 子目标边界明显 | 话题边界不一定是因果行为边界 |
| 环境规则稳定 | 用户会变化，关系也会改变 |
| 成败可复现 | 同一句话对不同用户结果不同 |

最大的风险是：`beta_t` 可能只学到“换话题、换段落、换语气”，`z_t` 可能只编码“主题或风格”，而不是能影响长期结果的抽象动作。

所以 probe 出“能读出关系状态”远远不够。必须证明：

\[
do(z=z_A)\neq do(z=z_B)
\]

也就是在其他条件相同时，替换 `z` 会因果性地改变后续语言策略和真实结果。

**怎样一步步证明**

第一阶段不要直接上完全开放的陪伴对话，而应建立一个“语言化游戏环境”：

- 所有动作通过自然语言完成
- 用户有隐藏状态
- 必须多轮澄清才能成功
- 中间没有密集 reward
- 最后结果可以客观判断
- 训练组合和测试组合不同

例如多轮故障排查、协商、信息澄清、计划执行、承诺追踪。这些任务保留了游戏环境的可验证性，又具有真实语言的多义性。

随后进行五组关键实验：

1. **抽象涌现**

   检查 `z_t` 能否复用到没见过的对话组合，`beta_t` 是否对齐因果策略切换，而不只是文本边界。

2. **残差因果干预**

   固定模型、prompt、用户状态和随机种子，只替换或打乱 `z_t/U_t`，看高层行为是否发生稳定变化。

3. **Internal RL 贡献**

   比较 `full / no-SSL / no-RL / shuffled-z / turn-level RL`。必须是 full 在延迟结果和组合泛化上更好。

4. **真实 PE 信用**

   所有奖励都必须追溯到行动前预测和行动后结果，不能直接用“用户说谢谢了”或 LLM judge 分数冒充学习信号。

5. **从模拟用户迁移到真人**

   模拟器结果只能证明语言机制可行；只有真人、跨会话、盲评和外部 ground truth 才能支持关系学习主张。

**对 Volvence 的准确结论**

我的判断是：

- **理论上成立概率较高**：语言确实具有可持续、可复用的潜在行为结构。
- **工程路径成立**：共享模型提供通用 action-family 先验，每用户状态负责实际校准，Internal RL 可以工作在 `z` 空间。
- **科学证据尚未成立**：目前不能证明语言里的 `z/beta` 是因果策略，而不是主题、风格或文本分段。
- **原论文只是必要性证据，不是充分性证据**：它证明了这类机制能够存在，但没有证明开放对话中一定会形成我们想要的抽象。

因此 Volvence 最核心的实验不是“语言模型里能不能 probe 出一个 `z`”，而是：

> 在真实多轮语言环境里，基于 `beta` 分段的 `z` 空间 Internal RL，是否比逐 turn 信用、随机分段和普通 memory/RAG 更省反馈、更能处理延迟结果，并且对 held-out 用户与新情境具有组合泛化。

这个问题现在已经被钉进 [#92 Gate 2、Gate 4 和 Gate 7](/Users/mengfu/Documents/GitHub/volvence/docs/known-debts.md:2168)。在这些门通过前，我们应该把它称作 **Volvence 最关键的待验证核心假设**，而不是既成事实。
