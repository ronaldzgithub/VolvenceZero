## 4. Codex（最终答复）

_2026-07-27T22:33:08.381Z_

好，我们把 ETA 的核心数学先压成一个清晰骨架。我的判断是：ETA 不应该被理解成“多了一个策略模块”，而是一个**在冻结基底上学习时间抽象的 latent control system**。核心变量只有几组：

1. `e_t`：冻结 substrate 在时刻 `t` 暴露的 residual / feature state
2. `z_t`：低维控制器代码，也就是抽象动作状态
3. `beta_t`：切换门，决定继续当前抽象动作还是开启新段
4. `U_t = Decoder(z_t)`：把抽象代码映射回 residual control
5. `PE_t` / reward / credit：从预测误差派生的学习信号

**最核心方程**

ETA 的主循环可以写成：

```text
q_phi(z_tilde_t | e_1:t, m_t) = N(mu_t, Sigma_t)

beta_t = Switch_phi(e_1:t, z_{t-1}, m_t)

z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}

U_t = Decoder_phi(z_t)

e'_t = e_t + Apply(U_t, e_t)
```

这里 `beta_t` 是时间抽象的关键。  
`beta_t ≈ 0` 表示“继续同一个 option / abstract action”；`beta_t ≈ 1` 表示“切换到新的 abstract action”。所以 ETA 的 segment 不是外部 ledger 划出来的，而是由 `beta_t` 自己涌现出来的。

**自监督目标**

ETA 的第一阶段不是 RL，而是 SSL 压缩历史，让系统学到“什么 latent controller 能解释/预测行为”。

可以写成：

```text
L_SSL =
sum_t [
  - log p_theta,phi(a_t | o_1:t, z_1:t)
  + alpha * KL(q_phi(z_tilde_t | e_1:t) || N(0, I))
  + lambda_switch * Sparse(beta_t)
  + lambda_smooth * ||z_t - z_{t-1}||^2
]
```

其中最重要的是 KL bottleneck：它逼迫 `z_t` 不要记住所有细节，而只保留能跨时间解释行为的压缩结构。  
如果没有这个瓶颈，`z_t` 会退化成“每步特征副本”；有了它，才可能形成抽象动作。

**Internal RL 目标**

第二阶段才是在 `z_t` 空间做 RL，而不是 token/action 空间：

```text
pi_psi(z_t | e_1:t, m_t)

J_RL(psi) = E[ sum_t gamma^t r_t ]
```

但这里的动作不是文本 token，也不是具体工具调用，而是 latent controller code。更完整一点：

```text
A_t = GAE(r_t, V(e_1:t, z_t))

L_PPO =
E_t [
  min(
    rho_t A_t,
    clip(rho_t, 1-eps, 1+eps) A_t
  )
  - c_v * (V_t - R_t)^2
  + c_ent * H(pi_psi)
]
```

其中：

```text
rho_t = pi_psi(z_t | state_t) / pi_old(z_t | state_t)
```

这就是你仓库里说的 Internal RL：强化发生在 `z_t`，不是 token 空间。

**ETA 最关键的数学命题**

我觉得 ETA 的核心不是“有 GRU、有 decoder、有 PPO”，而是这三个约束同时成立：

```text
dim(z_t) << dim(e_t) << dim(token/action space)
```

```text
z_t changes sparsely through beta_t
```

```text
credit is assigned over beta-defined segments, not raw turns
```

也就是：

```text
segment_k = {t_i ... t_j}
where beta_t_i is switch/open
and beta_t_j or terminal closes it
```

然后 delayed credit 应该写到：

```text
Credit(segment_k)
  = f( PE_t_i:t_j, outcome_t_j, z_digest_k )
```

而不是简单写给最近一轮 response。

**我建议我们把 ETA 数学定成四层**

1. **Latent State Inference**
   `e_1:t -> q(z_tilde_t)`  
   负责从 residual/history 推断候选控制代码。

2. **Temporal Segmentation**
   `(z_{t-1}, z_tilde_t, e_1:t) -> beta_t`  
   负责 option boundary / segment closure。

3. **Residual Control**
   `z_t -> U_t -> e'_t`  
   负责让 latent abstract action 真正影响 substrate 表达。

4. **PE-first Learning**
   `prediction -> outcome -> PE -> credit -> update z-policy / priors`  
   负责学习，但 PE 是原始信号，evaluation 只是 readout/gate。

如果一句话概括：**ETA = 用变分瓶颈发现低维时间控制代码，用切换门把连续经历切成抽象动作段，再在这些 latent 段上做 PE-first credit 与 RL。**

我觉得下一步最值得讨论的是：`beta_t` 到底应该由什么压力塑形。这里是 ETA 是否真的“涌现”的核心。我的倾向是 `beta_t` 至少要吃四类信号：posterior drift、prediction error spike、memory/regime context change、action-family competition。

## 15. Codex（最终答复）

_2026-07-27T22:33:08.386Z_

可以。我们用一个非常具体的例子贯穿整篇论文：

> 任务：一只 ant 机器人要按顺序完成  
> **去红色点 -> 去蓝色点 -> 去绿色点**  
> 只有全部完成后才给 1 分奖励，中间没有奖励。

论文里的 ETA/内部 RL 原理，可以一一对应成下面这些东西。

**1. 原始动作：每一步关节怎么动**

ant 的底层动作是：

```text
第 1 步：左前腿关节 +0.2，右后腿关节 -0.1...
第 2 步：左前腿关节 +0.25，右后腿关节 -0.08...
第 3 步：...
```

这就像 LLM 一个 token 一个 token 输出。  
如果 RL 在这个层面探索，它必须碰巧生成几百步正确关节动作，先走到红点，再走到蓝点，再走到绿点，最后才拿到奖励。

这就是论文说的 **token-by-token / raw-action exploration 很低效**。

对应到 Volvence：

```text
raw action / token 层不是长期策略学习的主空间
```

**2. 抽象动作：不是“关节怎么动”，而是“去红色点”**

人不会这样规划：

```text
第 1 毫秒腿怎么动
第 2 毫秒腿怎么动
...
```

人会说：

```text
先去红色点
再去蓝色点
再去绿色点
```

论文里的 temporally-abstract action 就是这种东西。

对应关系：

```text
原始动作：每一步关节力矩
抽象动作：go red / go blue / go green
```

ETA 的目标就是让模型自己从行为序列里发现：

```text
这一大段关节动作其实是在“去红色点”
下一大段动作其实是在“去蓝色点”
```

而不是靠人手写标签。

**3. 残差流 e_t：模型脑子里当前“怎么看局面”**

自回归模型每一步都有内部激活。论文叫 residual stream activations，记作：

```text
e_t
```

具体例子：

```text
e_t 里可能隐含：
- ant 当前在哪里
- 红点大概在哪
- 当前轨迹像是在追红点还是蓝点
- 墙的位置
- 接下来专家大概率会往哪走
```

虽然模型只被训练预测下一步动作，但它内部为了预测动作，会形成对“当前子目标”的隐式 belief。

所以线性 probe 可以从 `e_t` 里读出：

```text
当前正在去红点：概率 0.82
当前正在去蓝点：概率 0.10
当前正在去绿点：概率 0.08
```

这就是论文第一部分：**下一个动作预测器内部自然涌现出子目标表征**。

**4. 线性控制器 U：轻轻推一下模型脑子，让它换目标**

论文发现，如果在模型中层残差流加一个线性控制器：

```text
e_t <- e_t + U e_t
```

就能 steering 模型。

具体例子：

```text
U_red  让模型倾向执行“去红点”的动作序列
U_blue 让模型倾向执行“去蓝点”的动作序列
U_green 让模型倾向执行“去绿点”的动作序列
```

如果人工按顺序插入：

```text
U_red -> U_blue -> U_green
```

模型就能完成没见过的新组合任务。

这说明两件事：

```text
模型内部有抽象目标表征
这些表征可以被简单线性控制器操纵
```

对应 Volvence 里的意思：

```text
substrate 冻结
temporal owner 只通过 residual/control surface 调制
不直接改基底
```

**5. z_t：不是直接存 U，而是存“控制器代码”**

每个控制器 `U` 很大。论文不直接让 RL 操作 `U`，而是学一个低维代码：

```text
z_red   -> Decoder -> U_red
z_blue  -> Decoder -> U_blue
z_green -> Decoder -> U_green
```

具体类比：

```text
z_t = “当前抽象动作的压缩编码”
Decoder(z_t) = 生成对应残差流控制器
```

所以：

```text
z_t 不是一句话标签
z_t 不是 prompt
z_t 是低维 latent controller code
```

对应 Volvence：

```text
ControllerState.code == z_t
```

**6. beta_t：什么时候继续，什么时候切换**

这是 ETA 最核心的东西。

假设 ant 正在去红点。连续很多步里，应该保持同一个 `z_red`：

```text
t=1   beta=1    切换到 z_red
t=2   beta=0    继续 z_red
t=3   beta=0    继续 z_red
...
t=40  beta=0    继续 z_red
t=41  beta=1    到达红点，切换到 z_blue
```

公式就是：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

具体解释：

```text
beta_t = 0：
不要理会新的候选 z，继续之前的抽象动作。

beta_t = 1：
采用新的候选 z，开启新抽象动作。

beta_t = 0.3：
部分更新，介于继续和切换之间。
```

所以 `beta_t` 不是普通 gate。它定义了时间段：

```text
Segment 1: 去红点
Segment 2: 去蓝点
Segment 3: 去绿点
```

对应 Volvence：

```text
closed_segments 必须来自 beta_t
delayed credit 不应该靠最近 turn 猜
```

**7. 自监督训练：没有“去红点”标签，也能学出来**

训练数据里只有：

```text
观测，动作，观测，动作...
```

没有：

```text
这里是在去红点
这里切换到蓝点
```

元控制器训练时要做的是：生成 `z_t` 和 `U_t`，让冻结基础模型更好预测下一步动作。

损失是：

```text
动作预测损失 + KL 正则
```

具体例子：

```text
如果 z_t 乱切：
模型预测动作变差。

如果 z_t 每一步都记所有细节：
KL 惩罚变大。

最优解：
把一大段共用目标的动作压成一个 z，比如 z_red；
到目标变了再切换。
```

所以它会自然学到：

```text
第 1-40 步：一个 z 就够，因为都在去红点
第 41-80 步：另一个 z，因为开始去蓝点
```

这就是论文里最漂亮的地方：  
**稀疏切换不是手写出来的，是瓶颈压力下涌现出来的。**

**8. KL 瓶颈：防止 z_t 变成逐步作弊小抄**

如果没有 KL，`z_t` 可能这样：

```text
z_1 = 第 1 步该怎么动
z_2 = 第 2 步该怎么动
z_3 = 第 3 步该怎么动
```

这就不是时间抽象，只是把原始动作藏进 latent 里。

KL 正则逼它接近：

```text
N(0, I)
```

实际效果：

```text
z_t 容量有限
不能记住每一步细节
只能记住最有压缩价值的结构
```

于是模型倾向学：

```text
z_red = 一整段“去红点”的共同原因
```

而不是：

```text
z_17 = 第 17 步腿怎么动
```

对应 Volvence：

```text
z_t 必须是 compressed control code
不能变成语义状态第二 owner
也不能变成 action trace
```

**9. 为什么必须冻结基础模型**

论文比较了两种情况：

```text
A. 冻结基础模型，只训练元控制器
B. 基础模型和元控制器一起训练
```

具体例子：

在 A 中，基础模型已经形成了稳定内部表征：

```text
红点方向、当前子目标、动作模式
```

元控制器只能学习如何读写这些已有结构，所以容易发现：

```text
z_red / z_blue / z_green
```

在 B 中，基础模型也在变。它可能找到更偷懒的解：

```text
整段序列开始时切一次
后面靠基础模型内部自己吸收所有信息
```

结果 `beta_t` 不再对齐子目标，时间抽象退化。

对应 Volvence 的铁律：

```text
冻结基底 + 自适应控制器
online 不端到端更新整个 base model
```

**10. Internal RL：RL 不选关节动作，而选 z**

现在进入强化学习。

标准 RL 需要探索：

```text
每一步关节动作怎么选
```

内部 RL 探索的是：

```text
这段选 z_red 还是 z_blue？
什么时候切换？
下一段选哪个 z？
```

也就是：

```text
raw RL:
第 1 步动作、第 2 步动作、第 3 步动作...

internal RL:
第 1 段 go red
第 2 段 go blue
第 3 段 go green
```

搜索空间瞬间变小。

具体比较：

```text
原始动作空间：
300 个低层时间步，每步 8 个连续关节维度。

z 空间：
3-5 个抽象段，每段选一个 16 维 latent code。
```

所以稀疏奖励终于能学：

```text
成功奖励 1 分
可以回传给 z_red -> z_blue -> z_green 这个抽象序列
```

而不是淹没在几百步关节噪声里。

**11. delayed credit：奖励给 segment，不给最近一步**

假设 ant 第 120 步终于完成任务，得到奖励。

错误做法：

```text
奖励最近一步动作。
```

这会错，因为成功来自整个序列：

```text
先去红点
再去蓝点
再去绿点
```

ETA 正确做法：

```text
Segment 1: z_red
Segment 2: z_blue
Segment 3: z_green
```

奖励/PE 通过 segment 分配：

```text
z_red 有贡献
z_blue 有贡献
z_green 有贡献
```

对应 Volvence：

```text
EnvironmentOutcome -> PredictionError
PredictionError + temporal.closed_segments -> Credit
Credit 再进入 temporal owner 更新
```

这也是为什么你仓库里“不新增 delayed ledger owner”是对的：  
时间边界已经由 `beta_t` owner 产生。

```text
当前位置
```

```text
probe(e_{t,l}) -> 当前子目标概率
```

它能从残差流里读出：

```text
P(go red)   = 0.91

P(go green) = 0.03
```

```text
残差流里有一个分布式 latent state。
这个 latent state 线性可读出当前抽象动作 belief。

```

这就是论文最重要的实验证据。

用一个非常具体的例子：

也就是说：

```text
不是人告诉模型：这叫 red subgoal。
而是模型发现：有一类长时间动作序列共享某个隐藏原因。
```

这个隐藏原因在实验者看来对应“去红点”。

所以 ETA 里的内部表征可以这样定义：

> 在冻结自回归模型的残差流中，存在一种可线性解码、可因果干预、跨多个时间步稳定存在的 latent variable；它解释一整段低层动作序列的共同生成原因。这个 latent variable 就是时间抽象动作的内部表征。

为什么它会在残差流里？因为自回归模型要预测下一步动作，而下一步动作往往取决于长程目标。

如果模型只知道当前位置，不知道当前目标，它无法判断：

```text
同一个位置，下一步该往左还是往右？
```

例如：

```text
当前位置相同
红点在左
蓝点在右

如果任务是 go red：下一步向左
如果任务是 go blue：下一步向右
```

训练数据里没有显式目标标签，但动作历史会透露目标。模型为了降低 next-action loss，就会从历史中推断一个 latent goal belief，并把它放进内部状态。

```text

```

```text
强化它：internal RL
```

对，问到骨头上了。我们拆开。

**1. 残差流具体是什么**

在 Transformer 里，每一层大概是这样：

```text
x_l
 -> Attention
 -> x_l + Attention(x_l)
 -> MLP
 -> x_l + MLP(x_l)
 -> x_{l+1}
```

这里那条一直被加来加去、往下一层传的主干向量，就是 **residual stream**。

更具体：

```text
x_0 = token embedding + position embedding

第 1 层：
x_1 = x_0 + Attn_1(norm(x_0)) + MLP_1(norm(...))

第 2 层：
x_2 = x_1 + Attn_2(norm(x_1)) + MLP_2(norm(...))

...

第 L 层：
x_L -> logits -> next token/action
```

每个时间步 `t`、每一层 `l` 都有一个残差流向量：

```text
e_{t,l}
```

它就是模型在“第 t 个 token/动作位置、第 l 层处理到一半或处理完”的内部状态。

如果是语言模型：

```text
e_{t,l} = 模型在第 t 个 token 位置、第 l 层的隐藏向量
```

如果是 ant 行为模型：

```text
e_{t,l} = 模型在第 t 个观测-动作位置、第 l 层的隐藏向量
```

所以残差流不是额外模块。它就是 Transformer 主干里每层传递信息的隐藏状态通道。

**2. ETA 控制的是哪里**

论文不是控制所有层，也不是每一层都加控制器。它主要发现：**中层附近最好控**。

形式是：

```text
e_{t,l} <- e_{t,l} + U_t e_{t,l}
```

也就是在某一层 `l` 的残差流上插入一个线性干预。

你可以想象成：

```text
embedding
  -> 前几层：解析局面、历史、局部信息
  -> 中层：形成“当前目标/子任务”这种抽象状态
  -> 后几层：把抽象状态翻译成具体下一步动作/logits
```

所以在中层控制最有效：

```text
太早：信息还没整理好，控制方向不稳定
太晚：动作 logits 快出来了，来不及影响完整行为
中层：正好是“抽象意图 -> 低层动作”转换的地方
```

论文图 4 的意思就是：控制器插在中层，成功率最高。

所以答案是：

```text
不是每一层都控制。
通常选一个中间层 residual stream 做 read/write。
```

但元控制器可以“读”序列里的残差激活，再“写”到某个选定层。

**3. 每个时间步都控制吗**

控制器可以每个时间步都应用，但不是每个时间步都换一个控制器。

例如：

```text
t=1   使用 U_red
t=2   继续使用 U_red
t=3   继续使用 U_red
...
t=40  继续使用 U_red
t=41  切换成 U_blue
```

也就是说：

```text
控制发生在每步
切换不是每步
```

这个区别很关键。

每一步 residual 都被当前控制器轻推一下：

```text
e_{t,l} <- e_{t,l} + U_red e_{t,l}
```

但 `U_red` 可以持续很多步。

**4. 为什么要分段**

因为现实任务不是每一步都重新决定“我要成为什么”。

还是 ant 的例子：

```text
任务：去红点 -> 去蓝点 -> 去绿点
```

低层动作可能有 300 步：

```text
1,2,3,...,300
```

但真正的高层结构只有 3 段：

```text
1-80:   去红点
81-190: 去蓝点
191-300: 去绿点
```

如果不分段，RL 要在 300 个时间步上探索和归因。奖励只在最后给：

```text
第 300 步成功，reward = 1
```

那问题是：到底哪几步有贡献？

```text
第 299 步？
第 230 步？
第 90 步？
第 12 步？
```

信用分配会非常难。

分段之后，问题变成：

```text
Segment 1: go red
Segment 2: go blue
Segment 3: go green
```

成功奖励可以归因给这三个抽象动作段，而不是 300 个低层动作。

这就是分段的第一个原因：**降低信用分配难度**。

第二个原因：**降低探索空间**。

不分段时，探索是：

```text
每一步都采样低层动作
```

分段后，探索是：

```text
每一段采样一个抽象动作 z
```

从：

```text
300 次决策
```

变成：

```text
3 次决策
```

这对稀疏奖励是生死差别。

第三个原因：**复用子程序**。

如果学到了：

```text
go red
go blue
go green
```

以后新任务：

```text
go blue -> go red -> go green
```

就可以复用已有段，只需要重新排序。

没有分段，就没有明确的可复用单位。

**5. beta_t 就是分段器**

论文里的 `beta_t` 做这个事：

```text
beta_t ≈ 0：继续当前段
beta_t ≈ 1：开启新段
```

公式：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

具体：

```text
t=1: beta=1   新段：go red
t=2: beta=0   继续 go red
...
t=80: beta=0  继续 go red
t=81: beta=1  新段：go blue
```

所以 `beta_t` 不只是一个神经网络 gate。它定义了：

```text
哪个 z 从哪里开始
哪个 z 到哪里结束
哪个 reward 应该回传给哪段
```

**一句话**

残差流就是 Transformer 每层里那条主隐藏状态通道；ETA 通常在中层残差流上读写，用线性控制器持续影响每一步行为，但只在 `beta_t` 指示时切换控制器。分段是为了把几百步低层动作压成几个可复用、可探索、可归因的抽象动作段。

_2026-07-27T22:33:08.388Z_

`beta_t` 是一个**切换单元 switch unit** 算出来的，不是人工标注出来的。

论文里的结构大概是：

```text
残差流历史 e_1:t
当前 encoder hidden state
上一刻 z_{t-1}
候选 z_tilde_t
        |
        v
Switching unit
        |
        v
beta_t in [0, 1]
```

然后它进入公式：

```text
z_t = beta_t * z_tilde_t + (1 - beta_t) * z_{t-1}
```

所以 `beta_t` 本质上是神经网络输出的一个 gate。

**非常具体一点**

假设元控制器里有一个 GRU encoder。每个时间步它看到残差流：

```text
e_t
```

并更新内部状态：

```text
h_t = GRU(h_{t-1}, e_t, sequence_context)
```

然后从 `h_t` 产生两个东西。

第一个是候选新控制器代码：

```text
mu_t, Sigma_t = EncoderHead(h_t)
z_tilde_t ~ N(mu_t, Sigma_t)
```

第二个是切换门：

```text
beta_t = sigmoid(W_beta h_t + b_beta)
```

或者更一般：

```text
beta_t = SwitchNet(h_t, z_{t-1}, e_t)
```

输出范围是 `[0, 1]`。

所以它不是规则：

```text
如果到红点就 beta=1
```

而是可学习函数：

```text
beta_t = f_switch(...)
```

**它怎么学会什么时候切？**

关键在训练目标。

训练时没有子目标标签：

```text
没有告诉它：第 40 步从红切蓝
```

它只有动作预测损失和 KL 正则：

```text
L = next-action prediction loss + alpha * KL
```

如果它太少切：

```text
一直用同一个 z
```

那一个控制器要解释整条轨迹：

```text
去红点 -> 去蓝点 -> 去绿点
```

动作预测会变差，因为不同阶段需要不同控制策略。

如果它太频繁切：

```text
每一步都换 z
```

它可以预测得更细，但每次新 `z_tilde_t` 都要从 posterior 带信息过来，会被 KL 瓶颈惩罚，而且不能形成好的标准正态先验采样结构。

于是最划算的解变成：

```text
在真正的子目标边界切
段内保持
```

比如：

```text
去红点期间，继续 z_red
到红点后，动作模式突然变成去蓝点
这时继续 z_red 会让预测损失上升
所以 switch unit 学会 beta_t -> 1
```

这就是 `beta_t` 涌现的机制。

**更直观的训练压力**

看这个序列：

```text
t=1-40:  专家持续朝红点走
t=41-80: 专家持续朝蓝点走
```

如果 `beta_t` 在 t=20 切：

```text
前后其实都还在去红点
新 z 没必要
KL 成本增加
```

不划算。

如果 `beta_t` 到 t=60 才切：

```text
t=41-60 已经开始去蓝点
但还用 z_red
动作预测变差
```

也不划算。

所以最优位置自然靠近：

```text
t=41
```

即真实抽象动作切换点。

**论文里还有一个重要点：训练时 beta 基本是连续的**

训练时：

```text
beta_t in [0, 1]
```

可以是：

```text
0.03, 0.08, 0.92
```

论文说实际训练后它会变得 quasi-binary：

```text
大多数时候接近 0
切换时接近 1
```

也就是近似二值。

内部 RL 时，为了让抽象动作段更明确，还会 harden：

```text

```

例如：

```text
    hard_beta_t = 1
else:
    hard_beta_t = 0
```

然后：

```text

hard_beta=1 -> 换新 z
```

**它用不用未来信息？**

论文里比较细。

元控制器训练时 encoder 是非因果的，可以用整段序列 embedding：

```text
s(e_1:T)
```

所以训练时它更容易发现“这里应该切”，因为它能看到未来动作变了。

但内部 RL 阶段不能看未来，所以会替换成因果策略：

```text
pi(z_t | e_1:t)
```

而论文附录里也说，实验中他们让 switch 近似只依赖因果信息：

```text
q(beta_t | e_1:t, a_1:T) ≈ q(beta_t | e_1:t)
```

目的就是让 beta 在 RL 时可以真实在线发出。

**一句话**

`beta_t` 是 switch unit 从残差流/encoder 状态里学出来的一个连续切换门。它通过动作预测损失和 KL 瓶颈共同训练：切太少会预测不准，切太多会付出信息成本，所以最优解自然变成“段内保持、子目标边界切换”。

残差流控制的具体算法，可以拆成两步：

```text
1. 在 Transformer 某一层拿到残差流向量 e_{t,l}
2. 用一个控制器 U_t 对它做线性干预
```

核心公式就是论文里的 Eq. 1：

```text
e_{t,l} <- e_{t,l} + U_t e_{t,l}
```

也就是：

```text
新残差流 = 原残差流 + 控制器作用后的残差流增量
```

**1. Transformer 里的位置**

假设一层 Transformer 是：

```text
x_l
 -> Attention
 -> x_l + Attention(...)
 -> MLP
 -> x_l + Attention(...) + MLP(...)
 -> x_{l+1}
```

残差流就是这条 `x_l -> x_{l+1}` 的主隐藏状态。

控制发生在某个中间层 `l`：

```text
x_l = residual stream at layer l
x_l_controlled = x_l + U_t x_l
```

然后模型继续跑后面的层：

```text
x_l_controlled -> layer l+1 -> ... -> logits -> action
```

所以不是直接改输出动作，而是改中间表示，让后续层自然生成不同动作。

**2. U_t 是什么**

`U_t` 是一个线性矩阵：

```text
U_t in R^{n_e x n_e}
```

如果残差流维度是 768：

```text
e_t in R^768
U_t in R^{768 x 768}
```

直接学完整矩阵太大，所以通常用低秩形式：

```text
U_t = A_t B_t
```

其中：

```text
A_t in R^{n_e x r}
B_t in R^{r x n_e}
r << n_e
```

例如：

```text
n_e = 768
r = 8
```

那么：

```text
U_t e_t = A_t (B_t e_t)
```

这和 LoRA 很像。

完整控制变成：

```text
e'_{t,l} = e_{t,l} + A_t B_t e_{t,l}
```

**3. 最简单的监督版算法**

先看最简单版本：假设你有人类标签，知道当前该去哪个子目标。

比如有 4 个子目标：

```text
red, blue, green, yellow
```

训练 4 个控制器：

```text
U_red
U_blue
U_green
U_yellow
```

训练时冻结基础模型 `theta`，只训练这些 `U_g`。

每条训练样本：

```text
当前目标是 red
观测历史 o_1:t
专家动作 a_t
```

前向：

```text
e_{t,l} = BaseModelResidual(o_1:t, layer=l)

e'_{t,l} = e_{t,l} + U_red e_{t,l}

p(a_t | o_1:t, U_red) = 后续层输出动作分布
```

损失：

```text
L = - log p(a_t | o_1:t, U_red)
```

反向传播时：

```text
冻结 base model 参数 theta
只更新 U_red
```

伪代码：

```python
for batch in data:
    goal = batch.goal_label          # red / blue / green...
    action = batch.expert_action

    with freeze(base_model):
        e = base_model.forward_to_layer(batch.obs_history, layer=l)

        U = controllers[goal]
        e_controlled = e + U @ e

        logits = base_model.forward_from_layer(e_controlled, layer=l)
        loss = cross_entropy(logits, action)

    loss.backward()
    optimizer.step(controllers[goal])
```

这个版本证明：

```text
残差流里确实有可控的子目标表征
```

但它用到了标签，不是最终 ETA。

**4. ETA 版：U_t 由 z_t 生成**

无监督 ETA 不再维护：

```text
U_red, U_blue, U_green
```

而是：

```text
z_t -> Decoder -> U_t
```

也就是说，元控制器生成控制器。

流程：

```text
残差流历史 e_{1:t}
      ↓
Encoder
      ↓
候选 controller code z_tilde_t
      ↓
Switch unit 得到 beta_t
      ↓
z_t = beta_t z_tilde_t + (1-beta_t) z_{t-1}
      ↓
Decoder(z_t)
      ↓
U_t
      ↓
e'_{t,l} = e_{t,l} + U_t e_{t,l}
```

算法上就是：

```python
e_t = base_model.forward_to_layer(obs_history, layer=l)

mu_t, sigma_t = encoder(e_history, future_context_during_ssl)
z_tilde = sample_normal(mu_t, sigma_t)

beta_t = switch_unit(e_history, z_prev)

z_t = beta_t * z_tilde + (1 - beta_t) * z_prev

U_t = decoder(z_t)

e_controlled = e_t + U_t @ e_t

logits = base_model.forward_from_layer(e_controlled, layer=l)

loss = action_prediction_loss(logits, expert_action) \
     + alpha * kl_normal(mu_t, sigma_t, standard_normal)

update(meta_controller_params)
```

其中 base model 仍然冻结。

**5. Decoder 怎么生成 U_t**

最直接：

```text
Decoder(z_t) -> full matrix U_t
```

但太大。

更实际是生成低秩因子：

```text
Decoder_A(z_t) -> A_t
Decoder_B(z_t) -> B_t
U_t = A_t B_t
```

控制：

```text
e' = e + A_t (B_t e)
```

也可以加 scale / clamp：

```text
delta = A_t (B_t e)
delta = clamp_norm(delta, max_delta)
e' = e + eta * delta
```

这样避免控制过强，把模型激活推爆。

**6. 为什么是乘 `U_t e_t`，不是加一个固定向量**

可以有两种控制：

```text
additive steering:
e' = e + v

linear controller:
e' = e + U e
```

论文用的是线性控制器：

```text
e' = e + U e
```

因为它是状态依赖的。

具体区别：

```text
固定向量 v：
无论当前位置在哪里，都推同一个方向。

线性控制器 U：
根据当前 e_t 的不同，产生不同增量。
```

例如同样是 `go red`：

```text
如果 ant 在红点左边，需要向右走。
如果 ant 在红点右边，需要向左走。
```

固定向量很难表达这个；`U e_t` 可以根据当前状态产生不同控制增量。

所以 `U_t` 不是“直接命令往左”，而是一个小策略变换：

```text
在当前局面下，把内部状态改造成更像正在执行某个抽象目标的状态。
```

**7. 控制哪一层**

论文发现中层最好。

算法上可以 sweep：

```python
for layer in candidate_layers:
    train_controller_at(layer)
    evaluate_success()
```

结果通常是：

```text
浅层：信息太原始，不好控制
中层：抽象目标表征强，可控性最好
深层：太接近输出，干预窗口太短
```

所以实践里选：

```text
layer = middle_layer
```

例如 12 层模型选第 5/6 层附近。

**8. 内部 RL 阶段的残差流控制**

SSL 训练完后，encoder 可以被替换为因果策略：

```text
pi(z_t | e_{1:t})
```

然后 RL 选择 `z_t`，decoder 生成 `U_t`，继续控制残差流：

```text
z_t ~ pi(z_t | e_{1:t})
U_t = Decoder(z_t)
e' = e + U_t e
action = base_model_after_control(e')
reward = environment(action)
```

内部 RL 不直接更新 base model，也不直接输出 raw action。它更新的是：

```text
pi(z_t | e_{1:t})
```

也就是如何选择 latent controller code。

**9. 完整算法小结**

训练阶段：

```text
输入：无标签专家轨迹
冻结：base model theta
训练：metacontroller phi

for each trajectory:
  for each time t:
    e_t = residual at layer l
    z_tilde = encoder(e_history, sequence_context)
    beta_t = switch(e_history, z_prev)
    z_t = beta_t z_tilde + (1-beta_t) z_prev
    U_t = decoder(z_t)
    e'_t = e_t + U_t e_t
    predict action a_t
    loss = -log p(a_t) + alpha KL
```

RL 阶段：

```text
冻结：base model + decoder + switch mostly fixed
训练：causal policy pi(z | e_history)

while episode:
  e_t = residual at layer l
  if beta says switch:
      z_t ~ pi(z | e_history)
  else:
      z_t = z_prev
  U_t = decoder(z_t)
  e'_t = e_t + U_t e_t
  action = model output
  environment returns outcome/reward
  update pi with RL on z-space
```

**一句话**

残差流控制算法就是：在 Transformer 中层残差流取出隐藏向量 `e_t`，用由 `z_t` 生成的低秩线性控制器 `U_t` 做 `e_t <- e_t + U_t e_t`，再让后续冻结模型层把被控制后的内部状态转成动作；训练时用动作预测损失和 KL 学出 `z_t/beta_t/U_t`，强化学习时只在 `z_t` 空间探索。

_2026-07-27T22:33:08.394Z_

对，必须有一个**原始 PE 数值**，否则后面 credit、主动学习、ETA 更新都没有地基。

我建议 Volvence 里把 prediction error 拆成两层：

```text
原始 PE 数值：prediction vs actual 的可计算 mismatch
语义 PE 解释：这个 mismatch 属于什么 owner、意味着什么
```

核心原则是：

> 先算可复现的原始误差，再解释它。不能先解释再造分数。

**1. 最底层 PE 怎么算**

每次行动前，系统必须发布一个预测：

```text
PredictedOutcome
```

行动后，环境返回实际结果：

```text
ActualOutcome / EnvironmentOutcome
```

然后 PE owner 做比较：

```text
PE = distance(predicted, actual)
```

最简单统一公式可以是：

```text
pe_raw = weighted_sum(component_errors)
```

例如：

```text
pe_raw =
  0.30 * outcome_error
+ 0.20 * latency_error
+ 0.20 * user_response_error
+ 0.15 * commitment_error
+ 0.15 * relationship_error
```

但每个 component 必须来自 typed 字段，而不是靠文本关键词猜。

**2. 具体例子：工具调用**

预测：

```text
predicted:
  success_probability = 0.85
  expected_latency_ms = 1200
  expected_cost = 0.01
  expected_state_delta = "file_created"
```

实际：

```text
actual:
  success = false
  latency_ms = 4800
  cost = 0.02
  state_delta = "none"
```

原始 PE：

```text
success_error = |1 - 0.85| if success else |0 - 0.85| = 0.85
latency_error = normalized_abs_log_error(4800, 1200)
cost_error = normalized_abs_error(0.02, 0.01)
state_delta_error = 1.0 because predicted file_created but got none
```

合成：

```text
pe_raw = 0.85*w1 + latency*w2 + cost*w3 + state*w4
```

这个数将来可以直接和实际 outcome 对比，因为每一项都有 prediction 和 actual。

**3. 具体例子：对话理解**

预测不是“我觉得用户会满意”这种虚话，而要结构化：

```text
predicted:
  user_next_state:
    confusion_probability = 0.20
    clarification_needed_probability = 0.10
    likely_intent_resolved = 0.80
```

实际下一轮用户说：

```text
“这个和上面的说法矛盾吧？”
```

这由 environment/perception owner 转成 typed observation：

```text
actual:
  clarification_requested = true
  contradiction_challenge = true
  intent_resolved = false
```

PE：

```text
clarification_error = |1 - 0.10| = 0.90
intent_resolved_error = |0 - 0.80| = 0.80
contradiction_error = |1 - predicted_contradiction_probability|
```

这里不是用“矛盾”关键词直接学策略，而是把下一轮事件归一成 typed conversational outcome，再和上一轮预测比。

**4. 具体例子：关系状态**

预测：

```text
predicted:
  trust_delta = +0.05
  rapport_delta = +0.03
  boundary_risk = 0.05
```

实际由 relationship_state owner 的 pre/post snapshot 算：

```text
actual:
  trust_delta = -0.02
  rapport_delta = 0.00
  boundary_risk = 0.20
```

PE：

```text
relationship_pe =
  |actual_trust_delta - predicted_trust_delta|
+ |actual_rapport_delta - predicted_rapport_delta|
+ |actual_boundary_risk - predicted_boundary_risk|
```

重点：relationship PE 不是环境 outcome 自己写的，而是 relationship owner 发布 pre/post delta 后，PE owner 比较预测和实际。

**5. 推荐的原始 PE 数据结构**

可以这样想：

```text
PredictionErrorRecord:
  prediction_id
  owner
  predicted_value
  actual_value
  value_type
  raw_error
  normalized_error
  confidence
  surprise
  severity
  lineage
```

其中：

```text
raw_error:
  原始距离，比如 abs diff / NLL / 0-1 mismatch

normalized_error:
  归一化到 0..1，方便跨 component 聚合

confidence:
  当初预测有多自信

surprise:
  confidence * normalized_error

severity:
  这个误差影响有多大，不等于 surprise
```

我会把真正驱动学习的主量设为：

```text
learning_signal = surprise = confidence * normalized_error
```

因为：

```text
低置信预测错了：可接受
高置信预测错了：值得学
```

**6. 不同类型 PE 的算法**

```text
数值型：
  error = abs(actual - predicted) / scale

概率型：
  error = -log p_pred(actual)

分类型：
  error = 1 - p_pred(actual_class)

集合/状态型：
  error = Jaccard / edit distance / enum mismatch

向量型：
  error = 1 - cosine_similarity(predicted_vec, actual_vec)

分布型：
  error = KL(actual_distribution || predicted_distribution)
```

对 ETA 最重要的通常是：

```text
action/outcome prediction NLL
segment terminal outcome mismatch
user response prediction mismatch
owner state delta mismatch
```

**7. 和实际去比是什么意思**

将来要做验证时，每条 prediction 都要有可回放 lineage：

```text
prediction_id
predicted_at_turn
predicted_owner
action_context
z_t_digest
segment_id
environment_event_id
environment_outcome_id
actual_observed_at
```

这样你可以离线问：

```text
当时预测了什么？
后来实际发生什么？
误差怎么算的？
这个误差归因给哪个 z segment？
更新有没有降低后续同类误差？
```

这才是真 PE，不是评估分。

**8. 和 ETA 的连接**

在 ETA 里：

```text
z_t segment 做了一段行为
系统对该段 outcome 有预测
实际 outcome 到来
PE owner 算 raw PE
credit owner 把 PE 分配给 segment
temporal owner 用 segment credit 更新 z-family / beta prior
```

所以链路是：

```text
Prediction
 -> Actual
 -> raw PE
 -> segment credit
 -> active learning / temporal update
```

**一句话**

预测误差的原始数，应该由“行动前结构化预测”和“行动后结构化实际结果”的距离算出；按类型用 NLL、绝对误差、分类误差、状态差异或向量距离，归一化后乘以预测置信度形成 surprise。语义解释和 credit 都在这个原始数之后，不能替代它。

够不够，关键取决于你说的是**单个位置的残差流**，还是**带上下文历史的残差流序列**。

短答案是：

> 单个 token 位置的残差流不一定够；但自回归模型在预测下一个 token 时，当前位置残差流已经聚合了前文上下文，所以它通常包含“为了预测下一步所需的足够统计量”。ETA 进一步不是只看一个点，而是用 `e_{1:t}` 或 `e_{1:T}` 的残差流序列来推断 `z_t / beta_t`。

具体拆。

**1. 自回归确实每次只预测下一个 token**

标准 LM 是：

```text
p(x_{t+1} | x_{1:t})
```

它只输出下一个 token 分布。

但为了输出这个分布，Transformer 在位置 `t` 的隐藏状态并不是只看 `x_t`，而是通过 causal attention 看了：

```text
x_1, x_2, ..., x_t
```

所以第 `t` 位残差流其实是：

```text
e_t = f(x_1:t)
```

它是整段前缀压缩后的当前状态。

这就像人说下一句话前，脑子里的当前状态不是最后一个字，而是整段上下文的压缩。

**2. 为什么它可能包含高层信息**

如果下一步动作依赖当前高层目标，那么模型为了预测下一步，就必须推断这个目标。

例子：

同一个位置、同一个画面：

```text
红点在左，蓝点在右
```

下一步往左还是往右，取决于：

```text
当前目标是 go red 还是 go blue
```

训练数据没有显式目标标签，但动作历史透露了目标。模型为了预测下一步动作，只能从历史里推断：

```text
这个专家现在大概率在追红点
```

于是这个 belief 会进入残差流，因为不用它就预测不准。

所以残差流的信息不是来自“下一个 token 本身”，而是来自：

```text
为了预测下一个 token，必须压缩历史中的潜在原因
```

**3. 但单步残差流确实有局限**

你这个怀疑是对的。单个 `e_t` 可能不够，尤其在：

```text
长程任务
隐含目标
多段计划
未来边界
关系状态
```

这些场景中，一个瞬时 hidden state 可能只保留对下一步最有用的信息，而不保留完整长期结构。

所以 ETA 论文里不是只用单个残差流点。它有：

```text
residual stream sequence e_{1:T}
internal sequence embedder s(e_{1:T})
GRU encoder over time
```

训练时甚至用非因果 future-conditioning：

```text
s(e_{1:T})
```

也就是说，它先看完整轨迹，把长段结构压出来，再训练 metacontroller 学会 `z_t / beta_t`。

运行时内部 RL 才替换成因果策略：

```text
pi(z_t | e_{1:t})
```

所以完整说法是：

```text
单个 e_t 是前缀压缩；
ETA 用 e 序列发现时间抽象；
RL 阶段再学习用因果前缀近似这个抽象选择。
```

**4. 信息量够不够由任务决定**

如果任务是：

```text
下一步语法补全
```

残差流里主要会有局部语法、语义。

如果任务是：

```text
专家在导航中追某个隐藏目标
```

残差流里会被迫编码目标 belief。

如果任务是：

```text
长期关系连续性
```

单轮残差流肯定不够，因为关系状态跨 session。那就必须加：

```text
memory snapshot
user_model snapshot
relationship_state snapshot
temporal controller state
```

所以 Volvence 不能只依赖 LLM 当前 residual stream。我们需要：

```text
residual stream
+ memory state
+ user model
+ relationship state
+ PE history
+ z/beta state
```

一起作为 controller 输入。

**5. 残差流不是记忆库**

这点很重要。

残差流是当前前向传播里的激活：

```text
短暂、即时、上下文相关
```

它不是长期记忆。

所以：

```text
残差流适合读“当前模型如何理解这一段上下文”
不适合单独保存“这个用户长期是谁”
```

长期持续性必须在外部 owner state：

```text
memory
relationship_state
user_model
commitment
```

运行时再把这些状态注入上下文或控制器输入，让残差流在当前 forward 里承载它们的影响。

**6. 为什么论文实验里够**

因为论文任务设计得很清楚：

```text
专家轨迹里当前子目标强烈决定下一步动作
历史动作能透露子目标
任务 horizon 虽长，但子目标结构简单
```

所以模型为了 next-action prediction，会自然学：

```text
当前在 go red / go blue / go green
```

线性 probe 能读出来，控制器能操纵它。

但这不意味着所有现实智能都能只靠一个模型 residual stream 解决。论文证明的是：

```text
在有层级结构的行为序列中，
自回归模型的残差流可以涌现可读可控的时间抽象表征。
```

不是说：

```text
残差流自动包含所有长期事实和关系状态。
```

**7. 对我们架构的结论**

所以你这个问题对 Volvence 的设计约束很关键：

```text
不要把 residual stream 当作唯一状态。
```

应该是：

```text
substrate residual stream:
  当前上下文里的即时 latent representation

persistent organism state:
  用户、关系、记忆、承诺、边界、长期 PE

temporal controller:
  把两者合起来，产生 z_t / beta_t
```

也就是：

```text
z_t = Encoder(residual_sequence, memory_snapshot, user_model, relationship_state, PE_carryover)
```

而不是：

```text
z_t = Encoder(single residual vector only)
```

一句话：

> 自回归模型虽然只预测下一个 token，但当前位置残差流已经是前文上下文的压缩状态，因此能包含预测下一步所需的潜在目标信息；不过单个残差流不保证足够，ETA 用残差流序列发现抽象，Volvence 还必须把持久记忆、用户模型、关系状态和 PE 历史一起纳入控制器输入。

**1. next-token prediction 是否必然产生可用抽象：不必然**

ETA 的前提是：

```text
为了预测下一步，模型会推断长程潜变量。
```

这在论文任务里成立，因为：

```text
当前子目标强决定下一步动作
历史轨迹能透露子目标
子目标结构离散、重复、可组合
```

但在开放语言/关系/真实世界任务里，下一步 token 可能由很多浅层因素解释：

```text
语法惯性
常见表达模板
局部语义搭配
训练分布偏置
```

模型可能预测得很好，却没有形成干净的 `go red / go blue` 式抽象。

所以重大 bug 候选：

> next-token loss 只保证学到对下一步有用的 sufficient statistics，不保证学到对长期控制有用的 causal abstractions。

对 Volvence 的修正：不能假设 residual stream 自然足够。必须用 PE、memory、relationship_state、user_model、closed-loop outcome 来校准抽象是否真的有因果用处。

**2. probe 可读不等于控制因果**

论文做了线性 probe 和 causal intervention，这是优点。但一般化时要小心：

```text
probe 能读出 X
```

不等于：

```text
X 是模型用来产生行为的因果变量
```

ETA 通过 residual controller 证明了一部分 causality，但这仍可能是：

```text
控制器找到了一条能 steering 输出的捷径
而不是原模型原生使用的真正抽象变量
```

这不致命，但会影响 thesis 强度。严苛说：

> ETA 证明了中层 residual 存在可用 steering subspace；不完全证明该 subspace 就是模型自然规划机制本身。

对 Volvence 的要求：我们不能只看 probe accuracy，要看 intervention 后 PE 是否下降、segment credit 是否稳定、跨任务复用是否成立。

**3. 冻结基底的结论可能依赖任务结构**

论文 rate-distortion 分析显示冻结 base model 有利于发现时间抽象。这非常关键。但它可能部分依赖：

```text
先预训练出清晰行为先验
任务子目标结构简单
co-training baseline 优化不稳定
```

也就是说，冻结基底是强工程原则，但作为数学定理还没完全普适。

严苛版本：

> 冻结基底帮助保持抽象坐标系稳定；但“必须冻结”目前是强经验结论，不是所有环境下的绝对定理。

Volvence 可以接受这个，因为我们本来需要稳定性、回滚、用户隔离。即使理论不是绝对，工程上仍成立。

**4. KL 瓶颈会产生抽象，但不保证产生“正确抽象”**

PE/prediction loss 加 KL 会逼迫压缩：

```text
既要预测好
又不能传太多信息
```

这确实会产生抽象。但压缩出来的变量可能是：

```text
最省预测损失的信息
```

不一定是：

```text
对用户、关系、长期成长最正确的本体论
```

例子：

系统可能压缩成：

```text

```

这能预测很多下一轮行为，但可能遮蔽更重要状态：

```text
用户正在测试架构一致性
用户在建立信任边界
用户关心产品可证明性
```

所以重大 bug：

> KL 只给“压缩压力”，不给“语义正当性”。抽象可能有效但错误、粗暴或带偏见。

Volvence 需要 semantic owner 和 typed contract 来约束：`relationship_state`、`boundary_consent`、`commitment` 不能被一个黑箱 `z_t` 吞掉。

**5. beta 分段可能对齐行为边界，但不一定对齐因果边界**

论文里 `beta_t` 对齐子目标切换，很漂亮。但真实交互里边界可能不明显：

```text
用户表面继续问技术
内在其实从理解切到信任测试
一个回答同时服务任务、关系、边界
长期 outcome 延迟很多轮才出现
```

这时 `beta_t` 可能学到：

```text
话题切换边界
语气切换边界
文本结构边界
```

而不是真正的 causal learning boundary。

重大 bug：

> `beta_t` segment closure 简化 delayed credit，但如果 segment 边界错，credit 会系统性错配。

Volvence 的修正：`beta_t` 是 temporal owner 的边界候选，但 credit 还要结合 PE lineage、owner delta、commitment/outcome resolution。不能只靠时间邻近。

内部 RL 高效的前提是：

```text
z_t 空间已经包含可组合、可采样、有意义的抽象动作
```

如果 SSL 发现的 `z` 空间质量差，internal RL 会变成：

```text
在一个漂亮但错误的 latent space 里探索
```

这比 raw action RL 可能更快，也可能更固执地失败。

所以 ETA 的最大杠杆也是最大风险：

> internal RL 不是自动高效；它把问题转移到“抽象发现是否正确”。抽象错了，RL 会在错空间里优化。

Volvence 需要 action-family health、monopoly pressure、held-out composition、PE reduction proof 这些证据门。不能因为 `z_t` 存在就认为它有用。

论文任务是层级导航：

```text

明确成功奖励
专家轨迹
可重复颜色目标
```

Volvence 的目标是：

```text
关系连续性
主体性
用户信任
长期适应
开放文本
多 owner 语义状态
```

这里的 reward/PE 更软、更延迟、更有解释争议。

重大 gap：

> ETA 在 navigation/control 上的证据，不能直接推出在 relational cognition 上也能稳定发现正确 temporal abstractions。

这不是否定 ETA，而是说我们要把它作为 temporal/control kernel，不要让它独占语义解释。关系、承诺、边界必须有自己的 owner。

**8. PE 本身的原始测算是整套系统的真正薄弱点**

你前面问得很对。ETA 论文里主要用 action prediction loss 和 sparse reward。Volvence 要用 PE 作为原始学习信号，就必须回答：

```text
预测了什么？
实际是什么？
距离怎么算？
置信度怎么算？
哪个 owner 解释 actual？
```

如果 PE 算错，后面全错：

```text
PE 错 -> credit 错 -> z 更新错 -> beta 校准错 -> 主动学习错
```

重大 bug：

> ETA 假设有可靠 loss/reward；Volvence thesis 必须额外证明语义 PE 可被 typed、可复现、可回放地测算。

这可能是我们最大的工程/科学风险。

**结论**

严苛审视下，ETA 没有一个“致命推翻”的 bug，但有一个关键边界：

> ETA 证明了：在具有清晰层级结构的行为序列中，冻结自回归模型的残差流可以包含可读、可控、可压缩成时间抽象的 latent control structure，并且在这个结构上做 RL 可以大幅提高稀疏奖励学习效率。

它还没有证明：

```text
所有 next-token 模型都会自然形成通用人类本体论
所有关系/主体性状态都能由 residual z/beta 自动学出
PE/credit 在开放语义环境中天然可靠
```

所以对 Volvence，最稳的 thesis 应该是：

```text
ETA 提供 temporal abstraction 和 latent control kernel；
NL/PE 提供多时间尺度学习信号；
semantic owners 提供语义状态边界；
memory/user/relationship state 提供持续性；
active learning scheduler 在 ETA segment + PE/credit 上路由学习。
```

一句话：**ETA 是核心发动机之一，不是整个生命体。**

**NL 还应该补哪些证据门**

我会追加 4 个 NL gate。

**Gate 5：CMS Multi-timescale Memory Gate**

要证明：

```text
多频率 CMS 记忆塔优于单一 memory store。
```

实验组：

```text
A: no memory
B: flat memory
C: 3-band CMS: online/session/background
D: nested CMS with fast-to-slow meta-init
```

测什么：

```text
short-term adaptation:
  当前 session 内是否快速适应

cross-session retention:
  下次 session 是否保留稳定知识

anti-forgetting:
  新信息是否不破坏旧偏好/事实

context-reset recovery:
  新上下文开始时是否能更快恢复用户模式
```

retain 条件：

```text
CMS / nested CMS 同时提升在线适应和跨 session 保留；
且比 flat memory 更少遗忘/污染。
```

**Gate 6：Nested Meta-init Gate**

这是 NL 很核心的东西：

```text
慢层不是只存档，而是学习如何初始化快层。
```

具体例子：

用户每次讨论数学机制时，都需要：

```text
先定义变量 -> 具体例子 -> 架构映射
```

background-slow 层应该学到这个模式，然后下一次 session 开始时，online-fast 层不用重新摸索。

测什么：

```text
first_turn_adaptation_gain:
  新 session 前几轮是否更快进入正确策略

warm_start_error:
  fast layer 初始状态离后续收敛状态有多近

reset_benefit:
  context reset 后是否比普通 memory 更快恢复
```

retain 条件：

```text
nested meta-init 让新 session 的早期 PE 明显低于 flat carryover。
```

**Gate 7：LSS / PE Grounding Gate**

NL 里很重要的是：

```text
Prediction Error / LSS 是学习原始信号
```

但我们现在讨论的 PE 多是语义 PE。必须证明它和可计算梯度误差信号有桥。

实验：

```text
offline toy predictor:
  predicted y
  actual y
  compute true gradient LSS = dL/doutput

runtime PE:
  predicted - actual

compare:
  PE == -LSS 或同幅同向
```

在更复杂系统中，至少要证明：

```text
semantic PE 的方向能预测后续参数/状态更新是否改善 outcome。
```

retain 条件：

```text
runtime PE 与真实 loss gradient 在可控任务中符号/幅度一致；
语义 PE 在真实任务中能预测后续 improvement。
```

否则 PE 可能只是人工打分，不是学习信号。

**Gate 8：SSL-RL Alternation Gate**

Volvence/NL 不能只有：

```text
SSL 学一次，RL 学一次
```

而应该证明交替有增益：

```text
SSL 压缩经验 -> RL 在压缩空间探索 -> 新经验回流 -> SSL 再压缩
```

实验组：

```text
A: SSL only
B: RL only
C: SSL then RL once
D: alternating SSL-RL over cycles
```

测什么：

```text
new abstraction discovery:
  新 z-family 是否出现

policy improvement:
  RL 是否利用新 abstraction

stability:
  交替是否不破坏旧结构

sample efficiency:
  同等 episode 下是否更快降低 PE
```

retain 条件：

```text
交替循环比单次 SSL/RL 更能发现新抽象并降低 PE。
```

**也就是说，完整 Volvence evidence map 应该是 8 个门**

```text
ETA / PE:
1. ETA segment credit gate
2. Continuity / per-user organism state gate
3. Active learning scheduler gate
4. Rare-heavy artifact gate

NL:
5. CMS multi-timescale memory gate
6. Nested meta-init gate
7. LSS / PE grounding gate
8. SSL-RL alternation gate
```

如果再加关系主体性，可以有 Gate 9：

```text

relationship_state 是否比 task memory 更能预测和改善长期信任/边界/共同语境。
```
