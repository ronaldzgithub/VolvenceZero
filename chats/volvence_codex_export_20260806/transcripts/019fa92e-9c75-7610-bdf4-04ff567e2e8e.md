对于当前 ETA Gate 2 包，我建议采用三级验证：

1. 每轮开发必跑，聚焦根因：

```bash
pytest \
  packages/vz-substrate/tests/test_residual_control_summary_pooling.py \
  packages/vz-temporal/tests/test_counterfactual_action_selector.py \
  packages/vz-temporal/tests/test_residual_control_modes.py \
  packages/vz-temporal/tests/test_temporal_contracts.py \
  packages/vz-runtime/tests/test_eta_residual_causal_controls.py
```

2. 包完成时追加跨 wheel 契约：

```bash
pytest \
  tests/contracts/test_environment_contracts.py \
  tests/test_final_wiring.py
```

由于这次确实修改了 `vz-contracts/environment.py` 和多个公共导出，合并前最好再跑一次：

```bash
pytest tests/contracts
```

3. 真 Qwen / 多候选 counterfactual evidence run 不应当作为普通回归反复跑。只有这些内容改变时才值得重跑：

- residual capture/intervention 机制
- observation-state encoder
- action selector或训练目标
- evidence schema / promotion verdict
- frozen corpus或split

单纯改文档、报告字段、CLI 或非算法性校验时，不值得重跑昂贵实验。

我的结论是：

- **局部 unit + contract 测试很值得**，它们直接保护 residual control、冻结边界、matched-control 和 fail-loudly 契约。
- **开发过程中反复跑全仓测试不值得**，反馈慢，而且大量失败与当前根因无关。
- **合并前跑一次全仓测试有价值，但不是硬性要求**；如果 CI 会跑全量，本地可以只完成相关测试和 `tests/contracts`。
- **反复跑完整 empirical evidence 当前不值得**。v25 已经把失败收敛到 state representation / policy generalization；在 observation-state encoder 没发生实质变化前继续烧相同实验，信息增益很低。

因此我建议把验收口径改成：

> 相关单测全绿 + 受影响契约全绿 + 一次最小真实机制 smoke；全仓回归交给合并前单次执行或 CI。昂贵 evidence run 只在核心实验变量变化时触发。

这既没有降低 Gate 2 的科学标准，也避免把“全仓软件回归”和“昂贵因果证据实验”混成一个测试要求。

所以默认应该是“相关测试”，全量测试只是条件触发。但“需要全量回归时”定义不够明确，Agent 容易保守地把任何多文件改动都判为需要全量，实际会造成大量低价值等待。

我建议把 AGENTS.md 改得更明确：

```md
- 每个收敛包默认只运行：
  - changed paths 的 Ruff；
  - 直接相关的 unit / integration tests；
  - 涉及跨 wheel、共享契约或 import boundary 时追加 `pytest tests/contracts`。
- 禁止仅因“改动文件较多”或“属于收敛包”就默认运行全仓 `pytest`。
- 全仓 `pytest` 仅在以下情况运行：
  - 用户明确要求；
  - 发布、主分支合并或里程碑验收；
  - 修改全局初始化、公共基础设施或无法可靠圈定影响范围；
  - CI 不提供全量回归且本次变更具有广泛运行时影响。
- 昂贵的模型、GPU、外部 API 或 repeated-run evidence 不属于普通全量回归；
  仅在对应算法变量、证据契约或 promotion gate 改变时运行。
- 未运行全量测试时，在交付中如实记录已运行范围与未运行原因。
```

我的判断是：**现有原则不苛刻，但表述确实不够抗误读。**应该明确区分：

- 收敛包验收：相关测试 + 受影响契约；
- 仓库级合并门：必要时一次全量；
- 科学证据运行：独立按实验变量触发。

这样能显著减少 Agent 为求稳反复跑全量测试，同时不降低架构和契约质量。
