# 机制改造战役：Gate 9 / 1 / 6 / 4 / 10 owner 级修复

## 定位

五轮证据战役的结论一致：机制链全部可运行、可审计，但 Gate 1/4/6/7/9/10 的因果增益为零或为负，且历次对账均判定为**机制/实现缺口**而非实验设计问题。本战役不再新增证据程序，而是逐个修复缺口机制本身，然后用**既有 harness + 预注册门槛**重开对应 gate。

排序按「根因清晰度 × 修复成本」：Gate 9（接线 bug 级）→ Gate 1（消费面错位）→ Gate 6（先验结构缺陷）→ Gate 4（目标函数缺陷）→ Gate 10（训练信号错位）。Gate 7 的零增益依赖 Gate 1 的 PE→控制面修复后再评估，本战役不单列包。

## 全局纪律（每包适用）

- 一包一个 owner wheel、一个机制面；机制修改与证据重跑在同一包内但**先冻结验收门槛再跑**。
- 基底层（vz-substrate）与控制器层（vz-temporal / vz-cognition / vz-memory）改动不同包混合——本排序天然满足。
- 每包必须有 kill condition：机制修复后重跑仍不过门 → 该 gate 的失败结论从「实现缺口」升级为「设计层反证」，写入 known-debts 并停止在该 gate 上追加投入。
- 每包验证只跑直接相关测试 + 对应 gate harness，不跑全仓回归。
- 禁止为过门降低既有门槛数值；门槛沿用各 gate 已冻结的判据。

## 包 1：Gate 9 — M3 慢动量接入参数更新（vz-temporal）

**根因**：`M3Optimizer.update()`（[m3_optimizer.py](packages/vz-temporal/src/volvence_zero/temporal/m3_optimizer.py) L102-106）参数更新只用 `fast momentum`；慢动量只在 L111-120 聚合后经 `slow_momentum_signal()` 导出给 CMS，从不进入 `param += lr * fast` 这一步。因此 M3 的优化轨迹与 plain momentum **数值恒等**，四臂 optimizer suite 必然无差。

**机制修改**：让慢动量按 NL Appendix A.6 参与更新——`param += lr * (fast + slow_gain * slow)`，`slow_gain` 为构造参数（默认值预注册，不在线调）。慢动量语义不变（仍每 `slow_interval` 步聚合），`slow_momentum_signal()` 导出路径不动。同步更新 `export_state/restore_state` 的等价性（新增 `slow_gain` 字段）。

**验收（预注册）**：
- 单测：M3 与 plain momentum 轨迹不再逐字节相等；`slow_gain=0` 时退化为原行为（回滚等价性）。
- 重跑 Gate 9 四臂 optimizer suite：M3 臂在非平稳梯度任务上的收敛/终值指标须与 plain momentum 产生可区分且方向正确的差异（沿用该 suite 已冻结的判据）。
- kill condition：接线后 M3 仍无差或更差 → M3 判定为「该任务族下无效的设计模式」，Gate 9 optimizer 分支关闭。

**文件**：`m3_optimizer.py`、`packages/vz-temporal/tests/`（对应测试）、Gate 9 harness 脚本。

## 包 2：Gate 1 — PE 更新接入被消费的控制面（vz-temporal）

**根因**：PE 信号链 `TemporalModule._apply_prediction_error_signal → FullLearnedTemporalPolicy.fit_from_signals → temporal_weights{residual/memory/reflection}`（[interface.py](packages/vz-temporal/src/volvence_zero/temporal/interface.py)）只重写 `temporal_weights`；而 Gate 1 v2 harness 用的 `FullLearnedTemporalPolicy(n_z=4)` 走 `_step_impl_ndim` 推理路径，该路径**不读 temporal_weights**（`runtime_track_modulation=0`），所以 pe-drive on/off 的 next-session controller loss 逐字节相等。参数在改，行为面为空。

**机制修改**（owner 内，二选一在实现时定夺，倾向 a）：
- a. 让 `fit_from_signals` 的 PE 目标强度进入 ndim 路径实际消费的表面——把 temporal_weights 作为 track modulation 输入接进 `_step_impl_ndim` 的 code 合成（相当于把 `runtime_track_modulation` 从常 0 变为 PE 驱动的有界值）。
- b. 若 a 与 ndim 路径既有契约冲突，则让 PE 直接更新 ndim encoder/action head 的有界残差项。

任一方案都必须保持有界、可回滚（更新量 clamp + 可清零）。

**验收（预注册）**：
- 机制单测：PE 注入后，下一 session 的 `controller_state.code` 相对 drive-off 出现非零可测差异；PE=0 时行为与旧版逐字节相等。
- 重跑 Gate 1 v2 harness（升 v3）：`pe-drive-on` 臂的 next-session controller loss 相对 `drive-off` 出现方向正确的增益，沿用该 harness 已冻结的效应门。
- kill condition：接入后 loss 有差但方向为负或不稳定 → 记录为「PE→temporal 的当前信号合成无因果价值」，Gate 1 转入信号设计层重审。

**文件**：`interface.py`（`fit_from_signals` / `_step_impl_ndim`）、`packages/vz-runtime/src/volvence_zero/agent/gate1_pe_causal_v2_retest.py`、对应测试。

## 包 3：Gate 6 — 上下文条件化 meta-init（vz-memory）

**根因**：`CMS._update_nested_meta_targets`（[cms.py](packages/vz-memory/src/volvence_zero/memory/cms.py) L1446-1494）的 meta-init target 是**本频带历史收敛态的 EMA**——近似自复制，无 user/context 条件，因此打不过 copy-init 且跨上下文负迁移。另外 [store.py](packages/vz-memory/src/volvence_zero/memory/store.py) L285-288 的 `slow_to_fast_init_benefit` 定义为 reset 前后 online 向量的 mean|Δ|（位移幅度），不是任务收益，指标本身也是错的。

**机制修改**：
- meta-init target 从「无条件 EMA」改为**上下文条件化**：以 reset 时刻可得的 context 向量（user/context digest，CMS 内已有的表示）为 key，维护少量原型槽（k 个 prototype，EMA 归属最近原型），reset 时按 context 相似度混合原型作为 init target。全部在 CMS owner 内，不引入新模块依赖。
- `slow_to_fast_init_benefit` 重定义为 reset 后若干步的收敛加速量（相对 copy-init 的 loss 差），由 store 自己发布，消费者不重算。
- copy-init 保留为对照臂与回滚路径（`mode="copy-init"` 不动）。

**验收（预注册）**：
- 单测：同 context 重复 reset 收敛到稳定原型；异 context reset 不互相污染；k=1 且忽略 context 时退化为旧 EMA 行为（回滚等价性）。
- 重跑 Gate 6 harness：conditioned meta-init 臂相对 copy-init 的 held-out 收敛增益 ≥ 已冻结最小效应门，且**无负迁移**（任一 context 分组的增益下界不为负）。
- kill condition：条件化后仍输给 copy-init → 结论升级为「该 CMS 表示粒度下 slow→fast meta-init 无收益」，Gate 6 关闭并保留 copy-init 为正式行为。

**文件**：`cms.py`、`store.py`、`packages/vz-memory/tests/`、Gate 6 harness、`docs/DATA_CONTRACT.md`（`slow_to_fast_init_benefit` 语义变更须同步 slot 注册表）。

## 包 4：Gate 4 — 可学习的 segment 获取目标（vz-cognition）

**根因**：`select_active_candidate`（[active_learning.py](packages/vz-cognition/src/volvence_zero/apprenticeship/active_learning.py) L217-241）的 segment-aware 策略只是在 turn-level 分数上追加 `0.15*segment_novelty + 0.10*boundary_strength` 的**硬编码加权特征**；标签获取和训练目标不变，segment 结构不改变样本效率，故 saved-labels = 0。这也正是仓库规则禁止的手写启发式替代应学习能力的形态。

**机制修改**：把选样目标从硬编码加权和改为 **owner 内学习的获取价值估计**：用已标注样本在线拟合一个有界读出（输入 = uncertainty / pe_strength / segment_novelty / boundary_strength / 段级聚合特征，目标 = 该样本标注后对 readout loss 的实际改善，即 label-utility 回归），选样按预测效用排序。segment 的作用从「加分项」变为「效用估计的条件结构」——同一 segment 内已标注样本可抑制冗余标注（段内覆盖度进入特征）。冷启动阶段（拟合样本不足）回退到 uncertainty 排序，回退显式可观察。

**验收（预注册）**：
- 单测：utility 读出随标注积累单调改善其排序质量；段内冗余样本的预测效用低于未覆盖段样本；冷启动回退路径可测。
- 重跑 Gate 4 harness：segment-aware-active 相对 turn-level-active 在同等目标精度下 **saved labels > 0**（沿用已冻结判据）。
- kill condition：学习目标下 segment 条件仍不省标签 → 结论升级为「当前 segment 表示对该 readout 任务族无信息增量」，指向 vz-temporal 的 segment 质量而非获取策略。

**文件**：`active_learning.py`、`packages/vz-cognition/tests/`、`packages/vz-runtime/src/volvence_zero/agent/gate4_active_learning_evidence.py`（特征拼装 `_segment_features` 需同步）。

## 包 5：Gate 10 — candidate 训练对齐 held-out 行为增益（vz-substrate + runtime harness）

**根因**：Gate 10 证据里 candidate 由 `SyntheticOpenWeightResidualRuntime.train_rare_heavy` 在 4 条 cohort 文本上向「residual 整体 +0.012 常数偏移」拟合，held-out 评价却在 2 条不同文本上量接近度——训练目标与评价面错位，Δ=0.012 的信号量级下 held-out 增益实测 -4.88e-6。晋升/回滚闭环全绿但学习本身为空。

**机制修改**（这是基底层包，单独推进）：
- 训练目标从「全局常数 residual 偏移」改为**可迁移的结构性目标**：目标 substrate 差异改为与文本内容相关的可泛化变换（如按 token 统计/位置结构定义的 residual 调制），使 cohort 上学到的 checkpoint 在 held-out 上有非平凡预测内容；训练步数与样本量按信号量级重标（信噪比预算写进包内预注册）。
- 仅改 `train_rare_heavy` 的训练目标构造与 Gate 10 harness 的目标/评价定义（两者必须由同一 spec 定义驱动，消除错位）；晋升闭环、privacy、rollback 机制不动。

**验收（预注册）**：
- 重跑 Gate 10 四臂晋升闭环：candidate held-out gain ≥ 已冻结门槛（原判据 ≥ 0.008 量级，若目标重定义导致量纲变化，先在包内预注册换算后的等效门槛，再跑）。
- full-chain rollback drill 保持通过（回归项）。
- kill condition：目标对齐后 held-out 仍无增益 → 结论升级为「当前合成基底上 rare-heavy 训练无可迁移内容」，Gate 10 学习分支冻结、闭环机制结论保留。

**文件**：`packages/vz-substrate/src/volvence_zero/substrate/residual_backend.py`（`train_rare_heavy`）、`packages/vz-runtime/src/volvence_zero/agent/gate10_rare_heavy_promotion_evidence.py`、对应测试。
