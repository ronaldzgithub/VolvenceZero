- 验收矩阵比普通 PRD 更扎实：E2E、契约、安全、性能、迁移、告警都有初版。

主要缺口在“从 PRD 变成工程任务”这一层：

1. **接口还只是基线，不是冻结契约**  
   OpenAPI/AsyncAPI、字段类型、payload schema、错误码覆盖、分页/排序/筛选、权限失败细节还需要补齐。

2. **AI/烘焙/成熟度的 owner 还不够落地**  
   成熟度 schema、字段权重维护者、证据状态流、冲突解决、brain snapshot 的生成/校验/回滚，需要进一步定义到可实现级别。

3. **企微托管是最大外部风险**  
   文档已经标了合规风险，但这是上线前的硬阻塞项：到底用什么官方能力、授权如何撤销、封号/限流/消息失败如何兜底，必须在接口冻结前确认。

4. **安全与隐私还需要威胁模型**  
   已写了原则，但还缺更具体的攻击面：提示注入、工具参数注入、跨租户 IDOR、客户画像泄漏、材料解析恶意文件、支付链接滥用等的防护设计。

5. **和现有 Volvence 内核契约还需要映射**  
   PRD 里的 `EMO GPT`、`brain_snapshot_locator`、模板、证据、画像、工具调用，需要映射到仓库现有 wheel / owner / snapshot / `ModificationGate` 边界，否则容易做成平台侧平行实现。

6. **前端还缺细粒度交互状态**  
   页面级功能有了，但 loading、empty、error、权限不足、状态冲突、重复提交、离线、烘焙失败重试等具体 UX 还要补。

如实说，只看这场会议：赵江波属于“产品直觉很强、产品纪律偏弱”的创始人型产品思考者。

他绝不是没产品能力，甚至在愿景、商业闭环和平台化方面明显高于普通产品经理；但如果缺少一个能够约束范围、验证假设、把控风险的人，他很容易把团队带进“方向很兴奋，执行不断膨胀”的状态。

**他真正强的地方**

- 能抓住规模化的核心矛盾：不能让数字分身的训练永远依赖少数员工手工服务，必须把线下调教变成用户自助完成的线上产品。这是整场会议最有价值的判断。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:107)

- 有完整的产品闭环意识。他不是只想做一个聊天机器人，而是在串联“创建、调教、成熟度、发布、托管、收费、领养、再训练、再次上架和分成”。这属于平台产品思维。

- 商业嗅觉很好。把收费放在微信对话的自然节点，而不是让用户跳网站，方向上是对的。他能意识到交易必须嵌入用户行为，而不能脱离场景。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:295)

- 系统抽象能力不错。他能够区分“脑子、平台能力、终端表达”，也能想到多模态能力应沉淀在平台层供多个应用复用，还提到工具、租户、版本、认知快照、集群定位。这不是纯市场型老板常有的能力。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:623)

- 能看到网络效应。Character Store、创作者分成、模板衍生关系，本质上是在把一次性交付升级为供给市场。这条远期方向有想象力。

**他最明显的问题**

第一，缺少从客户证据出发的聚焦。

会议里目标客户从医生迅速扩张到销售、个人分身、神婆、情感陪伴、游戏角色和任意 UGC。这里有市场想象力，但没有明确回答：第一个真正高频、刚需、愿意稳定付费，而且合规可交付的客户是谁。

他经常把三件事连成一步：

> 技术上可能实现 → 用户一定需要 → 能形成大规模生意。

这三步实际上都需要单独验证。关于“几百万用户必然有商机”的推演，更像规模想象，不是市场证据。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:221)

这会造成一种典型后果：口头上是 MVP，实际上团队同时背负平台、工具市场、多模态、支付、租户、托管、UGC 和分成体系。

第三，严重低估工程化成本。

他相信基于三个代码仓库，让 AI 生成接口和七成代码，再由其他人联调，很有时代感；“先冻结接口再编码”也是正确判断。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:927)

但他低估了真正费时间的部分：语义歧义、权限、数据隔离、失败恢复、渠道协议、模型效果评估、线上观测和合规。AI 可以显著降低编码成本，却不能自动消除产品定义和系统所有权的歧义。“基本没有缺口”这个判断明显过于乐观。[逐字稿](/Users/mengfu/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files/q1369465376_f8e2/temp/drag/20260729175501-转写_wing预定的会议-逐字稿文本-1.txt:883)
