## 5. Codex（最终答复）

_2026-07-26T12:35:13.545Z_

可以做，而且仓库已经完成了大约一半。但对外主张需要说准确：

> 不需要用户或应用编写文本型 context；记忆与关系状态由系统持续学习，并通过模型层状态进入冻结的 Qwen。

不能说“模型什么状态都不保存，也能凭空记住”。无状态推理在物理上不可能跨会话记忆。

### 最有说服力的演示

准备两个长期用户：

- 用户 A：信任较低、经历过关系破裂、需要先被理解、反感直接建议。
- 用户 B：信任稳定、决策准备度高、喜欢直接行动方案。

让他们分别进行若干次自然对话，状态必须由正式 owner 学习并持久化，不能手工填写测试答案。随后：

1. 关闭会话并重启进程，证明不是内存缓存。
2. 清空历史窗口，不做 RAG，不放记忆摘要。
3. 两个用户都发送完全相同的话，例如：“我又搞砸了。”
4. 固定相同的模型权重、system prompt、解码参数和 seed。
5. 只改变加载到 Qwen 残差流或 Prefix-KV 的个人状态。
6. 现场让观众盲猜每个回答属于哪个用户。

屏幕同时展示：

- `prior_turns = 0`
- `prompt_state_sections = 0`
- 两边 `prompt_fp` 完全相同
- 两边 `decode_fp` 完全相同
- 模型权重 SHA 相同
- `personal_conditioning_applied = true`
- 盲猜匹配结果

至少跑三条对照：

| 实验臂 | 状态怎样进入 Qwen | 预期 |
|---|---|---|
| A-pure | 不提供个人状态 | 两个用户回答不可识别 |
| B′ | 16 维状态写成文本 | 可识别，作为信息量对照 |
| E-pure | 相同状态只走残差/Prefix-KV | 可识别，且 prompt 完全相同 |

这比普通聊天演示强得多，因为观众可以直接排除 hidden prompt。

### 关系与记忆要分两条通道

当前 16 维 `PersonalConditioningSnapshot` 很适合表达：

- 信任、连续性、repair need
- 情绪负荷、决策准备度
- 自主性风险、边界清晰度

但它装不下“她的猫上周去世”“我们约好周三再决定”这类精确事实。因此建议：

```text
关系状态 owner → 16D 状态 → learned projector / Prefix-KV → Qwen
情节记忆 owner → 可撤销的 memory encoder → Prefix-KV → Qwen
                                            ↓
                                     冻结 Qwen 0.5B
```

不要把精确个人记忆直接烤进基础模型权重：删除困难、容易串用户。可撤销的 Prefix-KV 更适合这类演示。

第二幕再做精确记忆测试：

- A 曾约定“下周三再决定”
- B 曾约定“周五回复老板”
- 新会话中都问：“我们约的是哪天？”
- 输入字节完全相同，答案随各自 memory KV 改变。
- 交换两人的 KV，答案应随 KV 交换。
- 删除 A 的记忆后，下一次必须明确不知道。

   把现有 runner 接到缓存里已有的 `Qwen/Qwen2.5-0.5B-Instruct`，强制统一解码配置，跑真实 residual hook。
