## 1. 准备通用训练数据

当前入口只接受严格 JSONL，每行只能有 `trace_id` 和 `source_text`：

```json
{"trace_id":"common-000001","source_text":"用户：我现在很乱，不知道该先做什么。\\n助手：我们先把事情分成紧急、重要和可以延后的三类……"}
{"trace_id":"common-000002","source_text":"用户：他打破了承诺，我不知道是否还该信任他。\\n助手：先区分事实、影响和修复条件，再决定是否恢复信任……"}
```

建议拆成：

- `train.jsonl`：跨角色通用对话、关系修复、状态跟随、边界、安全、规划等。
- `heldout.jsonl`：永远不进入训练，只用于 Gate。
- 单一角色的姓名、口癖、故事身份不要大量进入 L1；这些应留给 L2 角色包。
- 当前训练器最大截断长度是 128 tokens，长对话应切成独立训练片段。

`--max-steps` 是优化步数，不是 epoch。若有 `N` 条训练记录，第一轮可以从 `2N` 左右开始，再由 held-out 结果选择，不能只看训练 loss。

## 2. 生成匹配 1.5B 的 control basis

仓库现有 control basis 是 0.5B、hidden size 896，不能用于 1.5B。先生成 1.5B 候选：

```bash
python scripts/run_state_kv_control_dim_diagnostic.py \
  --model-id Qwen/Qwen2.5-1.5B-Instruct \
  --model-source .local/hf-cache/hub/models--Qwen--Qwen2.5-1.5B-Instruct/snapshots/989aa7980e4cf806f80c7fef2b1adb7bc71aa306 \
  --device cuda \
  --full-rank 16 \
  --candidate-artifact-output artifacts/common-adapters/qwen2.5-1.5b/v1/control-basis.json \
  --observation-output artifacts/common-adapters/qwen2.5-1.5b/v1/control-basis-observations.json \
  --output artifacts/common-adapters/qwen2.5-1.5b/v1/control-basis-verdict.json
```

当前这台机器检测不到 CUDA 或 MPS，只能使用 `--device cpu`，1.5B 完整训练会很慢。建议在 CUDA 机器正式训练；本机先用 0.5B 做 smoke。

## 4. held-out 评测与发布

不能直接把训练结果设为 ACTIVE。必须比较 base 与 candidate 的 held-out 表现，并由 cognition-owned ModificationGate 产生：

```text
common-adapter-gate-record.v1
```

然后发布：

```bash
python scripts/train_common_adapter_model.py publish \
  --candidate artifacts/common-adapters/qwen2.5-1.5b/v1/common-adapter-candidate.json \
  --gate-record artifacts/common-adapters/qwen2.5-1.5b/v1/common-adapter-gate-record.json \
  --output artifacts/common-adapters/qwen2.5-1.5b/common-adapter-bundle.json
```

这里有一个尚未自动化的环节：仓库目前没有把“candidate held-out 对照评测”直接转换成 `CommonAdapterGateRecord` 的端到端 CLI。因此现在可以完整训练出 candidate，但正式 ACTIVE 前仍需补齐评测→Gate 的自动化适配；不应该手写一个 `allow` 记录绕过它。

## 建议的实际下一步

先不要投入 1.5B 正式算力。最稳妥的顺序是：

1. 补齐 L1 candidate 的 held-out 对照评测与 Gate 生成 CLI。
2. 补齐 L2 角色 fidelity 与 Gate 生成 CLI。
3. 用 0.5B、少量数据、`max_steps=2` 做全链 smoke。
4. 再迁移到 CUDA 机器训练 1.5B。
5. SHADOW 观察通过后才切 ACTIVE。

也就是说，训练器已经能工作，但从“训练结果”到“可信 ACTIVE 制品”的最后两段评测自动化仍应先补齐。

### 建议数据量

当前仓库只有：

- 2 条 smoke train
- 2 条 smoke held-out

它们只验证链路，不能证明模型质量，[smoke 说明](/Users/mengfu/Documents/GitHub/volvence/docs/common-adapter-character-training.md:320)。

建议分三档：

| 阶段 | 训练数据 | 冻结 held-out | 用途 |
|---|---:|---:|---|
| 连通性 smoke | 2–10 条 | 2–10 条 | 验证训练、序列化、三臂、Gate |
| 第一轮有效实验 | 500–1,000 条 | 200–300 条 | 判断 adapter 是否存在稳定正向信号 |
| 正式晋升候选 | 5,000–20,000 条 | 1,000–2,000 条 | 做能力分层、负控、3 seeds 和回归统计 |

当前每条最多截断到 128 tokens，[数据约束](/Users/mengfu/Documents/GitHub/volvence/docs/common-adapter-character-training.md:65)。按平均80–120 tokens估算：

- 500条：约4万–6万 tokens
- 5,000条：约40万–60万 tokens
- 20,000条：约160万–240万 tokens

我建议第一枪先做：

- **1,000条高质量训练 trace**
- **300条完全冻结 held-out**
- 覆盖关系、边界、安全、状态跟随、计划五个 cohort
- improve/preserve 大致各半
- 至少100条有明确 counterfactual state
- 先跑1个 seed；出现正信号后再扩到5,000条、3个 seeds

代码虽然允许 held-out 最少8条，但那只是契约下限，不是统计可信的测试规模，[Gate 默认值](/Users/mengfu/Documents/GitHub/volvence/scripts/train_common_adapter_model.py:1170)。

## 104. Codex（最终答复）

_2026-08-04T00:45:43.713Z_

会。按当前格式“原样公布”存在明确泄密风险，不建议直接上传 `artifacts/`、Common Adapter bundle 或角色包。

风险大致如下：

| 公布方式 | 风险 |
|---|---|
| 只提供受控 API | 中低，可限流、审计和撤回 |
| 经过脱敏的 Adapter 权重 | 中等，仍有训练数据反推风险 |
| 当前 bundle/角色包原样公开 | 高，包含路径、指纹和内部训练信息 |
| 整个训练 run 目录公开 | 极高，会直接暴露训练/held-out 文本和角色材料 |

目前已经确认的直接问题：

- 最终 Common Adapter 不直接包含 `train.jsonl` 原文，但会内嵌 rare-heavy、State-KV、control basis、Gate 和描述字段，[序列化位置](/Users/mengfu/Documents/GitHub/volvence/packages/vz-substrate/src/volvence_zero/substrate/common_adapter_bundle.py:304)。
- rare-heavy 描述会写入训练模型来源 `{source}`；本地训练时可能是绝对路径，[代码位置](/Users/mengfu/Documents/GitHub/volvence/packages/vz-substrate/src/volvence_zero/substrate/rare_heavy_training.py:313)。
- 当前张无忌 Prefix artifact 已直接包含本机路径 `/Users/mengfu/Documents/...`，[实际文件](/Users/mengfu/Documents/GitHub/volvence/artifacts/character-packages/zhang_wuji/zhang-wuji-qwen2.5-1.5b.character-prefix.json:9)。
- 角色包还公开人物名称、训练模型、案例数、epochs、slots、template/proof 指纹等内部 provenance。
- `train.jsonl` 和角色 reviewed ledger 如果一起发布，会直接暴露完整训练文本。
- 即使删除所有文本，Adapter 浮点权重仍可能通过记忆提取、membership inference 或重复提示暴露训练数据。我们没有使用差分隐私，因此不能宣称“权重一定不泄密”。

建议采用“两层发布”：

公开层只包含：

- 脱敏后的数值权重；
- base model ID、必要 geometry、版本和兼容字段；
- 相对文件名，不含本机路径；
- 聚合评测指标、许可证、模型卡和已知风险。

私有证据库保留：

- `train.jsonl`、`held-out.jsonl`；
- reviewed ledger、bake proof、原始 fidelity cases；
- case-level evaluation report；
- 本机路径、git dirty 状态、内部环境和完整 Gate provenance。

正式公开前至少需要：

1. 对训练数据和所有产物扫描 API key、token、邮箱、电话、身份证、内部域名及绝对路径。
2. 做训练语句精确提取、canary extraction 和 membership-inference 测试。
3. 检查 base model、角色原著和训练材料的授权范围。
4. 生成新的、字段白名单式 `PublicReleaseBundle`，不要在现有 bundle 上直接删字段——直接修改会破坏 bundle ID、SHA-256 和 Gate 绑定。
5. 风险未完全验证前优先只开放 API；公开权重下载后基本不可撤回。

结论是：基础模型本身不是主要机密，真正危险的是训练数据、角色材料、内部 provenance，以及权重对这些数据的潜在记忆。当前产物还没有达到可安全公开的状态。
