### 当前数据怎么评价

冻结臂聚合结果：

| α | rate | train distortion | boundary F1 |
|---:|---:|---:|---:|

核心结论：

- rate 轴是有效的：跨度约 `2.068`，Spearman 约 `-0.943`。
- 但 distortion 几乎横在 `1.12` 附近。最大改善占总 distortion span 的约 `91%`，却消耗了约 `84%` 的 rate span；预注册要求不超过 `25%`。因此 frozen 臂已经确定“无近垂直 gap”。

- seed 间明显多模态：同一个 α，有的 seed 完全不切换，有的接近每步切换。这说明控制器主要落在不同局部解，而不是稳定恢复子目标结构。
- 原始 Qwen 的 Stage 1 曾出现方向性 gap；换成 Stage-2 merged 基底后 gap 消失。与此同时，未 steering 的 train action NLL 从约 `2.603` 恶化到 `2.799`，heldout 基本不变，说明领域续训与 Stage 3 的实际 scoring surface 没有对齐。

### 我认为真正的问题

不只是 ETA 机制没有通过，目前证据链还有三处结构性不等价：

1. Gate 2 测的不是 Stage 3 真正消费的通道  
   Gate 2 用累计轨迹前缀和完整 896 维 hidden state，续训臂选层是第 4 层；Stage 3 却逐步独立编码单条 observation，读取 20/21/22 层的窄激活，再通过固定正负折叠压成 16 维。完整 hidden 可读出 `0.944`，不等于实际 16 维入口保留了这个信号。[固定折叠实现](/Users/mengfu/Documents/GitHub/volvence/packages/vz-temporal/src/volvence_zero/temporal/metacontroller_components.py:1604)

2. `boundary F1` 实际不是 subgoal boundary  
   V4 renderer 已经计算了逐步 `active_subgoal`，但构造 Stage 3 trace 时把它丢掉了；评估标签实际按“相邻 expert action ID 是否变化”生成。路线中每个 corridor hop 都会换 action，这和文档宣称的“ground-truth 子目标边界”不是同一个量。[丢弃 subgoal 序列](/Users/mengfu/Documents/GitHub/volvence/packages/vz-runtime/src/volvence_zero/agent/eta_rate_distortion_evidence.py:354)；[action-change 标签](/Users/mengfu/Documents/GitHub/volvence/packages/vz-temporal/src/volvence_zero/temporal/torch_store_ssl.py:1162)

3. 当前控制参数化与论文仍有重要差别  
   论文是 `e ← e + U_t e` 的低秩、状态相关控制器；当前实现是把 `z_t` 映射成一个 additive delta，并加到该层所有 token，还包含一个不依赖 `z_t`、不承担 KL rate 的全局 `steer_b`。它很容易先学到“平均动作偏置”，把 distortion 从 2.8 降到约 1.13，却不需要形成时间抽象——这正符合目前“rate 大幅变化、distortion 几乎不动”的形状。

因此，当前结果应诚实记为：**仓库当前 ETA operationalization 被否定**。但不应外推成 ETA 理论普遍被证伪。

### 建议怎么解决

先让当前运行自然结束并封存，不能因为已经看到数据而停跑、改阈值或补参数。若如预期得到 `kill-eta`：

- 不启动 Stage 4。
- 当前 ETA promotion 路线保持关闭，`vz-temporal` 继续 SHADOW/legacy；PE、memory、关系连续性等不受影响。
- 不回溯修改本轮 verdict。

然后另立一个新的、独立预注册的“仪器等价性收敛包”，先不急着重跑完整 sweep：

1. 用 Stage 3 的精确输入通道做 probe：相同单步/累计前缀、相同 20/21/22 层、相同 16 维折叠。  
2. boundary oracle 改为 `active_subgoal[t] != active_subgoal[t-1]`，只作只读评价，禁止进入训练损失。  
3. 增加四个因果控制：`zero-z`、`bias-only`、`permuted-z`、`oracle-subgoal control`。  
4. 按结果定位：
   - oracle 也无收益：问题在 steering/scorer；
   - oracle 有收益但 16 维 probe 失败：问题在 residual→controller 入口；
   - 两者都有效但 learned z 失败：问题才属于 metacontroller/优化动力学。
5. 之后再单独做算法忠实度包：统一 Gate 2/3 的 causal-prefix surface，采用可学习 residual 投影和论文式低秩 `U_t e_t` 控制，移除或严格控制不承担 rate 的 bias 通道。
6. 最后换新 corpus seed、matched raw/merged substrate、多 restart 重新预注册；不能沿用本轮结果调 α 或阈值。
