## 4. Codex（最终答复）

_2026-07-24T11:08:06.865Z_

会，而且这是目前最强的 counter argument 之一。更准确地说：**我们现在还没有用真实证据反驳它。**

它可以被严格表述为：

> 同一个冻结 LLM，只要获得足够清晰的语言 context，就已经在 hidden state 中完成了情境理解、人物建模和策略抽象。Volvence 的 semantic owners、`z_t` 和 memory 只是把这些已有抽象重新结构化，并没有创造独立能力。

如果成立，我们就不是“新的认知/学习架构”，而主要是一个 context compiler、memory wrapper 和 control scaffold。

### 它真正击中的地方

这个反驳对“语义表征”打击很大。因为当前 9 类 semantic owner 的 proposal，在真实 HF 部署里主要还是由 LLM 产生。仓库自己的 spec 已经明确承认这一点，而且真实 HF trace 的依赖消融尚未完成：[semantic-grounding-evidence.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/semantic-grounding-evidence.md:9>)。

因此目前最诚实的口径不是：

> 系统独立涌现了人类语义抽象。

而是：

> LLM 提供语义感知，系统把感知结果变成有 owner、生命周期、因果链和更新边界的持久状态。

后者仍然有价值，但 claim 小得多。

### 但“LLM 理解了抽象”不等于“系统问题已经解决”

这里要区分三件事：

| 层次 | 语言 context 可能已经解决 | Volvence 必须额外证明 |
|---|---|---|
| 理解 | 当前是什么情境、用户想什么 | 未必有独立增益 |
| 状态 | 承诺、关系、open loop 是否跨轮持续且可冲突更新 | 不靠每轮重新让 LLM猜 |
| 控制与学习 | 下一步怎么做 | delayed outcome 能否真正更新策略，并在新情境迁移 |

语言 context 很擅长让 LLM“此刻重新推断”。但它不自动保证：

- 跨 session 状态持续、冲突处理与 provenance；
- 哪个过去动作应为延迟结果负责；
- 系统在新反馈后发生了可验证的参数或策略更新；
- 可以干预某个内部抽象并产生可预测的行为变化；
- 在没有语言解释答案时仍能适应；
- 同一学习机制可以迁移到非语言环境。

所以我们的护城河不应该是“LLM 没有抽象能力”。那几乎肯定站不住。真正应该验证的是：

> LLM 有丰富的 latent prior；Volvence 是否能把它变成比语言 context 更持久、更可控、更可学习、更省样本、更可审计的行为系统。

### 什么实验才能真正回答

最关键的不是证明 `z_t` 和某些语义标签相关，而是证明它有**独立因果价值**：

1. **最强语言基线**

   同一冻结模型对比：

   - 全量长 context；
   - 高质量结构化 summary；
   - memory-only；
   - RAG；
   - 标准 agent framework；
   - Volvence；
   - Volvence ETA-off。

   不能拿一个弱 prompt baseline 来赢。仓库已经设计了这些 matched arms，但目前仍然只是 `wiring-ready`，真实 P1/P2 verdict 未跑：[human-world-model-ablation.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/human-world-model-ablation.md:29>)。

2. **`z_t` 因果干预**

   保持 transcript、context 和 LLM 完全不变，只做：

   - swap 两个 action family；
   - clamp / randomize `z_t`；
   - 延迟或打乱 `β_t` switch；
   - ETA-off。

   如果行为没有稳定、方向明确的变化，`z_t` 很可能只是 telemetry。如果 `z_t` 总在语义变化之后才变化，它也只是对 LLM 语义的事后复述。现有 grounding spec 已经把“领先而非滞后”列为 kill 条件：[semantic-grounding-evidence.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/semantic-grounding-evidence.md:40>)。

3. **不给语言答案的在线适应**

   环境发生隐藏变化，但 transcript 不描述变化规律。比较 learned、no-optimize、PE-off 和 context-only。

   只有系统根据 outcome 改善，语言 baseline 无法靠重读 context 获得答案时，才能说明 prediction error、credit 和 controller learning 真有贡献。

4. **LLM proposal 消融与换模**

   - proposal-on vs proposal-off；
   - 再加 proposal-provider swap；
   - 同 substrate、同轨迹、同 seed。

   如果 off 后语义状态塌缩，必须把 claim 降级成 **LLM-assisted typed semantic tracking**。仓库已经明确冻结了这个解释规则：[semantic-grounding-evidence.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/semantic-grounding-evidence.md:110>)。

5. **非语言迁移**

   Digital Ant 的意义正是在没有 LLM、token 和语言 context 的情况下复用同一控制/学习内核：[digital-ant-embodiment.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/digital-ant-embodiment.md:7>)。

   如果它通过严格 matched controls，能证明这套学习机制不是语言表征的副产品。但当前相关正式 evidence 仍有 rerun/block 状态，所以也不能提前引用为反驳。

### 我的判断

这个 counter argument **不会自动否定整个架构，但会否定我们最容易讲大的那种叙事**。

我们现在应该主动收缩 thesis：

> 不是声称“我们创造了 LLM 没有的人类抽象”，而是检验“显式、持久、可干预、可信用分配的 latent control，是否比让 LLM 每轮从语言 context 重新推断更有效”。

最终判决应当很硬：

- 如果强语言基线追平 Volvence，而且 `z_t` 干预没有独立因果效应：接受反驳，系统应收缩为 memory/companion infrastructure。
- 如果主要收益来自状态持久化和审计，而不是新抽象：保留产品价值，放弃“新认知架构”主张。
- 如果 ETA-off、no-optimize、proposal-off 和非语言实验都形成稳定因果差：才有资格说语言 LLM 不是整个能力的唯一来源。

所以答案是：**对，这是一个很大的反驳；而且它其实给出了我们最重要、也最诚实的实验路线。**

而你问的“这个模型是什么”，其实暴露了一个必须讲清楚的问题：**Volvence 当前不是在在线训练一个完整 LLM，而是在训练冻结 LLM 上方的个体化控制器与记忆模型。**

## 精确一点的定义

可以把系统写成：

\[
\text{IndividualAdaptiveModel}_i = (\phi_i,\ \psi_i,\ S_i,\ A_i)
\]

其中：

| 部分 | 是什么 | 是否在线学习 |
|---|---|---|
| \(\theta\) | 共享冻结 LLM substrate | 默认不在线更新 |
| \(\phi_i\) | 个体 \(i\) 的 metacontroller / causal `z_t` policy / `β_t` switch / decoder | 核心 online-fast 学习对象 |
| \(\psi_i\) | 个体的 CMS 多时间尺度记忆参数 | online/session/background 更新 |
| \(S_i\) | commitment、relationship、user model 等结构化状态 | 状态更新，但不一定是神经网络训练 |
| \(A_i\) | 可选 LoRA / adapter delta | rare-heavy 离线训练，经门控后部署 |

所以最核心的“模型”应该是：

\[
\pi_{\phi_i}(z_t \mid e_{1:t}, m_t, S_t)
\]

也就是：**给定 LLM residual 表征、记忆和结构化状态，选择当前潜在行为策略 `z_t` 的个体化策略模型。**

LLM 不是被学习的主体，而更像：

- 预训练世界知识；
- 语言理解器；
- 行为生成器；
- 被 controller 控制的稳定环境。

当前设计也是这样分层的：在线更新 controller，LLM live 默认冻结；基底 adapter 只走 rare-heavy 路径。[multi-timescale-learning.md](</Users/mengfu/Documents/GitHub/volvence/docs/specs/multi-timescale-learning.md:40>)

## 一次学习循环到底发生什么

理想的运行循环应当是：

\[
e_t = F_\theta(x_t,\ context_t)
\]

冻结 LLM 把输入编码成 residual state：

\[
z_t,\beta_t = C_{\phi_i}(e_{1:t},m_t,S_t)
\]

个体 controller 选择当前抽象行为：

\[
r_t = F_\theta(x_t;\ D_{\phi_i}(z_t))
\]

系统执行行为，看到真实结果 \(o_{t+1}\)，计算：

\[
\delta_t = \text{PredictionError}(\hat{o}_{t+1},o_{t+1})
\]

然后更新：

\[
\phi_i \leftarrow \text{Update}(\phi_i,\delta_t,\text{credit})
\]

\[
\psi_i \leftarrow \text{MemoryUpdate}(\psi_i,\text{experience})
\]

关键变化发生在 \(\phi_i,\psi_i\)，不是每次都修改巨大 LLM 的 \(\theta\)。

## 为什么这和“把经历写进 context”不同

两者最本质的区别是：

### Context learning

```text
旧模型 + 更多文字 → 这一轮表现不同
```

删除文字、开启新 context，能力可能消失。变化发生在输入，不在模型。

### Continual learning

```text
同一个输入 + 已更新的参数/记忆状态 → 未来表现不同
```

即使：

- 清空 transcript；
- 不提供上次经历的语言总结；
- 换一种表述；
- 进入新的 held-out 场景；

行为变化仍然保留。

所以判断系统有没有持续学习，不能看“它记不记得”，而要看：

> 在控制当前 context 完全一致的情况下，训练前后的 checkpoint 是否产生稳定、可迁移、可归因的行为差异。

## “在线训练 LLM”反而不是核心

我认为不应该把产品命题定义为“在线训练整个语言模型”。

因为这样会带来：

- 单次错误反馈污染全模型；
- 灾难性遗忘；
- 用户之间相互污染；
- prompt injection 变成参数投毒；
- 延迟结果难以分配到亿万参数；
- 更新成本和回滚成本极高。

更合理的是：

```text
共享冻结基底 θ
        │
        ├── 用户 A：controller φ_A + memory ψ_A
        ├── 用户 B：controller φ_B + memory ψ_B
        └── 用户 C：controller φ_C + memory ψ_C
```

每个生命体/关系实例拥有自己的可学习状态。经过大量验证的共性能力，才可能在 rare-heavy 阶段蒸馏为 adapter 或下一版基底。

## 但这里有一个真实的架构风险

目前系统包含很多“会变化的东西”：

- semantic snapshot；
- memory entries；
- controller priors；
- action families；
- CMS 参数；
- `z_t` policy；
- adapter delta。

如果我们说不清：

1. 哪组参数被训练；
2. loss 或更新信号是什么；
3. 更新属于哪个个体；
4. checkpoint 在哪里；
5. context reset 后是否保留；
6. 参数变化是否因果导致行为变化；

那“持续学习”就可能只是多个状态机和 memory write 的总称，不是一个真正的学习模型。

因此技术上最好把核心对象正式命名为：

> **Individual Adaptive Controller，个体自适应控制模型**

而不是笼统叫“新的 LLM”或“人类世界模型”。

它的最小参数面就是：

\[
M_i = \{\text{metacontroller encoder},\ \beta\text{ switch},\ z\text{-policy},\ decoder,\ CMS\}
\]

语义 owner 是它的可观察认知状态；LLM 是感知与生成 substrate；PE/credit 是学习信号。

## 最硬的持续学习验收标准

真正证明“模型学了”，至少需要以下实验：

1. 从同一个 checkpoint 分叉 learned / no-optimize。
2. 两臂经历完全相同的输入、context 和 outcome。
3. learned 臂允许更新 \(\phi,\psi\)，no-optimize 禁止更新。
4. 训练后清空 transcript，冻结所有学习。
5. 在 paraphrase 和 held-out 场景测试。
6. 验证 learned 显著优于 no-optimize。
7. controller/memory fingerprint 确实变化，LLM fingerprint 不变。
8. 恢复旧 checkpoint 后增益消失。
9. 重新应用新 checkpoint 后增益恢复。

最后两条特别重要：它们证明行为改善来自模型参数，而不是缓存、随机性或 context 泄漏。

所以我会把 Volvence 的核心命题收敛成一句话：

> **不是在线训练一个更会说话的 LLM，而是在冻结语言基底上，持续训练一个属于具体生命体的、可回滚的长期行为策略与记忆模型。**

如果这个个体模型在 context reset 后仍不能表现出可迁移的行为变化，那么不管内部有多少 owner、snapshot、PE 和 `z_t`，都还不能称为真正的持续学习。

更准确的表述是：

> 如果有足够的算力、可靠奖励和大量可重复经验，当然可以直接在 token policy 上做 RL。  
> 但如果要在真实交互中，用稀疏、延迟、不可重复的反馈进行安全的在线参数更新，就需要一个比 token 序列更低维、更持久、更可归因的控制空间。Volvence 选择让这个空间由 `z_t / β_t` 涌现出来。

### 为什么不只是算力问题

Token-space RL 在数学上完全可行：

\[
\pi_\theta(y_1,\dots,y_T\mid x)
\]

拿最终奖励直接更新 token policy 参数 \(\theta\)。只要：

- 有大量 rollout；
- 奖励足够可靠；
- 可以反复试错；
- 能承受训练成本；
- 能处理 reward hacking 和遗忘；

确实可以学。

但真实在线交互的问题是：**数据和反馈比算力更稀缺。**

用户的一次失望、一次关系破裂、一个几天后才显现的结果，通常无法重复采样一万次。即使算力无限，也不能凭空获得真实反事实：

> 如果当时换一种策略，用户会不会更信任系统？

所以 token-space RL 的困难主要是：

- 一个长期结果要分配给数百上千个 token；
- 每个 token 都是巨大动作空间中的一次选择；
- 同样语义有无数种语言实现；
- 更新整个生成模型容易污染无关能力；
- 每个用户只有少量真实轨迹；
- 在线探索本身可能伤害用户。

### 抽象空间解决的是什么

我们希望把：

```text
几百个 token：
“先承认误解 → 澄清边界 → 给出修复方案 → 暂时不追问”
```

压缩成一个持续若干轮的抽象动作：

```text
z_t = repair-and-rebuild-trust
```

这样长期结果可以归因给一个 option/segment，而不是归因给每个具体措辞。

形式上是：

\[
z_k \sim \pi_\phi(z_k\mid e_{1:t},m_t)
\]

\[
y_{t:t+n} \sim \text{LLM}_\theta(\cdot\mid z_k)
\]

其中：

- \(\theta\)：冻结的 LLM，负责理解和表达；
- \(\phi\)：在线学习的抽象策略；
- `z_k`：持续多个 token 或多个 turn 的抽象行动；
- `β_t`：决定何时继续、何时切换抽象行动。

最终反馈主要更新 \(\phi\)，而不是直接更新所有 \(\theta\)。

### 但“必须在涌现抽象上学习”仍然太强

严格来说，在线学习并不必然要求“涌现”抽象。还可以使用：

- 人工定义的 action/options；
- 固定技能库；
- 工具调用动作；
- LoRA/adapters；
- 外部记忆和检索策略；
- 少量预定义行为模式。

真正接近“必须”的是：

> 长程、稀疏反馈的在线学习，需要某种时间压缩和信用分配单位。

这个单位可以是人工定义的，也可以是学习出来的。

Volvence 更强的 thesis 是：

> 行为世界不断变化，预定义 option 不可能覆盖所有关系和情境，因此控制抽象本身也应该从经历中发现、分裂、合并和复用。

所以这里有两级 claim：

1. **低维时间抽象有用**：`z_t` 学习优于 token-space online RL 和无 ETA 基线。
2. **涌现抽象有用**：learned family 优于固定、人工定义的 action family。

第二条需要单独实验，不能由第一条自动推出。

### 我建议最终这样表达

> Token-space RL 在充足算力、数据和可靠奖励下当然可行，但它更适合大规模离线训练。真实持续交互中的瓶颈不是单纯算力，而是稀疏经验、延迟信用、安全探索和参数污染。要进行有界、个体化的在线学习，系统需要一个低维、时间持续、可回滚的控制参数面；Volvence 的假设是，这个参数面最好由经历中涌现的 `z_t / β_t` 抽象承担，而冻结 LLM 负责语言理解与表达。

一句话版本：

> **token 空间可以训练，但不适合作为真实在线持续学习的主要可塑面；在线可塑面应该位于 token 之上的时间抽象控制空间。**

不过必须保留“这是待验证的架构假设”，而不是已经证明的定理。
