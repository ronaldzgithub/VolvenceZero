### 方案真正做对的地方

完整的 DRIFT 不是单独一个 token 权重公式，而是一个两阶段闭环：

1. 先用 SDPO warm-up，快速积累成功轨迹。
2. 混合阶段中，失败轨迹走 SDPO，由当前成功 sibling 或历史成功缓冲提供密集纠错。
3. 成功轨迹走 GRPO，再按历史通过率区分 easy/medium/hard。
4. 只有中等难度的成功轨迹才启用 rhythm gate，额外强化特定 token。

这种“按学习状态分配信号”的思路是合理的：它同时处理了 GRPO 在全错组里 advantage collapse、SDPO 缺少成功教师，以及简单样本被重复训练的问题。成功缓冲也只在当前组没有正样本时回退使用，比无条件 replay 克制得多。[论文方法部分](https://arxiv.org/html/2606.30345v1)

### 最大的问题：核心卖点没有被消融验证

论文消融了：

- difficulty routing；
- success buffer；
- warm-up。

但**没有提供 `w/o rhythm gating`**，也没有同梯度预算的 random gate、entropy-only gate 或简单 token-weight baseline。论文却把 rhythm gating 描述成主要创新之一，并归因于“关键推理位置”的识别。[论文消融表](https://arxiv.org/html/2606.30345v1)

因此现在能比较有把握地说：

- 路由有效；
- warm-up 有效；
- 成功轨迹回放有效。

但还不能说：

- entropy collapse 真能定位推理转折点；
- rebellious bonus 带来了增益；
- 复杂 rhythm 公式比随机或简单 reweighting 更好。

这是这套方案最明显的证据缺口。

### Token 门控的解释有些过度

幻灯片把它称为“奖励验证创新”，但：

- 学生对某个已采样 token 的 log-prob 高于特权教师，并不等于创新，也可能只是过度自信或教师条件上下文不同；
- 教师比学生更快降低熵，是“结构关键点”的启发式代理，不是因果信用；
- 公式使用未来窗口，因此只能做离线训练期分析，不能直接称为因果、实时的在线门控；
- 最终权重主要是单向放大，缺少“保持总梯度预算不变”的对照，所以收益可能部分来自局部有效学习率增加。

此外，幻灯片公式不能视为可实现规范。论文实际还有 margin、指数截断、瞬时熵差、序列内 z-score、sigmoid、均值归一化和 clipping；比图里的两个 `tanh` 复杂得多。[完整 rhythm 公式](https://arxiv.org/html/2606.30345v1)

### 成功缓冲有用，但还不是强意义上的“经验记忆”

它按**同一个训练问题 `x`**保存至多三条历史成功答案。因此更接近“同题成功示范缓存”，而不是能跨任务检索、组合和迁移的经验记忆。

主要风险是：

- 对重复训练题产生记忆化；
- 旧轨迹与当前策略分布越来越不匹配；
- 只按 reward 替换，不能保证推理正确性、风格多样性和覆盖度；
- 如果 reward 是二值或非常粗粒度，所谓“更高奖励替换旧教师”基本无法区分不同成功轨迹；
- 没有展示 buffer 对 OOD 泛化和遗忘的影响。

所以它很好地解决了“这一批没采到正样本”，但还没有证明解决了长期经验积累。

### 结果亮眼，但 PPT 容易让人高估

79.5 的平均分确实最好，但应区分三个参照：

- 相对初始 Qwen3-8B：`+30.0`；
- 相对复现 SDPO：`+7.5`；
- 相对表中最强基线 SRPO：实际只有 **`+2.1`**。

而且 SRPO 等强基线使用的是其他论文报告值，作者只统一复现了 GRPO 和 SDPO。尤其作者复现的 GRPO 是 63.0，而引用结果是 70.0，说明结果对实现和训练设置非常敏感。[主结果表](https://arxiv.org/html/2606.30345v1)

当前 v1 还存在几项重要不足：

- 没有多随机种子、标准差或置信区间；`mean@16` 是采样指标，不是独立训练重复；
- 用 training steps 比较，但不同方法的每步 rollout、forward 和 token 计算量未必一致；
- 主要是 in-domain train/test split，没有真正 OOD、持续学习和灾难性遗忘测试；
- 所以“稳定自进化”和“SOTA”都比证据本身走得更远。

### 对 Volvence 的判断

不能原样搬。DRIFT 明确在 token 空间做 RL 并训练模型权重，而 Volvence 要求 live 基底默认冻结、Internal RL 位于 `z_t` 控制器空间：[multi-timescale-learning.md](/Users/mengfu/Documents/GitHub/volvence/docs/specs/multi-timescale-learning.md:69)、[temporal-abstraction.md](/Users/mengfu/Documents/GitHub/volvence/docs/specs/temporal-abstraction.md:9)。同时，Volvence 要求信用源自 Prediction Error，且记忆写入必须经过唯一 owner：[credit-and-self-modification.md](/Users/mengfu/Documents/GitHub/volvence/docs/specs/credit-and-self-modification.md:11)、[continuum-memory.md](/Users/mengfu/Documents/GitHub/volvence/docs/specs/continuum-memory.md:15)。

但可以吸收三件事：

- 把 EMA 难度/掌握度变成 temporal controller 的只读 advisory；
- 把成功 buffer 改成 memory owner 管理的、带策略版本/PE lineage/新鲜度/多样性约束的 replay snapshot；
- 把 rhythm signal 先作为 SHADOW 诊断信号，在 `z_t` 或抽象动作级验证，不直接重加权 token RL。

我的落地建议是：**先复现 difficulty routing + success buffer，不先实现 rhythm gate。**等加入 `w/o rhythm`、同预算 random gate、至少 3–5 seeds、OOD 和遗忘测试之后，再决定这套复杂 token 门控是否真的值得保留。
